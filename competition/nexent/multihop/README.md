# 跨文档多跳任务集（I21）

赛题任务要求④要求"跨文档多跳知识推理，决策链路可溯源"。单次检索能答的问题不算多跳；
本目录把 5 个**必须联合两份以上资料**才能回答的任务写成可执行资产，而不是只写在文档里。

## 结构

| 文件 | 作用 |
|---|---|
| `tasks.json` | 5 个任务，每个声明若干跳（hop），每跳绑定一个真实数据源 |
| `run_multihop.py` | 执行器：跑跳 → 组装证据链 → 推导结论 → 断言检查（stdlib，无第三方依赖） |
| `results/` | 每次运行的完整报告（含每条证据的定位符） |

## 运行

```bash
python competition/nexent/multihop/run_multihop.py
```

退出码 0 = 全部任务断言通过；非 0 表示有任务未达标（可直接接进验收脚本）。

| ID | 问题 | 跳数 / 来源数 | 关键结论 |
|---|---|---|---|

## 断言设计

每个任务断言三类：

1. `min_sources` —— 至少联合几个源，防止"单源冒充多跳"；
2. `must_flag` —— 必须得出的结论标记（如 `unstable_domain`），防止推理走偏却不报错；
3. `block_ready_claim` —— 结论里不得出现**未加否定**的放行声明（"可直接生成""可上机"等），
   防止模型为了好看给出越权承诺。

第 3 条是验收时最容易漏的：数字对、来源全，但结论句写成了"可以直接加工"，一样是错的。

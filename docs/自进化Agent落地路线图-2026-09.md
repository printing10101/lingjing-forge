# 灵境制造 · 自进化 Agent 落地路线图（2026-09）

> 定位：把《Agent-Lightning-认识与规划》（2026-09-11，桌面文档）的蓝图翻译成本仓库的工程方案。
> 方法：全部结论经 2026-09-12 源码核实，文件路径与行号可溯源。
> 核心判断：**本项目离「真正自进化」的距离，不是引入某个训练框架，而是把仓库里已经存在的五层零件焊成一个闭环，并补上四个断点。** Agent Lightning（下称 AGL）是这个闭环最后一级（权重级 RL）的可选引擎，不是起点。

---

## 一、目标定义：什么叫「真正自进化」

```
        ┌──────────────────────────────────────────────────────┐
        │                    自进化闭环                          │
        │                                                      │
        │  ① 执行   AgentRuntime 接任务 → 多轮 LLM+工具 → 产物    │
        │     ↓      （每次运行产出 trace + 产物）                 │
        │  ② 评价   Evaluator 统一评分 → EvalReport              │
        │     ↓      （语法/安全 + 几何 + 物理，一个分数出口）      │
        │  ③ 记忆失败入册 → failure_case_store                │
        │     ↓      成功入 RAG → ProcessQuadruple（已实现）      │
        │     ↓      用户反馈 → feedback_collector               │
        │  ④ 改进   T1 提示词/检索迭代 ── 现在就能跑（Ollama）     │
        │     ↓      T2 SFT（LoRA，validator 案例蒸馏）           │
        │     ↓      T3 权重级 RL（AGL，算力允许后）               │
        │  ⑤ 治理   replay 重放 → regression_gate 门禁 → 灰度上线 │
        │     ↓                                                 │
        │  └→ 回到 ①，带着更强的提示词/检索/权重                    │
        └──────────────────────────────────────────────────────┘
```

任何一环缺失就不是自进化：没有②是盲改，没有③是无记忆，没有④是只有记忆没有学习，没有⑤是拿生产环境赌运气。**本项目的独特优势在②**：制造域有自动 ground truth（校验器 + 体素仿真 + 物理评分），这是大多数 Agent 产品不具备的闭环条件。

## 三、目标架构

```
 GUI 聊天 ─┐
 agent_gateway ├─→  AgentRuntime（统一 in-process ReAct 循环，M2 产物）
 MCP 外壳 ─┘        ├─ ToolRegistry：制造工具集（pipeline 封装为工具，与 mcp_server 同源后端）
                    ├─ TrajectoryRecorder → trace store（JSONL，含 prompt_version/model_version）
                    └─ LLM Provider 网关（base_url 可切 → 训练时切 AGL 代理）
                              │ 产物
                              ▼
                     Evaluator（唯一分数出口，M0 产物）
                     evaluate(task, output) → EvalReport
                     = SafetyValidator + VoxelValidator + SimScore(0-100) 复合
                              │
            ┌─────────────────┼──────────────────┐
            ▼                 ▼                  ▼
   failure_case_store   success_case_harvester   feedback_collector
   （失败入册）            （成功入 RAG，已有）      （用户反馈，M0 接线）
            └─────────────────┼──────────────────┘
                              ▼
                  Evolution Orchestrator（M1 产物）
                  = heartbeat cron 触发 workflow 模板 evolution_loop.yaml
                  = stats → 提案（T1 提示词补丁 / T2 SFT 数据集 / T3 RL 任务）
                              │
                              ▼
                  replay_harness 重放 → regression_gate 门禁 → 灰度（canary）
                              │
                              └→ 提示词版本 / 检索配置 / 模型权重 → 回到 AgentRuntime
```

**「一个分数」原则**：全项目只有 Evaluator 一处定义「好不好」。回归门控、成功案例收割、RL reward、进化报告全部消费同一个 `EvalReport`。避免「训练骗过 A 校验器、门禁用 B 校验器」的口径分裂。

### M1 — 闭环运转（补断点③，~1-2 周）已实现（2026-09-12）

> **实现记录**：
> - 演化引擎：`app/evolution/loop.py`（`EvolutionEngine`：collect_stats → propose → promote/reject/rollback → report，全部入口永不抛异常）。**提案制安全边界**：propose 的候选版本只入持久化存储（proposed），不进 live 注册表——线上提示词在人工审核前保持不变；promote = 热更新上线 → replay 回归门控 → FAIL 自动回滚（unregister + rolled_back 留痕），inconclusive（样本不足）保持 applied 继续观察。`LNN_EVOLUTION_AUTO_APPLY=1` 可开自动发布（默认关）。

> - **SHARP 保留并行（决策）**：不迁移。理由：其 ReActLoop 服务三元组验证的专用语义（StrategicPlanner 规划 / 证据重排 / 置信度终止），泛化 runtime 复刻这些属高回归风险重写，收益仅是架构统一；两套循环已对齐的是关键底座——Prompt Registry、轨迹 JSONL 模式、失败入册口径。若未来 SHARP 提示词进入 T1 迭代面再评估迁移。
> - **mcp_server 无需去重（决策）**：mcp 是外部智能体的 HTTP 壳（26 工具转发 REST），runtime ToolRegistry 直调 app 层，二者共享同一后端 pipeline、逻辑重复为零；同源关系已在 `tools.py` docstring 声明。
> - 回归：docs sync 门禁 FULLY SYNCHRONIZED。

## 五、治理红线（贯穿所有阶段）

1. **门禁纪律**：任何被进化物（提示词版本/检索配置/权重）上线前必过 replay gate；`regression_gate` 从 gcode 域泛化为全局门禁。改了不能让历史通过案例变差。
2. **血缘可追溯**：每个 trace 与 G-code 产物携带 `prompt_version + model_version + EvalReport 摘要`，出问题可回滚、可归因到具体演化动作。
3. **诚实边界**：没有自动评价器的领域不做自进化（本路线全部锚定在制造域的 ground truth 上）；主 venv 永不安装 verl/vllm/AGL；训练流量永不进 GUI 流式路径；LNN 颤振模型的自进化（data_flywheel 原目标）与 LLM 自进化共享治理层、分开演进。
4. **提案制起步**：T1 补丁人审 apply → 门禁数据积累后 → 半自动（门禁过即发布，抽样人审）→ 全自动。每一步降级路径都要保留。

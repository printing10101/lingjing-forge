## 1. 安装与启动

### 1.1 端口被占用

- **症状**：启动时报告 `OSError: [Errno 98] Address already in use` 或 `bind: address already in use`
- **可能原因**：
  1. 8765 端口被其他应用占用
  2. 上一次安装的进程未完全退出
- **解决方案**：
  1. 查找占用进程：`lsof -i:8765` (Linux/macOS) 或 `netstat -ano | findstr :8765` (Windows)
  2. 结束占用进程，或使用 `--port` 参数指定其他端口
- **预防措施**：使用非标准端口（如 18765）减少冲突概率

### 1.2 依赖安装失败

- **症状**：`pip install` 报 `Could not build wheels for ...`
- **可能原因**：
  1. Python 版本过低（< 3.10）
  2. 系统缺少编译工具（gcc、g++）
  3. 网络无法访问 PyPI
- **解决方案**：
  1. 升级 Python 到 3.11
  2. Linux：`sudo apt install build-essential`；macOS：`xcode-select --install`
  3. 配置国内镜像：`pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`
- **预防措施**：使用官方 Docker 镜像避免本地编译

### 1.3 服务启动后立即退出

- **症状**：服务启动 1-2 秒后自动退出，无明显错误
- **可能原因**：
  1. 配置文件 `python/config/lnn_workflow.yaml` 格式错误
  2. 数据目录无写权限
- **解决方案**：
  1. 检查日志：`tail -100 logs/app.log`
  2. 验证 YAML 语法：`python -c "import yaml; yaml.safe_load(open('config/lnn_workflow.yaml'))"`
  3. 修改数据目录权限：`chmod -R 755 /var/lib/lingjing`

## 2. 登录与权限

### 2.1 忘记密码

- **症状**：登录时提示"用户名或密码错误"
- **解决方案**：
  1. **普通用户**：联系系统管理员重置
  2. **管理员**：在服务器执行 `python -m app.cli reset-password --user <username> --new-password <newpass>`
- **预防措施**：
  - 使用密码管理器记录密码
  - 启用 LDAP / SSO 集成（参见 [安全须知](./安全须知.md)）

### 2.2 提示"权限不足"

- **症状**：访问某功能时提示 `403 FORBIDDEN`
- **可能原因**：
  1. 当前用户角色无权访问
  2. 资源所有者已离职/转岗
- **解决方案**：
  1. 联系系统管理员申请权限
  2. 管理员在"用户管理 → 角色"中调整
- **预防措施**：使用 RBAC 角色模板，遵循最小权限原则

### 2.3 Token 过期频繁

- **症状**：每 30 分钟需要重新登录
- **可能原因**：JWT 过期时间设置过短
- **解决方案**：
  1. 联系管理员调整 `JWT_EXPIRES_MINUTES` 环境变量（默认 1800 = 30 分钟）
  2. 启用 "记住我" 选项（延长至 7 天）
- **预防措施**：使用单点登录（SSO）

## 3. 工件导入

### 3.1 STEP 文件导入失败

- **症状**：上传 STEP 后提示"解析失败"或长时间无响应
- **可能原因**：
  1. STEP 文件损坏或不完整
  2. 文件版本过旧/过新
  3. 文件包含不识别的曲面类型
- **解决方案**：
  1. 在原 CAD 软件中重新导出 STEP（推荐 AP214）
  2. 尝试用 FreeCAD 打开验证文件完整性
  3. 简化模型（移除装饰性特征）
- **预防措施**：
  - 统一使用 STEP AP214 格式
  - 单文件不超过 50MB
  - 复杂模型先做"几何简化"

### 3.2 特征识别率低

- **症状**：导入成功但识别到的特征数量远少于预期
- **可能原因**：
  1. 工件坐标系不在几何中心
  2. 图纸分辨率不足
  3. 特征过于复杂（如自由曲面）
- **解决方案**：
  1. 在 CAD 中重新设置坐标系到几何中心
  2. 提高 STEP 导出精度（`Solidworks: 导出选项 → 精度 → 高`）
  3. 使用 **手动标注特征** 功能补全
- **预防措施**：
  - 遵循 CAD 建模规范
  - 复杂工件分多个子装配体导入

### 3.3 导入后 3D 视图空白

- **症状**：导入成功但 3D 预览不显示任何内容
- **可能原因**：
  1. 浏览器 GPU 加速被禁用
  2. WebGL 兼容性问题
- **解决方案**：
  1. 浏览器开启硬件加速：`chrome://settings/system → 使用硬件加速`
  2. 更新显卡驱动
  3. 尝试使用最新版 Chrome / Edge
- **预防措施**：
  - 部署前在客户端环境验证 WebGL 支持

## 4. 工艺规划与 AI 推理

### 4.1 AI 推荐置信度过低

- **症状**：AI 推荐的方案置信度 < 0.5
- **可能原因**：
  1. 该材料/参数组合在训练数据中样本不足
  2. 输入特征缺失或异常
- **解决方案**：
  1. 切换到"手动配置"模式
  2. 补充该材料/参数的历史加工数据（参见 [刀具库管理 - 寿命记录](./功能详解.md#5-刀具库管理)）
  3. 调整输入特征使其更接近训练分布
- **预防措施**：
  - 定期导入历史加工数据
  - 标注异常工况用于模型持续学习

### 4.2 推理超时

- **症状**：AI 推理 > 30 秒未返回
- **可能原因**：
  1. GPU 显存不足，回退到 CPU 后处理慢
  2. 模型文件损坏
  3. 任务队列阻塞
- **解决方案**：
  1. 检查 GPU 状态：`nvidia-smi`
  2. 重新下载模型：`python -m app.cli download-models --model cutting_force --force`
  3. 重启服务清理任务队列
- **预防措施**：
  - 生产环境保证 GPU 显存 ≥ 8GB
  - 定期巡检任务队列长度

### 4.3 工艺路线不合理

- **症状**：生成的工艺路线与经验不符（如先精后粗）
- **可能原因**：
  1. 工艺规则配置错误
  2. 材料/刀具参数填写有误
- **解决方案**：
  1. 检查 **工艺规划 → 规则** 子标签中的配置
  2. 切换到"手动模式"调整工序顺序
  3. 提交"工艺建议"反馈（系统会收集用于持续改进）
- **预防措施**：
  - 工艺审核流程
  - 关键工件"双签"复核

## 5. 仿真与后处理

### 5.1 仿真报告碰撞

- **症状**：刀轨仿真提示碰撞
- **可能原因**：
  1. 装夹方案与加工特征冲突
  2. 安全高度设置过低
  3. 换刀点位置不当
- **解决方案**：
  1. 调整装夹位置（参见 [E3003 错误](../api/error-codes.md#e3003)）
  2. 提高安全高度（推荐：毛坯最高点 + 10mm）
  3. 在程序头添加 `G91 G28 Z0.` 回参考点指令
- **预防措施**：
  - 仿真是强制步骤，未通过仿真不可生成 NC 代码
  - 定期校验装夹方案库

### 5.2 后处理输出格式错误

- **症状**：NC 代码上传到机床后报警"语法错误"
- **可能原因**：
  1. 后处理器与目标机床型号不匹配
  2. 小数位数超过机床精度
  3. 行号超出机床限制
- **解决方案**：
  1. 确认后处理器型号与机床完全一致
  2. 调整小数位数为机床支持的最大精度
  3. 关闭行号或使用 `N` 替代 `N0001`
- **预防措施**：
  - 建立"机床-后处理器"对应表
  - 首次使用某型号机床时，**先空跑验证**（不装工件，不装刀具）

### 5.3 后处理脚本错误

- **症状**：报告 `E4002 后处理转换失败`
- **可能原因**：
  1. 自定义后处理脚本语法错误
  2. 缺少依赖库
- **解决方案**：
  1. 查看详细错误日志
  2. 在本地运行 `python post_processor.py --debug`
  3. 必要时联系后处理脚本作者
- **预防措施**：
  - 后处理脚本纳入代码审查
  - 单元测试覆盖常见刀轨

## 6. NC 代码导出与传输

### 6.1 导出文件乱码

- **症状**：导出的 NC 代码用记事本打开是乱码
- **可能原因**：文件编码不匹配（系统默认 UTF-8，部分旧机床需要 GBK）
- **解决方案**：
  1. 在导出对话框中切换编码格式
  2. 使用 Notepad++ 等编辑器转换编码
- **预防措施**：
  - 车间与编程端统一编码（推荐 UTF-8）

### 6.2 NC 代码传输失败

- **症状**：通过 FTP / U 盘传输到机床时中断
- **可能原因**：
  1. 文件过大
  2. 网络不稳定
  3. U 盘格式不兼容（FAT32 单文件 ≤ 4GB）
- **解决方案**：
  1. 拆分文件（按工序分割）
  2. 使用有线网络而非 WiFi
  3. 格式化 U 盘为 exFAT
- **预防措施**：
  - DNC 在线传输（避免 U 盘）

### 6.3 机床实际加工与仿真不符

- **症状**：实际加工尺寸偏差 > 仿真预测
- **可能原因**：
  1. 刀具实际磨损（未及时更换）
  2. 装夹松动
  3. 切削液未充分冷却
- **解决方案**：
  1. 检查刀具寿命记录，更换磨损刀具
  2. 复紧装夹
  3. 调整切削液流量
- **预防措施**：
  - 严格遵循"首件必检"流程
  - 关键尺寸 100% 在机检测

## 7. 性能与稳定性

### 7.1 系统响应慢

- **症状**：操作有明显卡顿（> 3 秒）
- **可能原因**：
  1. 服务端负载高（CPU/内存占用 > 80%）
  2. 数据库查询慢（缺少索引）
  3. 网络延迟高
- **解决方案**：
  1. **服务端**：
     - 增加工作进程：`--workers 8`
     - 升级 Redis 集群
     - 清理过期日志与临时文件
  2. **客户端**：
     - 关闭其他占用资源的应用
     - 使用有线网络
- **预防措施**：
  - 定期容量评估
  - 监控关键指标（参见 [监控与可观测性](./功能详解.md#12-监控与可观测性)）

### 7.2 内存溢出（OOM）

- **症状**：进程被系统强制杀死，日志显示 `MemoryError`
- **可能原因**：
  1. 单次推理 batch_size 过大
  2. 并发任务数过多
  3. 内存泄漏
- **解决方案**：
  1. 减小 batch_size（参见 [E5002](../api/error-codes.md#e5002)）
  2. 降低并发数（`MAX_CONCURRENT_TASKS`）
  3. 升级到最新版本（修复已知内存泄漏）
- **预防措施**：
  - 配置内存监控告警
  - 定期重启服务（推荐每周一次低峰期）

### 7.3 数据库锁等待

- **症状**：操作卡住 10+ 秒后报"数据库繁忙"
- **可能原因**：
  1. 长事务未提交
  2. 死锁
- **解决方案**：
  1. 找出长事务：`SELECT * FROM information_schema.innodb_trx ORDER BY trx_started;`
  2. 必要时 `KILL <trx_id>;`
- **预防措施**：
  - 业务代码避免长事务
  - 启用连接池监控

## 8. 网络与集成

### 8.1 API 请求超时

- **症状**：客户端报 `504 Gateway Timeout`
- **可能原因**：
  1. 任务在队列中等待
  2. 后端处理慢
  3. 反向代理超时设置过短
- **解决方案**：
  1. **客户端**：使用异步任务接口（`/api/v1/jobs/...`）
  2. **服务端**：调整 Nginx 超时：`proxy_read_timeout 300s;`
- **预防措施**：
  - 长任务使用异步 + 轮询或 SSE/Webhook

### 8.2 WebSocket 连接断开

- **症状**：实时推送中断
- **可能原因**：
  1. 反向代理未配置 WebSocket 升级
  2. 心跳超时
- **解决方案**：
  1. Nginx 添加 `Upgrade` / `Connection` 头
  2. 客户端实现自动重连
- **预防措施**：
  - 使用心跳保活

### 8.3 LDAP 登录失败

- **症状**：LDAP 用户登录时提示"认证失败"
- **可能原因**：
  1. LDAP 配置错误
  2. 证书问题
  3. 用户被禁用
- **解决方案**：
  1. 测试 LDAP 连接：`ldapsearch -x -H ldap://... -D "cn=admin" -W`
  2. 检查证书：`openssl s_client -connect ldap.example.com:636`
- **预防措施**：
  - LDAP 连接监控
  - 本地账号兜底

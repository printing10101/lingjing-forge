## 1. 研究问题与假设

- **RQ1**: LLM 生成的自由曲面 CAD 模型，在五级信号漏斗（编译 → B-rep 有效 → 几何相似 → 3 轴可达 → 物理可加工）上的通过率如何逐级衰减？
- **RQ2**: 物理层的失败（颤振超限 / 切削力超限 / 刀具不可达 / 仿真碰撞）中有多少是几何指标（CD/IoU）完全无法区分的？
- **H1（pilot 验证对象）**: 存在统计上显著的「几何有效但物理不可加工」案例子集，且该子集随曲面复杂度单调扩大。

Pilot 只测 H1（测量型实验）。H2（物理反馈修复能否提升通过率，方法型）留给 Paper B。

## 2. 范围与口径（先说清楚不做什么）

| 边界 | 口径 | 原因 |
|---|---|---|
| 加工方式 | 仅 3 轴铣削 | 多轴 RTCP/刀姿可达性未实现（`app/simulation/kinematics` 仅行程级校验） |
| 曲面刀轨 | **2.5D 水线近似**：trimesh Z 等高线切片 → `PlanarToolpathEngine` 环切/轮廓 | 全仓无 cutter-location 曲面刀轨引擎（`app/toolpath/planar_engine.py:13-15` 明示不处理曲面刀轨）。水线是诚实的 3 轴粗加工近似；论文中作为 limitation 声明 |
| 物理模型 | 解析解（Tlusty 单自由度 + Kienzle） | LNN 权重缺失：`app/simulation/chatter/checkpoints/`、`cutting_force/checkpoints/` 目录不存在，`predict_stability`/`predict_cutting_force` 恒回退解析法。**论文只能写 analytical 口径，严禁写 neural/LNN 口径** |
| 评估器口径 | 每条结果记录 `method` 与回退标志（如 `ltc_active`） | 可追溯性；防审稿人质疑口径漂移 |

## 3. 案例集（N=50）

**10 个参数化设计族 × 5 个难度档**，全部自行编写 CadQuery 真值代码（复用 `app/cad/` 沙箱执行生成真值 STL/STEP）：

| 设计族 | 核心曲面特征 | CadQuery 实现 |
|---|---|---|
| F01 过渡接头 | 异截面 loft（圆→椭圆→矩形） | `loft` |
| F02 螺旋输送槽 | 螺旋 sweep | `sweep` + helix path |
| F03 波形模具面 | 正弦参数曲面 | 参数化 `workplane` + 曲线 |
| F04 凸轮盘 | 非圆曲线 revolve/拉伸 + 圆角族 | `revolve` + `fillet` |
| F05 涡壳流道 | 扫掠 + 壳体 | `sweep` + `shell` |
| F06 叶片式支架（低弯度） | 直纹面 loft + 薄壁 | `loft` + `shell` |
| F07 变圆角拓扑块 | 链式变半径 fillet | `fillet` |
| F08 扭转挤压件 | twisted extrusion | 扭曲变换 |
| F09 复合腔体 | loft 型腔 + 阵列孔 | loft + `rarray`/`cut` |
| F10 组合曲面零件 | 以上 ≥3 种特征组合 | 组合 |

- 每族 5 难度档（特征尺寸递减 / 曲率递增 / 特征数递增），难度档命名对齐 Text2CAD-Bench 的 L1-L4 精神但不混用其案例。
- 每案例数据三件套：`(case_id, 设计规格 JSON, 真值代码)` → 生成真值 `STL/STEP`（存 `pilot/cases/{case_id}/`）。
- 双风格 prompt（几何描述式 / 指令序列式）按 Text2CAD-Bench 的模式为每案例写两条，pilot 阶段只用几何描述式。

## 4. 生成配置（2 个后端 × 50 案例 = 100 次生成）

| 后端 | 接入 | 说明 |
|---|---|---|
| 本地 llama-server | OpenAI 兼容 `http://localhost:1234/v1`，模型 `qwen3-8b` | 由「运动综合数据平台」项目自动拉起；pilot 依赖该平台在线，不可用时跳过并在运行记录标注 |
| DeepSeek API | `DEEPSEEK_API_KEY`（本机唯一配置的云 key） | 作为第二个数据点；控制预算（pilot 总 token < 2M） |

生成参数：temperature=0.2，每案例每后端 3 次尝试（失败反馈重试最多 2 轮，复用 `app/cad/nl2cad_llm.py` 的闭环逻辑），记录每次原始响应与尝试轮次。

## 5. 五级评估漏斗（每条生成结果的判定链）

所有入口均为已验证可调用的真实 API：

| 级 | 判定 | 入口（文件:行） | 失败形态 |
|---|---|---|---|
| S1 执行 | 代码编译 + 沙箱执行成功 | `app/cad/_cadquery_helpers.py`（沙箱 + AST 审计） | 语法错 / 超时 / 崩溃 |
| S2 拓扑 | B-rep 有效性 | `app/cad/_brep_validator.py`（OCCT isValid / 体积 / bbox / 最小特征尺寸） | 非流形 / 退化体 |
| S3 几何 | 与真值相似度 | trimesh 采样 30k 点 Chamfer + 256³ IoU（**口径对齐 Text2CAD-Bench**，便于论文对比） | CD > 阈值（阈值由真值族内扰动标定） |
| S4 可达性 | 3 轴几何可达 | trimesh 沿 +Z/−X/+Y 光线投射的遮挡比；最小特征 vs 刀具直径（φ10 立铣刀） | 顶面遮挡 / 窄缝 < 刀径 |
| S5 物理 | 工艺物理全链 | 见 §6 | 颤振 / 力 / 碰撞 / 行程 |

S4/S5 任一失败即记「物理不可加工」，并记录**失败原因码**（`chatter_depth_exceeded` / `force_exceeded` / `tool_unreachable` / `kinematics_violation` / `sim_collision` / `needs_multiaxis`）。

## 6. S5 物理链具体调用（无需任何训练权重）

对每个通过 S2 的生成模型：

1. **切削参数**：实例化 `CuttingParamRecommender`（`app/cutting_parameters/recommender.py`，材料基线 `material_resolver.py:40`，pilot 用 6061-T6），得到 `spindle_speed_rpm / axial_depth_mm / radial_depth_mm / feed_rate`。
2. **颤振稳定域**：`compute_stability_lobe(machine, tool, speed_range)`（`app/simulation/chatter/stability.py:296`，机床参数取 `app/database/data/machines.json` 的 vmc_850）→ 在推荐转速处取极限切深 `a_lim`，与推荐 `axial_depth_mm` 比较。
3. **切削力**：`compute_cutting_forces(material, width, chip_thickness)`（`app/simulation/cutting_force/kienzle.py:168`）→ Fx/Fy/Fz 与机床功率/力上限比较（材料名需过 `MATERIAL_ALIASES`，`kienzle.py:48`）。
4. **刀轨生成**：trimesh 对 STL 做 Z 等高线切片 → 折线多边形喂 `PlanarToolpathEngine(tool_diameter, ...)`（`app/toolpath/planar_engine.py:322`）的 `profile`/`pocket`/`face_raster`；`PocketTooNarrowError` 记 `tool_unreachable`。
5. **运动学**：G 代码文本喂 `KinematicsValidator.validate()`（`app/simulation/kinematics/validator.py:113`）→ K001-K009 问题码。
6. **体素切削**：`VoxelCutter(voxel_size=1.0).run_simulation(stock_stl_path, tool, segments, output_dir)`（`app/voxel_cutter/cutter.py:429`；优先 Rust 内核 `app/simulation/rust_engine.py:184`，用 `is_rust_available()` 探测并记录）→ 碰撞、去除体素比、时长。

毛坯：从生成模型 bbox + 2mm 余量自动生成长方体 STL。

## 7. 数据记录与产出

- 每条生成结果一条 JSON 记录：`{run_id, case_id, backend, attempt, prompt_style, s1..s5 布尔, fail_reason_code, cd, iou, a_lim_mm, ap_rec_mm, Fx,Fy,Fz, voxel_removed_ratio, sim_collision, cycle_time_est_min, method_flags}`。
- 运行注册表：`pilot/runs/{run_id}/manifest.json`（git commit、种子、模型版本、案例集哈希）。
- **论文第一张图**：分难度档的漏斗瀑布图（100 → S1 → … → S5 通过数），叠加「S3 通过但 S5 失败」的高亮子集——这张图就是 H1 的直接证据。
- 附加图：失败原因码分布 × 曲面特征族热力图（哪类曲面特征最容易物理不可加工）。

## 8. Go / No-Go 判据（pilot 结束时裁决）

| 结果 | 决策 |
|---|---|
| ≥1 个后端在 ≥30/50 案例上通过 S2，且「S3 通过但 S5 失败」≥20% 且原因非退化（非空洞/非超时） | **GO**：扩大案例集至 200+，按 F1 §4 声明写 Paper A |
| S5 失败率 < 10%（几何有效≈可加工，缺口故事不成立） | **PIVOT**：直接转 Paper B（物理反馈修复方法），或提高难度档/引入薄壁族重测 |
| S1/S2 通过率过低（<30%） | 先修生成配置（换模型 / 增加反馈轮次）再判，不做科研结论 |

## 10. 已知风险与对策

| 风险 | 对策 |
|---|---|
| 水线近似被审稿人质疑（曲面精加工失真） | 论文明确 scope=3 轴粗加工可行性；`needs_multiaxis` 作为分类结论输出而非仿真结论；Paper B 阶段评估引入外部 CAM（PyCAM，见 D-1 P2-1）做对照 |
| 本地 llama-server 依赖另一项目在线 | DeepSeek API 兜底；运行记录标注后端可用性 |
| Text2CAD-Bench L3 与我们案例重叠导致"案例集无新意"质疑 | 论文卖点定位在**评估维度**（S4/S5 信号），案例集引用其分层法并声明不重复其数据 |
| Kienzle 固定比例（Fx=0.3Fz/Fy=0.4Fz）过简 | pilot 够用（排序意义 > 绝对值）；D 系列 P3-3 校准试验数据出来后回填 |
| 检索限流导致查重残留盲区 | M4 节点强制重跑检索 + Google Scholar 系统查重后再投稿 |

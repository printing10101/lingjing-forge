## 3. 已确认代码缺陷

### D01 · 校验后替换 NC 内容仍可能放行（P0）

- 位置：`app/dnc/nc_gate.py:103`、`:126`；回归证据 `tests/unit/test_dnc_voxel_gate_closed_loop.py` 的已知 xfail。
- 触发：程序通过校验后，在同一路径修改 NC 内容，再请求下发。
- 原因：按路径追溯成功任务，没有绑定当时验证的文件内容指纹。
- 影响：发送内容可能不是经过校验的内容。运动学与体素标志不能弥补这一缺口。
- 修复验收：任务记录内容哈希；实际发送使用已验证的不可变快照或同一份字节；任意字节变化、缺失指纹的历史记录均拒绝并要求重验。单纯先算哈希后重新读文件仍有竞态。

### D02 · 工艺链查询方向错误，且 max_hops 没有实际逐跳遍历（P1）

- 位置：`app/knowledge_graph/query_api.py:287`。
- 复现：构造 `Process → Feature (APPLIED_TO)`、`Process → Tool (USED)`；从 Feature 查工艺链返回 0 条。
- 原因：查 Feature 的出边，与本体定义方向相反；max_hops 只用于截取数量。
- 修复验收：从 Feature 沿 APPLIED_TO 入边找 Process，再沿 USED 出边找 Tool；按跳数遍历、去重、防环并返回路径证据。

### D03 · 刀具适用材料查询把加工特征当材料返回（P1）

- 位置：`app/knowledge_graph/query_api.py:261`。
- 复现：同一刀具有指向 Material 与 Feature 的 SUITABLE_FOR 边，materials_for_tool 返回两者，实际类型为 feature、material。
- 原因：同名关系服务两类目标，查询未限定目标节点类型。
- 修复验收：材料查询只返回 Material；刀具查询也校验起点类型，增加混合关系测试。

### D04 · 相同 record_id 重复反馈会重复计数（P1）

- 位置：`app/knowledge_graph/feedback_updater.py:52`、`:158`。
- 复现：同一记录提交两次，sample_count 从 1 增为 2。
- 原因：虽然注释承诺幂等，实现没有已处理记录检查/唯一约束。
- 影响：重试或重复消息会污染成功率和置信度。
- 修复验收：同一记录重复提交不再改变统计；并发重复、失败重试、进程重启也满足幂等。

### D05 · 未提供粗糙度会被当作 0，制造虚假的质量改善（P1）

- 位置：`app/knowledge_graph/feedback_updater.py:163`。
- 复现：首条粗糙度为 2.0，第二条没有该字段，平均值变为 1.0。
- 修复验收：仅实际测量值进入均值；维护独立有效测量计数，验证缺失、None、非数与非有限值。

### D06 · 中文材料名更新后，后续置信度调整找错节点（P1）

- 位置：`app/knowledge_graph/feedback_updater.py:244`、`:405`。
- 复现：合法 ASCII 材料 ID 得到一次 confidence_adjustments；同等中文材料名为 0 次。
- 原因：建边先归一化材料 ID，后续调整却用原材料名查边。
- 修复验收：统一身份解析；中文名、牌号、规范 ID 对同一材料只更新同一条边，调整结果一致。

### D07 · 反馈更新中途失败仍留下部分图谱修改（P1）

- 位置：`app/knowledge_graph/feedback_updater.py:52`。
- 复现：工艺节点更新成功后，非法刀具 ID 触发异常；工艺节点仍已创建并计数。
- 原因：多个修改依次执行，入口没有整条记录预校验或回滚。
- 修复验收：整条反馈全成或全败；失败后的重试不会污染统计，存储提交也保持原子性。

### D08 · 删除实体后，审核导出仍含引用它的关系（P1）

- 位置：`app/knowledge_graph/extractor/review.py:313`、`:382`。
- 复现：批准刀具、材料及关系后删除材料；approved 导出仍有 1 条指向已删除材料的关系。
- 修复验收：失去有效端点的关系不得进入批准导出；修改或删除后重新检查引用完整性。

### D09 · 批量批准会把仍需修改的审核单标成已批准（P1）

- 位置：`app/knowledge_graph/extractor/review.py:359`。
- 复现：某实体设 needs_revision 后执行 approve_all；实体保持 needs_revision，但整体变 approved。
- 原因：只批准 unverified 项，随后无条件设整体 approved。
- 修复验收：整体状态从真实子项状态重新计算；存在 needs_revision 时不能显示整体通过。

### D10 · 合金钢被知识增强模块识别成铝（P0）

- 位置：`app/agent/knowledge_augmenter.py` 的 `_MATERIAL_KEYWORDS` 与 `normalize_material()`。
- 复现：执行原函数，normalize_material('alloy steel') 返回 aluminum。
- 原因：铝类别用通用词 alloy 做子串匹配，且先于 steel 检查。
- 影响：可能召回铝加工知识，给钢件提供不合适的参数提案；后续数值上下限并不能验证材料类别正确。
- 修复验收：具体牌号/完整词优先，删除泛词映射，覆盖 alloy steel、aluminum alloy、titanium alloy 等易混输入；未知材料明确返回未知。

### D11 · 中文连续文本中的材料实体漏提取（P1）

- 位置：`app/rag/document_importer.py:31`、`:68`。
- 复现：执行原实体抽取函数，文本“加工45钢工件”没有提取出“45钢”。
- 原因：使用 Unicode 单词边界 `\b`，相邻中文和数字均可能属于单词字符，不产生预期边界。
- 修复验收：覆盖中文连续句、混合英文牌号、标点、空格及误匹配负例，使用适合各实体格式的边界。

## 5. 实验和部署证据的已知边界

- I5 是仓库测试图纸的单轮廓三轴离线规则级实验；厚度为推断值，没有机床反馈，没有调用 Nexent 或 LLM，不能冒充企业实机闭环。
- 体素精度、夹具刀柄、固定循环和最终公差覆盖均有边界；当前通过不等于加工质量已经认证。
- `d_line/v3_mechanism/gate_result.json` 是 10 案例一次通过率 0.8→0.8，证明未退化，不证明收益；本轮没有重新审计这些案例的独立性。
- I3 的真实切削力按实验分组测试 R²=0.542；合成数据上的 0.998 不能用作真实预测精度。文档对“信息论上限”的推导本轮未审计，不在本报告替其背书。

## 6. 建议整改顺序与完成标准

1. **先修 P0 与知识可信度**：D01、D10，其次 D02—D09、D11。每项补失败复现测试与修复后通过证据；不能仅把 xfail 去掉。
2. **统一文档、知识与验证身份**：同一文档版本、实体、加工上下文和 NC 内容均可追溯，处理 S01/S02。DNC 验证还应核对目标机床、刀具、毛坯和装夹上下文；本轮未证明上下文绑定完整。
3. **在现有制造场景完成 Nexent 链路**：先选一个有明确支持范围的零件，以工艺资料和参数表驱动决策，真实调用规划与校验工具，保存整个运行过程。
4. **实现并交付 Nexent Skills**：按知识构建、决策、验证反馈拆可复用流程；固定输入输出、失败处理、版本与导入方法。
5. **补赛题核心证据**：低资源构建效率、标准更新前后、多文档推理依据、反馈前后收益、独立留出任务和专家核对。没有提升就如实报未提升。
6. **完成演示与提交包**：启动稳定性、超时恢复、录屏、Word、PPT、脱敏导出、许可证、从干净环境重建；最后再做多行业附加分。

完成标准不是“模块都存在”，而是评委拿到固定版本和脱敏材料后，能重新运行同一个案例，看到来源、决策、校验、更新与前后变化。

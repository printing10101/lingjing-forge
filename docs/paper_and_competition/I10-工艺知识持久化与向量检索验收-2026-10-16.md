## 工艺知识缺陷与修复

| 缺陷 | 修复 | 验证 |
|---|---|---|
| 默认索引仅在内存中，重启丢失 | 单例默认落盘，可配置 LINGJING_PROCESS_KNOWLEDGE_DIR | 单条、批量写入后启动独立新进程，参数和来源标识完整恢复 |
| 单条新增不保存，批量保存失败仍返回成功 | 写盘成功才确认；原子替换失败撤回所有内部索引，外部实体关联不写入 | 注入 PermissionError，检查原文件字节与内存索引均未变化 |
| 某些读取接口自动灌入默认配方 | 删除隐式种子导入 | 空库读取仍为空，不生成文件 |
| 示例配方冒用 manual 来源 | 明确 source=example，不进入正式推荐 | 显式添加示例后逐条确认不能推荐 |
| 只按特征排序，把其他材料配方推荐给当前材料 | 正式推荐限制为精确材料或 general；跨材料仅留在带匹配级别的相似参考查询 | 铝材配方不能作为钢材正式推荐，general 标签保留 |
| 坏文件被跳过或当成空库继续运行 | 整体解析成功才加载，错误停止加载且不覆盖文件 | 坏 JSON、错结构、缺字段均拒绝加载 |
| 网关先初始化后，RAG 的来源文档依赖未绑定 | 支持后续显式注入依赖 | 先取单例、后绑定文档库，仍为同一索引 |

## 在线文档检索

CPU 嵌入服务实际返回 HTTP 200、1024 维、有限且非零的向量。
Nexent 的两个文档查询各返回 3 条结果，包含原文件路径、文件名、分块编号和索引。
“加工失败”前两条命中失败案例文件；这是基础检索联通验收，不是准确率或多跳推理效果评测。

初次调用遇到 Docker 停止；重启时认证依赖尚未就绪，出现超时。
依赖就绪后，直接认证健康检查与密码登录均 200，Nexent 重新登录与实际查询成功。
未修改账号密码或绕过认证。证据：`I10-validation/auth-path.json`、`vector-search.json`。

## 新文件入库试验与限制

创建独立 PRIVATE 知识库 `lingjing_acceptance_i10_synthetic`，没有绑定到业务智能体。
样本只含唯一检索标记和合成验收声明，不含加工参数。
首次上传成功，但处理发生 Ray 内存保护：5.55 / 5.79 GB 超过 95% 阈值，工作进程被杀，零分块。
原失败记录保留于 `new-ingestion-memory-failure.json`。

将处理并发和 actor 数降至 1、关闭后台监控后，仍观察到内存保护，不能宣称低并发已解决。
已备份 WSL 配置并把内存上限从 6 GB 调为 8 GB，处理器设置保持不变；仅 Docker 发行版运行。
这是本机运行预算调整，尚不能替代多文件并发或生产容量验证。
新增入库最终结果以 `new-ingestion.json` 的 `completed_and_source_traceable` 为准。
最终该字段为 true：原验收文件重试后完成，生成 1 个分块，唯一标记检索命中，原始路径一致。
新建验收库为第九个索引；已有八个索引文档计数及原 C 盘文件哈希复核一致。
试验中另有一个因文件重名而生成、提交时服务未就绪的失败样本记录，保留在独立验收库，未进入业务智能体。
这次通过仅证明小 Markdown 文件的上传、处理、向量化和可追溯检索；PDF/OCR、大文件与并发负载仍未验收。

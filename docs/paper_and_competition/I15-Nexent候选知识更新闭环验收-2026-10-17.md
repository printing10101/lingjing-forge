| 项目 | 实现与证据 |
|---|---|
| 网关候选提交 | R+W Agent 可提交候选；来源、权重和初始待审状态由服务端确定 |

## 隔离闭环与回归

合成临时库使用真实 Agent Token 认证中间件，验证：
提交 → 读取 pending → 重启恢复 → 人工审核函数批准 → Agent 读取有效批准 → 正式推荐命中 → 撤销 → 不再推荐。
MCP handler 经真实 ASGI HTTP 和认证层调用，未用成功返回桩代替整个网关。
模拟人工批准仅发生在临时合成库，真实厂商候选没有批准。

扩大回归包括 I14 后端验收文件及既有统一认证、访问日志、权限辅助测试；结果见 `I15-validation/regression.xml`。
新网关和 MCP 两个模块覆盖率见 `coverage.json`，满足 80% 门槛。
最终 418 项扩大回归通过，两个新模块语句及分支覆盖率均为 100%，九种故障变异均被拦住。
另有 60 项 MCP 注册与候选错误处理复验通过，确认 409/422 等输入或内容冲突不能被误报为可以直接重试。
最终部署还通过真实 Nexent 提交一次同编号不同内容的冲突请求，回读 409、retryable=false，确认原候选内容和版本完全未变。
原 API 文档扫描不递归进入 agent_gateway 子目录；本轮额外对两个新端点显式提取并核对文档，缺漏为 0。
故障注入覆盖所有者隔离、内容冲突、独立写权限、修订后提交记录、通用缓存绕过、待审推荐过滤、状态批准检查、非有限 JSON 拒绝和 HTTP 重试分类。
第一轮写权限变异被外层中间件掩盖，已增加独立路由权限断言；不能把外层拦截当作路由守卫已验证。

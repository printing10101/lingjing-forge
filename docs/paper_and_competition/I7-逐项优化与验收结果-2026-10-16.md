## 结论

11 项已确认代码缺陷均已修复并有回归证据；3 项附加限制已有针对性处理。
这不等于 40 项比赛交付全部完成：Nexent 联运、Skills、知识本体演进、真实业务收益与实机验证仍未完成。

本轮修改集中在代码正确性、知识导入与软件验收契约；保留此前已有的 DXF/单图纸反馈工作区改动。
没有提交 Git、没有下发 NC、没有修改 WSL/Docker 配置或启动 Nexent 全栈。

### 附加优化

- **S01 文档标识/更新**：规范化完整路径标识文档，源内容与分块配置/内容标识版本；生产导入按文档替换分块，清理旧尾块和实体索引。真实 ChromaDB 验证了不同目录同名文件、缩短文档、重复导入和后端删除失败后的旧版本恢复。
- **S02 评分与验收分离**：保留旧 passed 的部分评分语义，新增 dimensions_complete、fully_validated、validation_scope。完整标志要求三维度实际执行并通过，且有切削段与非零去除。内置 Agent 工具输出该标志、提示其用途，并透传 cutting_params。没有声称所有历史消费者已迁移。
- **S03 Excel**：明确只支持 xlsx/xlsm；旧 xls 提示先转换。合并区域展开为左上角值，没有计算缓存的公式拒绝导入，防止缺失数值被当成有效参数。
- **文档入库接线**：Excel/CSV 现在可以走统一 RAG 导入；Word 保留段落与表格顺序和表格内容，不再因缺少依赖而把 DOCX 压缩包当文本。真实 Word 表格和 Excel 行进入同一向量库并被材料实体关联；损坏 Word 返回失败且不改库。
- **历史测试修正**：重试测试用实际 I/O 错误 OSError 并验证重试 3 次；PDF 中文测试嵌入 CJK 字体，避免默认字体把源文字变成点号。没有降低业务断言。

## 4. 当前不能扩大宣称的边界

1. 内容指纹解决校验后文件替换，不代表验证上下文已绑定目标机床，也不代表所有 DNC 入口已审计。显式历史程序逃生阀及其审计机制仍存在。
2. 图谱事务目前通过全图快照提供单进程回滚；没有完成大图性能、多个服务进程同时写入的测试。数据湖与图数据库不是跨系统事务。
3. 文档替换在单进程 VectorStore 包装器内串行，并在普通后端错误时尝试恢复；断电、进程崩溃、索引更新失败及恢复失败没有统一事务保证。
4. 旧分块没有 document_id，不能仅凭同名猜测删除；需要显式迁移。移动文件路径视为新文档，检索缓存自动失效尚未接线。
5. fully_validated 只证明传入上下文内的软件校验完成，不证明最终尺寸公差，也不能作为机床操作许可。历史评分消费者仍需逐个迁移。
6. 桌面运行时是未完成依赖安装的状态；直接启动会缺少框架、图纸与 CAD 依赖。系统 Python 的测试成功不能替代桌面打包验收。

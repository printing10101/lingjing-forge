## T1 · feature_extraction 几何算法（P0）— ✅ 2026-11-16 达标

- **实测**（新增 `tests/unit/test_feature_extraction_pipeline.py` 9 项，域口径 1223 语句）：域合计 **76%**；`pipeline` 62%、`hole_detector` 87%、`cylinder_extractor` 77%、`feature_store` 93%、`review_state_machine` 90%、`plane_extractor` 61%。
- **做法**：用 trimesh 现场生成 mesh（方块 8 顶点无特征；圆柱 130 顶点 → 平面 2/圆柱 1/孔 1；icosphere 642 顶点 → 平面 20/孔 14），跑真实异步管线 `create_task → run_task → get_result`。
- **覆盖点**：mesh 加载（STL/缺文件/非法后缀）、任务创建校验、提取计数、评审动作（confirmed/edited/非法 action）、导出 JSON、免责声明、未知任务降级。
- **注意**：低顶点数 mesh 提取不到特征（方块 0 特征），夹具必须用 ≥100 顶点模型。

## T1 · feature_extraction 几何算法（原始说明，已完成）

- **目标**：`plane_extractor.py`(16%) / `cylinder_extractor.py`(16%) / `hole_detector.py`(14%) → 60%+
- **为什么 P0**：特征识别（孔/面/腔/凸台）是「图纸→NC」链路第一步，上游全依赖它。
- **依赖**：trimesh（构造 mesh）+ sklearn（RANSAC）。均在 requirements 已声明。
- **策略**：
  1. 用 numpy 合成小 mesh（如 `trimesh.creation.box/cylinder` 或手写顶点/面），喂给 extractor；
  2. 测「正例」：规则平面/圆柱/孔能被正确识别（feature_type、params、confidence）；
  3. 测「边界」：空 mesh、退化几何、极小半径、噪点；
  4. `precision_disclaimer.py` 与 `feature_store.py` 已 100%/86%，只补算法层。
- **工作量**：2-3 天。风险：RANSAC 对合成数据的敏感度，需调阈值避免 flaky。

## T3 · knowledge_graph（P1）— ✅ 2026-11-16 达标

- **实测（非测试代码口径，2861 语句）**：域合计 **64.4%**。分模块：`repository` 77%、`persistence` 71%、`models` 90%、`graph_store` 80%、`query_api` 58%、`extractor/validator` 79%、`health/checker` 80%、`health/report` 93%、导入器 70–89%。
- **新增 7 个测试文件（约 40 项）**：查询 API、仓储与持久化（sqlite StaticPool）、抽取校验器、规则解析器、健康检查与报告、四类 JSON 导入器、反馈回灌、本体提案审核（含 sqlite 持久化往返）。
- **顺带修复两处生产缺陷**：
  1. `health/checker.py` 用 `graph.edges(v, u, keys=True, data=True)` 取反向边——networkx ≥3.4 签名变更（`data` 为位置参数）会抛 `TypeError: multiple values for 'data'`，即**任何存在互逆关系的图都会崩**；改为邻接字典 `get_edge_data(v, u)`。
  2. `extractor/validator.py` 用 `e["id"]` 构造实体映射——上游 LLM 输出缺 `id` 时整份校验抛 `KeyError`；改为跳过缺 id 实体（其已被记为无效）。
- **仍为 0%**：`extractor/review.py`（283，需评审工作流夹具）、`llm_extractor`/`pdf_extractor`（依赖 LLM/PDF）、`importer/coordinator`（39）。
- **夹具经验**：sqlite 内存库必须 `StaticPool`，否则每连接一个新空库、建表丢失。

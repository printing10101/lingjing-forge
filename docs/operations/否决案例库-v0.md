# 否决案例库 v0（B2）

日期：2026-11-14。状态：**v0 已落地**——存储、schema、脱敏、导入脚本、测试齐备；已导入 **6 条真实拦截记录**（来自 `engineering/python/data/failure_cases.db` 的 222 条失败记录，按参数去重取样）。

## 是什么

把「被物理校验拦下的加工提案」结构化沉淀：哪一步拦截、为什么、参数是多少、严重度如何。它不是失败日志的副本，而是**可对外复用的教学/销售/论文/RAG/再训练素材**（经脱敏）。

## Schema（`app/cam_validation/rejection_case_store.py`）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `case_id` | str | 必填，稳定哈希 | `rc_` + sha256(来源, 原 case_id)[:16]，重复导入不新�� |
| `source_task_id` | str | 必填 | 上游任务 ID（可追溯，不含客户信息） |
| `stage` | str | `cam_validation` / `gcode_gate` / `stability_gate` / `manual_review` | 拦截环节 |
| `decision` | str | `blocked` / `warned` | 处置结果 |
| `severity` | str | `critical` / `high` / `medium` / `low` | 按超限比例：ap/limit ≥1.5 critical，>1.0 high |
| `error_codes` | list[str] | 非空 | 结构化错误码（如 `UNSTABLE_FEATURES`） |
| `evidence_summary` | str | ≤500 字，禁未脱敏路径/邮箱 | 人可读拦截原因（含关键参数） |
| `material_family` | str | 族级别 | `steel_carbon` / `aluminium` / `titanium` / …，不落具体牌号批次 |
| `controller_type` | str | 可空 | 控制器型号（如 `fanuc_0i`） |
| `params` | dict | 键白名单 | 只允许轴向/径向切深、极限切深、转速、进给、刀具参数 |
| `created_at` | float | epoch 秒 | 原始记录时间 |
| `desensitized` | bool | 必须 True | 未脱敏案例在校验期直接拒绝 |
| `redaction_notes` | list[str] | — | 命中的脱敏规则（path/email/ip/long_id） |
| `schema_version` | int | 1 | 后续扩展用 |

存储：JSONL 追加写（`data/rejection_cases/rejection_cases.jsonl`），`case_id` 去重。

## 脱敏规范（硬约束）

写入前必须经 `redact_text()`：

| 目标 | 规则 | 替换 |
|---|---|---|
| 绝对路径 | Windows/Unix 路径正则 | `<path>` |
| 邮箱 | 标准邮箱正则 | `<email>` |
| IP | IPv4 正则 | `<ip>` |
| 长数字 ID | 连续 ≥8 位数字（工单/批次/电话） | `<long_id>` |

**保留**：材料族、控制器型号、切削参数、拦截原因、严重度。**禁止**：客户名、零件号、图纸编号、刀具序列号、人员信息。`RejectionCase.validate()` 对未脱敏文本直接抛错，不允许"先入库后清洗"。

## 五用（各一句）

1. **教学**：用真实拦截案例讲"为什么这条参数不能上机"，比虚构示例可信。
2. **销售**：演示"AI 产出必经物理校验"的硬闸证据链（参数 → 极限 → 拦截原因）。
3. **论文**：作为校验闸有效性的案例材料，脱敏后可直接引用（遵循数据隔离纪律）。
4. **RAG**：作为工艺知识库的反例条目，检索"类似参数是否曾被拦截"。
5. **再训练**：为阈值/模型提供负样本；但**不得直接进训练集**，须经论文/数据隔离流程复核。

## 采集入口

当前：离线导入（已有真实记录）

```bash
# 仓库根
python engineering/python/scripts/import_rejection_cases.py \
  --db engineering/python/data/failure_cases.db \
  --out data/rejection_cases/rejection_cases.jsonl \
  --per-code 5
```

参数：`--per-code` 控制每个错误码的去重取样上限（默认 3）；重复执行不会产生重复记录。

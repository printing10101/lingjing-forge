# 产品叙事调整与战略对标方案（2026-09）

> 定位：回答两个问题——**灵境制造对外到底怎么讲**（叙事），以及**围绕新叙事把现有能力做深的具体路径**（建议）。
> 对标参照：数博会调研的三家公司——浪潮云洲（工业互联网平台）、智平方（具身智能机器人）、江行智能（物理 AI）。
> 执行原则沿用《优化升级路线图-2026-08》：**不堆功能、做深信任**。本文所有建议都是对既有能力的加深或接线，不开新功能线。

---

## 第一部分：产品叙事调整

### 1.1 现有叙事诊断

当前对外定位（PROJECT_OVERVIEW.md / AGENTS.md）：

> 「AI 驱动的 CAD/CAM/NC 一体化、工业级可落地、数据不出厂的桌面平台」
> 「图纸 → 3D 模型 → 工艺规划 → NC 代码 全流程智能化」

问题有四个：

| 问题 | 说明 |
|---|---|
| **"AI 驱动"没有区分度** | 2026 年所有 CAM 厂商都在喊 AI，这个词已经是背景噪音，不是卖点 |
| **讲的是流程，不是品类** | "图纸→NC 全流程"描述功能边界，回答了"你是什么"，没回答"你属于什么、你和别人差在哪" |
| **最大的差异化资产没有被叙事化** | 体素仿真强制闸门 + DNC 下发硬闸是全行业少见的"敢让 AI 上机"的硬约束设计，但现有定位一句话里完全没有体现 |
| **"工具"与"平台"混用** | 定位摇摆，客户无法给产品归档 |

一句话总结：**现在的叙事是"功能清单"，缺一个品类词、一个敌人、一个证据链。**

### 1.2 三家对标公司分别教会我们什么

| 公司 | 品类话语 | 对灵境制造的启示 |
|---|---|---|
| **江行智能** | "物理 AI""每一次执行都有确定结果""一个大脑、多种本体" | **给了品类词**。灵境制造就是物理 AI 在离散机加场景的落地形态：AI 产出的是会被真实机床执行的指令，必须对物理结果负责。这个品类词是 2026 年资本与产业市场的共识热点（江行 B++ 轮的叙事核心） |
| **浪潮云洲** | "智能底座 + 大模型平台 + 智能体服务"三层体系、"质量码"全生命周期追溯 | **给了参照系和反方向**。浪潮做的是大企业上云平台，服务不了也服务不好中小厂的桌面/内网场景——这正是灵境制造的位置。其"质量码"（每个关键质量环节赋码追溯）是全流程血缘 ID 的成熟先例，可直接移植 |
| **智平方** | 端到端具身大模型、仿真合成数据训练、"模型+硬件+场景" | **给了技术叙事和同构性**。灵境制造的"图纸→NC"链路本质是具身智能的"感知→决策→执行"序列；其 sim2real（仿真合成数据训练真实执行体）与"仿真合成工艺数据预训练飞轮"完全同构 |

三家共同的母题：**AI 从"生成内容"走向"对物理世界负责"**。灵境制造恰好是这条路上离落地最近的形态——生成完就能验证、验证完就能出代码、出了代码有闸门兜底。

### 1.3 新叙事核心

**品类定义**（回答"你属于什么"）：

> 灵境制造是**装在工厂自己电脑里的制造物理 AI**（Desktop Physical AI for Machining）。

**主推一句话定位**（替换现有 PROJECT_OVERVIEW 的一句话定位）：

> **图纸进，代码出——每一行 G 代码都经过物理校验才上机，每一份数据都留在你自己的电脑里。**

**备选**（不同场合选用）：
- 正式版（BP/官网）：「灵境制造：桌面级制造物理 AI。AI 全流程生成「图纸→3D→工艺→NC」，体素仿真强制校验、DNC 下发硬闸兜底；推理与数据全程本地，工艺资产不出厂。」
- 口语版（展会/销售）：「车间里来了一位 AI 编程员：它写的每一段程序都先在自己脑子里的虚拟机床上跑一遍，确认不撞刀、不过切，才敢交给真机床。」

**品牌名锚点**（可选用）：钱学森将 Virtual Reality 译作"灵境"——虚拟与真实交融之境。灵境制造的叙事闭环正好是这个译名的现代版：**智能在虚拟中生成，在真实中执行，在反馈中进化**。（若项目名另有出处，此条忽略。）

### 1.4 叙事三大支柱

新叙事用三根支柱，每根支柱必须有一条产品事实兜底：

| 支柱 | 对外口号 | 背后产品事实 | 借鉴来源 |
|---|---|---|---|
| **① 敢上机** | "AI 说的不算，物理说了算" | 体素仿真强制校验（`cam_validation/voxel_validator`，撞刀/过切即拦截）+ DNC 下发硬闸（未过校验 403/错误码 8013）+ 颤振稳定性预测（LNN） | 江行"确定结果" |
| **② 不泄密** | "你的工艺秘密不需要上别人的云" | 9+ LLM 本地/云可插拔但全本地可用、SQLite/ChromaDB 全本地存储、桌面形态天然边缘、MCP 网关 fail-closed 鉴权 | 浪潮信创叙事的中小厂版 |
| **③ 越用越懂你** | "第三个月的第一天，它已经见过你车间两千次真实反馈" | 数据飞轮插件（采集/迭代模板/热更新）、cutting_experience 经验库、实测数据回灌管线（`pipelines/feedback_loop`） | 浪潮质量码 + 智平方数据闭环 |

**必须树立的"敌人"**（没有对比客户记不住）：直接让大模型写 G 代码的"生成式玩具"——能生成，不敢上机。制造现场一次过切 = 报废工件、断刀甚至安全事件。这个对比让"物理校验闸门"从一个功能升级为**购买理由**。

### 1.6 叙事纪律（红线）

呼应路线图"不堆功能、做深信任"：

1. **不说"无人化/全自动"**。产品事实是"AI 起草 → 物理校验 → 人工确认 → 硬闸兜底"，叙事必须与之严格一致。说了全自动，一次事故就是信任崩塌。
2. **不承诺"支持任意机床"**。一切机床承诺按《postprocessor-验证矩阵》的 L1(语法)/L2(黄金)/L3(编程站)/L4(实机) 分级表述；对外只对已过 L2 的机型做公开承诺。
3. **叙事不跑在能力前面**。每一条对外宣称都必须在 1.7 的对照表里有代码资产对应，没有的不说。
4. **监控画面不得默认演示数据**。~~`dnc/mock_agent.py`（127.0.0.1:5010 模拟器）当前是监控链路（monitor_ws）的默认 agent_url~~ **已解除（2026-09）**：monitor_ws 默认不再回落模拟数据，需显式 `LNN_MONITOR_ALLOW_DEMO=1`；未连接时推送 `agent_disconnected` 告警。
5. **~~"数据主权"不得只是前端开关~~**（已解除 2026-09，W9.1 落地）：主权设置现以后端为权威数据源（sqlite3 持久化），并通过 `/rl-agent/training/start` FORBIDDEN 门禁与 `/rl-agent/act` 主权决策字段真实影响后端 AI 行为；前端 localStorage 降级为离线缓存。注意：主权等级不越过物理安全闸门（体素校验/DNC 硬闸/SafetyShield 任何等级下照常生效）。

## 第二部分：细化建议

四个工作流 W1-W4，每个都给出**现状与缺口（精确到模块）→ 动作 → 验收标准 → 风险**。

### W1 把"闸门"升级为"闭环"（对标：江行"每一次执行都有确定结果"）

**现状**：Agent 编排器（`app/agent/orchestrator.py`）已有完整步骤链 dxf_parse → process_understanding → parameter_recommend → gcode_generate → validate_safety；体素校验失败会拦截下发。**缺口：拦截之后是"拒绝"，不是"修复后交付"**——校验失败把负担交回给人。

**动作**：
1. **闭环重试**：`validate_safety` 失败时，把结构化诊断（过切位置/段号/深度、G00 切入段）注入 `gcode_generate` 的上下文并重试；修复预算建议 3 次，仍失败则转人工工单并附诊断报告。（已完成 2026-09：`LNN_ORCHESTRATOR_MAX_REPAIRS` 可调，`repair_count`/`repair_history` 随 trace 落盘，10 用例覆盖修复/预算耗尽/不可修复/零预算关闭四条路径）
2. **诊断报告产品化**：`voxel_simulation_report` 目前是 JSON 字段，前端加一层"为什么不能上机"的人话解释（`ai/process_explainer` 已有可解释化基础，直接复用）。（待做）
3. **颤振护栏前移**：把稳定性叶瓣图约束前移到 `parameter_recommend` 步骤，让参数推荐阶段就避开颤振区，而不是等仿真后才发现——修复成本最低的位置在生成之前。（待做）

**验收**：构造已知缺陷图纸的回归集，闭环自动修复率可度量（首版目标 60%+，随模型迭代上升）；每次修复过程在 orchestrator trace（已有 `trace_log_dir` 机制）中留痕。

**风险**：修复回路可能掩盖生成端的系统性缺陷 → 修复率本身作为监控指标，不达标回头改生成端，而不是无限加修复预算。

### W2 全流程血缘"质量码"（对标：浪潮质量码）

**现状**：`cam_report.json`、orchestrator trace、workflow 步骤各有记录，但**没有一个贯穿全链的 ID**，任一 NC 程序无法一键回溯"它从哪张图纸来、用了什么工艺策略、过了什么校验"。

**动作**：
1. **定义 provenance_id**：一次加工任务的全局 ID，贯穿图纸文件 hash → 3D 模型 → 特征识别 → 工序 → 刀轨 → NC 文件 → 仿真报告 → DNC 下发记录，SQLite 落血缘表。
2. **NC 文件头写元数据**：通过后处理器现有 hooks 机制把 provenance_id 与关键参数写进程序头注释；写入内容必须过 L1 合规检查器（`tests/utils/nc_dialect_checker.py` 可复用）——11 种方言的注释规则不同（如国产方言不支持嵌套括号），不能引入新的合规缺陷。
3. **与飞轮相乘**：血缘让 cutting_experience 采集的每条经验样本自动携带完整上下文（什么图纸、什么策略、什么参数、结果如何）——**质量码是飞轮样本的自动标注器**，这是浪潮"质量码"与"数据飞轮"两个灵感的乘法，也是 W4 的前置。

**验收**：任一 NC 程序输入 provenance_id 即可回溯整链（API + 前端一页视图）；飞轮样本字段完整率 ≥95%。

**风险**：血缘 ID 写入 NC 文件头后，golden 基线会全部漂移 → 基线对比时剥离元数据注释行（合规检查器同位置处理）。

### W3 "一个大脑、多种本体"产品化（对标：江行同名理念）

**现状**：`toolpath/` 统一中间表示 + 11 种后处理器（DSL + 控制器语法树）+ L1 合规层（首轮就抓出 5 个真实方言缺陷并修复）+ golden 基线。**能力已经存在，缺的是把它"说"出来并推向 L2-L4**。

**动作**：
1. **叙事与文档**：把"统一刀轨 IR 是大脑，11 种控制器方言是本体"明确写进架构文档与官网——这是江行验证过的成熟话语，且灵境制造是它在 CAM 领域的精确对应物。
2. **验证矩阵推进**：L2（golden 回归）已具备，L3（编程站）/L4（实机试切）依赖真机接入，排期绑定路线图 A 线"真实机床接入"，不单独推进。
3. **方言规则反哺**：L1 合规检查器抓出的违规模式沉淀为规则库，反哺后处理 DSL 的语法树定义，让同类缺陷在生成侧就不会出现。

**验收**：对外发布"官方支持机型清单"（× 验证等级）；每机型 golden 回归进 CI（`pytest.mark.postprocessor` 已有挂点）。

**风险**：清单一旦发布就是承诺边界，L1 与 L4 之间的机型要明确标注"语法合规、未经实机验证"，把分级本身作为诚实卖点。

### W4 飞轮充能（对标：智平方 sim2real + 浪潮数据资产）

**现状**：`data_flywheel` 插件骨架齐（feedback_collector / 模型迭代管线模板 / hot_update_manager / 看板）、cutting_experience API 已接线（`/api/v1/experience`）、实测回灌管线 `pipelines/feedback_loop.py` 已具备（去重/重试/异步，写入知识图谱 + TrainingDataLake）。**全链路管道都在，缺的是水**——真机未接（`dnc/mock_agent.py` 仍在生产角色上），经验库零冷启动。

**动作**（按"不等真机也能动"排序）：
1. **仿真合成数据先行**（智平方 sim2real 的 CAM 版）：用体素仿真 + 切削力模型做参数扫描（材料 × 刀具 × 转速 × 进给），批量生成"参数 → 仿真结果"对写入 TrainingDataLake。这是唯一不依赖真机、现在就能做的数据源，且与 `dreaming` 模块的定位天然契合。
2. **cutting_experience 冷启动**（路线图 A 线已列，本文确认其飞轮定位）：公开切削手册结构化入库 + 首个试点客户的老师傅经验采集——每次试点 = 飞轮充能，写进销售流程。
3. **真机接入后自动回灌**：`feedback_loop.py` 就是"持续反馈迭代"的落地管道，真机（FOCAS/MTConnect）接入后接线即可，不需要新开发。
4. **飞轮看板取真实数**（插件 p4-4）：对外讲"越用越准"必须有曲线证据，看板从 IDatasetStore 取真实规模/质量指标。

**验收**：合成数据集规模与分布报告；首版模型迭代在既有基准（`app/benchmarks/`）上可度量提升；试点客户经验样本 ≥N 条（N 由试点合同约定）。

**风险**：合成数据与真实切削存在分布差距（sim2real gap）→ 合成数据定位为"预训练/冷启动"，真实数据到达后做微调校准，叙事上诚实表述为"仿真起步、实机校准"。

### W5（轻量）边缘协同形态（对标：浪潮平台 + 江行边缘 AI）

不新开功能线，只对既有规划做叙事包装与排期确认：
- 路线图 C 线的 Docker 服务器形态，对外命名 **"厂内边缘节点"**——覆盖"内网全厂共用"需求，同时保住"数据不出厂"叙事不破。
- MCP 网关（stdio/SSE + 强制令牌）是对外生态接口的标准答案：让厂里已有的 Agent/排产/质检系统调用制造智能，而不是再造一个平台。
- 远期观察：与工业互联网平台（浪潮云洲一类）谈**"边缘节点"级对接**而非上云——他们是平台缺边缘内容，你是边缘缺渠道，互补不冲突。

### 4.2 W6 「工艺世界模型 + RL 优化」显性化（对标：智平方 AlphaBrain / 江行"物理 AI 大脑"）

**现状**：world_model 与 rl_agent 能力完整、测试最好，但产品里看不见——它们是"物理 AI"叙事最贴切的技术对应物，却没被用起来。

**动作**：
1. **世界模型进确认页**：工艺/参数确认界面展示"世界模型预演"卡（预测切削力、颤振倾向、碰撞概率 vs 阈值带），让用户确认前看到 AI 对物理结果的预判——把"敢上机"从事后闸门延伸到事前预演。（已完成 2026-09：`POST /api/v1/world-model/preview` 一次返回预演卡全量数据；Workspace 新增「物理预演」Tab 承载，阈值带全部引用仓库既有判据）
2. **rl_agent 安全护盾 = 自主权的执行体**：与主权/自主等级设置联动（见 W9.1），等级越低护盾介入越深，让"AI 起草、人确认"有机制支撑。（已完成 2026-09：护盾过滤后按等级保守缩放 L0=0.5/L1=0.7/L2+=1.0，行为矩阵 6 用例；预演卡展示阻尼标记；顺带修复 SafetyShield strict 回退可返回违规动作本身的真 bug）
3. **叙事直接采用"世界模型"话语**：这是物理 AI 阵营的通用词汇，无需发明新词。

**验收**：审批/确认页可见世界模型预测卡；主权等级切换能实际改变 rl_agent 介入程度（有行为矩阵测试）。
**风险**：预测与实测偏差会放大不信任 → 预测一律带置信区间展示，偏差数据进 W4 回灌校准。

### 4.3 W7 「自进化」实证引擎：dreaming 产品化（"越用越懂你"的证据链）

**现状**：dreaming 是完整的自进化闭环（规则合成/渐进发布/回滚），`flywheel_metrics` 五项指标（数据量/模型质量/采纳率/不确定性/回灌延迟）已设计好；缺口是零 API 出口、测试仅一角，"能力在地下室"。

**动作**：
1. **先补测试到可暴露水平**（当前仅 `test_dreaming_apply_rules`），这是本工作流的前置门槛。（已完成 2026-09：灰度发布 16 用例 + 回滚管理器 7 用例）
2. **最小 API 面**：触发反思 / 查看合成规则 / 灰度状态 / 一键回滚，四个端点。（已完成 2026-09：扩展为七端点——reflect / rules / publish（人工放行入影子）/ promote / rollback / status / learnings，`app/api/v1/dreaming.py`，注册进 workflows 域；反思管线提取为 `app/dreaming/service.py` 供 CLI 与 API 共用）
3. **前端"它这周学会了什么"**：飞轮看板新增规则卡片，每条合成规则带来源样本血缘（接 W2 provenance_id）——自进化从口号变成可审计的流水。（已完成 2026-09：飞轮看板第 5 个 Tab，时间线事件卡 + 中英双语；血缘字段（source_insight_category/supporting_sessions）已随 learnings 事件预留，深 度接入待 W2）
4. **把"灰度+可回滚"作为差异化话术**："AI 的自我改进永远可回滚"，这是多数竞品不敢承诺的信任点。

**验收**：一次完整的"经验→规则→灰度→转正/回滚"循环全程留痕并在看板可展示。
**风险**：错误规则污染下游 → 严格执行既有渐进发布与回滚机制，规则命中量小步放开。

### 4.4 W8 统一嵌入检索上线 + RAG 引用溯源（知识可信度工程）

**现状**：unified_embedding 零出口；RAG 混合检索链路强（BM25+向量 RRF+CrossEncoder+查询改写+评估）但**答案不带出处**——对工艺工程师这种"较真"用户，没有出处的建议等于不可采纳。

**动作**：
1. 给 unified_embedding 包一层检索 API（图纸特征 / 工艺案例 / 文本知识跨层检索），先接入 process_understanding 的方案生成路径做 A/B。（API 面已落地 2026-09：`app/api/v1/embedding_retrieval.py`（/encode /index /query /status，ai 域注册，5 用例）——由并行会话按本方案同步实施，本会话已删除重复构建让位；process_understanding A/B 接入与结构化条目便捷编码为后续项）
2. **RAG 答案加引用溯源字段**：每条建议带 [来源: 文档/案例 ID]，与 W2 血缘体系对齐。（已完成 2026-09：`/api/v1/rag/query` 双管线响应新增 `sources`（rank/source/doc_id/similarity/preview），10 用例）
3. **相似案例推荐**：新图纸自动推荐历史相似工艺案例（经血缘 ID 反查），这是"越用越懂你"在检索侧的体现，也是飞轮数据的第二消费方。（待飞轮数据起量，半年项不变）

**验收**：A/B 方案采纳率不低于现状；引用字段全量返回；相似案例推荐上线。
**风险**：嵌入本地推理延迟 → 走 ONNX 侧推理并控制首查延迟；召回质量依赖入库样本量 → 与 W4 冷启动同步推进。

### 4.5 W9 信任证据工程（把"敢上机"从设计变成可出示的证据）

**动作**：

**验收**：性能白皮书一份 + 颤振预测对照表 + 主权等级行为矩阵测试通过 + 监控页无默认假数据。

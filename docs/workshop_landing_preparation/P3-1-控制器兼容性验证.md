# P3-1: G 代码控制器兼容性验证 SOP（机床空运行）

**ADR 关联**: [ADR-019-车间落地准备.md](../adr/ADR-019-车间落地准备.md) P3-1

**责任人**: 项目负责人 + 持证 CNC 操作员 + 导师在场
**前置 ADR**: [ADR-014-G代码生成.md](../adr/ADR-014-G代码生成.md)、[ADR-018-CAM校验.md](../adr/ADR-018-CAM校验.md)

## 1. 目标

将阶段 6 生成的 `.nc` G 代码文件加载到真实 CNC 控制器（Fanuc 0i / Siemens 840D），在**不上工件、不上刀具**的条件下执行空运行，验证：

1. G 代码语法与目标控制器兼容（无格式报错）
2. 刀位轨迹在机床工作空间内（无超程报警）
3. 换刀序列顺畅（刀库动作正常）
4. 全程无异常报警

**产出**: `gcode_controller_compatibility_report.json`（含控制器型号、空运行结果、报警记录）

## 4. 执行 SOP

### 步骤 1：预检查（不上机，30 分钟）

1.1 打开 `.nc` 文件，核对首行 `%` 与末行 `%`（Fanuc 标准格式）

1.2 统计 G 代码中的关键指令：
   - `G00 / G01 / G02 / G03` 模态指令
   - `T__` 换刀指令（刀号列表）
   - `M06` 换刀执行
   - `M03 / M05` 主轴启停
   - `M30` 程序结束
   - `G54 ~ G59` 工件坐标系

1.3 对照机床工作空间参数，检查 G 代码 AABB 包围盒是否在行程内：
   ```
   X_min ≥ 机床 X_min + 10mm 安全裕量
   X_max ≤ 机床 X_max - 10mm
   Y/Z 同理
   ```

1.4 若 1.3 失败，**终止本次空运行**，回到阶段 6 修复 G 代码后重新校验。

### 步骤 2：机床准备（操作员执行，15 分钟）

2.1 操作员开机回零，确认机床坐标系正常

2.2 **卸下工件与夹具**（空运行不上工件）

2.3 **卸下真实刀具**，刀库仅保留对刀块或空刀柄占位

2.4 设置机床为「空运行模式」（Dry Run）+「单段模式」（Single Block）

2.5 进给倍率旋钮调至 0%（后续逐步提升）

### 步骤 3：G 代码加载（操作员执行，10 分钟）

3.1 通过 DNC / RS232 / U 盘将 `.nc` 文件传入控制器

3.2 在编辑模式下打开程序，目视检查首 20 行 + 末 10 行无乱码

3.3 若控制器支持语法预校验（Fanuc 0i 的 PROG CHECK），执行预校验

3.4 若预校验报错，**记录报警号 + 报警信息**，终止本次空运行

### 步骤 4：单段试运行（操作员执行，30 分钟）

4.1 启动单段模式，按「循环启动」执行第 1 段（通常是 `G54 G90 G17` 安全初始化）

4.2 观察机床动作：
   - 是否回参考点
   - 是否切换到正确工件坐标系
   - 主轴是否启动（M03）

4.3 逐步按「循环启动」执行后续单段，重点关注：
   - 首个 `G00` 快速移动：方向是否正确，是否超程
   - 首个 `T__ M06` 换刀：刀库动作是否正常
   - 首个 `G01` 切削进给：进给倍率是否生效

4.4 若任一单段报警，**立即记录报警号 + 段号 + 机床状态**，按急停，终止本次空运行

### 步骤 5：全程空运行（操作员执行，20 分钟）

5.1 单段试运行无异常后，切换到「自动模式」（保留空运行模式 + 进给倍率 25%）

5.2 按「循环启动」全程执行，操作员手悬于急停按钮

5.3 项目负责人同步录像（手机即可），重点记录：
   - 换刀全过程
   - G00 快速移动极限位置
   - 主轴启停时机
   - 程序结束（M30）后机床状态

5.4 若中途报警，**立即按急停，记录报警号 + 段号 + 机床位置**

### 步骤 6：报警汇总与判定（10 分钟）

6.1 操作员汇总全程报警记录（报警号 / 段号 / 描述 / 处置）

6.2 判定矩阵：

| 报警类型 | 判定 | 处置 |
|----------|------|------|
| 无报警 | PASS | 进入步骤 7 |
| 超程报警（Overtravel） | FAIL | 阶段 6 修复 G 代码 AABB |
| 换刀报警 | FAIL | 核对刀库映射表 |
| 语法报警 | FAIL | 阶段 6 修复 G 代码格式 |
| 主轴报警 | FAIL | 检查 M03/M05 指令与主轴参数 |
| 急停触发 | FAIL | 排查原因后重新评估 |

### 步骤 7：生成验证报告（项目负责人执行，15 分钟）

填写 `gcode_controller_compatibility_report.json`（模板见第 5 节），打印一份纸质件，操作员 + 导师 + 项目负责人三方签字。

## 7. 失败回退路径

### 7.1 超程报警 → 阶段 6 修复

回到阶段 6 G 代码生成器，调整 AABB 包围盒（缩小切削范围或平移工件坐标系），重新生成 `.nc` 文件 → 重新走阶段 7 CAM 校验 → 重新走 P3-1。

### 7.2 语法报警 → 控制器后处理配置

阶段 6 G 代码生成器可能未针对目标控制器后处理（如 Fanuc 0i 与 Siemens 840D 的 G 代码格式差异）。修复 `python/app/gcode_generator/post_processors/` 下对应控制器的后处理器，重新生成 → 重新走阶段 7 → 重新走 P3-1。

### 7.3 换刀报警 → 刀库映射核对

核对 G 代码中 `T__` 指令与机床实际刀库刀位映射，修复阶段 6 的刀具号分配逻辑。

## 8. 已知工程边界

1. **空运行 ≠ 真实加工**：P3-1 仅验证控制器兼容性，不验证切削力 / 颤振 / 表面质量（这些需 P3-3 / P3-4）
2. **Fanuc 0i-MF 与 Fanuc 0i-Mate-TD 差异**：同系列不同子型号的 G 代码格式可能略有差异，P3-1 仅对当日实际使用的机床型号负责
3. **DNC 传输 vs U 盘传输**：DNC 传输可能因波特率问题导致长程序丢字符，建议优先 U 盘传输
4. **录像不可替代签字**：录像仅作为辅助证据，合规以签字为准

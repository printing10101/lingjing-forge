# P3-5: 合规链路归档模板（车间落地全链路产物索引）

**ADR 关联**: [ADR-019-车间落地准备.md](../adr/ADR-019-车间落地准备.md) P3-5
**状态**: 待执行（P3-1 ~ P3-4 完成后启动归档）
**责任人**: 项目负责人（归档协调） + 导师（审核） + 持证操作员（确认）
**前置文档**: [P3-1-控制器兼容性验证.md](P3-1-控制器兼容性验证.md)、[P3-3-颤振模型校准试验.md](P3-3-颤振模型校准试验.md)、[P3-4-首次试切件质量检测.md](P3-4-首次试切件质量检测.md)

---

## 1. 目标

将车间落地全链路（照片 → cam_report.json → 试切件质量报告）涉及的全部合规材料、技术产物、签字记录、实物资产纳入统一归档索引，确保：

1. **可追溯**：任何一个试切件都能反向追溯到原始照片、CAD 模型、G 代码、CAM 校验报告、操作员证件、保险凭证
2. **可审计**：外部审计（导师 / 学校 / 期刊 / 工业合作方）可在 30 分钟内调阅全部材料
3. **可复现**：在其他车间、其他机床上可基于归档材料复现试切
4. **合规存证**：满足工业安全规程、保险理赔、学术诚信的全部存证要求

**产出**: `workshop_landing_archive.json`（合规归档索引，全链路材料的"目录页"）

## 2. 工业硬门槛（必须满足，无例外）

| 门槛 | 要求 | 验证方式 |
|------|------|----------|
| 操作员资质 | 持证 CNC 操作员 | 证件复印件归档 + 证件编号入索引 |
| 导师签字 | 全程关键节点签字 | 签字记录扫描件归档 |
| 车间保险 | 已生效（覆盖试切全程） | 保险凭证扫描件归档 + 保单号入索引 |
| 安全规程 | 操作员已阅读并签字 | 安全规程签字件归档 |
| 试切件实物 | 实物归档 + 标签唯一编号 | 实物归档位置入索引 |
| 视频录像 | 试切全程录像（不可替代签字） | 录像文件路径入索引 |
| 全链路产物 | 阶段 0-7 产物完整 | 各阶段产物路径入索引 |
| 检测报告 | P3-1 / P3-3 / P3-4 报告齐备 | 报告 ID 入索引 |

## 3. 归档分类体系

### 3.1 一级分类：6 大类

| 类别代码 | 类别名称 | 内容简述 | 保管期限 |
|----------|----------|----------|----------|
| A | 人员资质材料 | 操作员证、导师证、测量员证 | 长期（证件有效期内） |
| B | 合规凭证材料 | 保险、安全规程、申请单 | 长期（保单有效期内） |
| C | 全链路技术产物 | 阶段 0-7 产物（照片 → cam_report.json） | 永久 |
| D | 车间试切过程材料 | P3-1 / P3-3 / P3-4 报告、视频、照片 | 永久 |
| E | 试切件实物 | 试切件本体、毛坯余料 | ≥ 5 年 |
| F | 签字记录材料 | 各环节签字扫描件 | 永久 |

```

  A-1  CNC 操作员证件

  C-1  阶段 1：3D 重建产物（点云 / mesh）
  C-2  阶段 2：几何特征 JSON
  C-3  阶段 3：STEP + OperationPlan
  C-4  阶段 4：ChatterParams JSON
  C-5  阶段 5：ChatterReport JSON
  C-6  阶段 6：G 代码 .nc + gc_<uuid>_report.json
  C-7  阶段 7：cam_<uuid>.cam_report.json + cam_<uuid>.internal_report.json

  D-2  P3-3 校准试验报告 + 校准试验视频 + 信号原始数据
```

## 5. 执行 SOP

### 步骤 1：归档初始化

1. 生成归档唯一 ID：`archive_<YYYYMMDD>_<short_uuid>`（如 `archive_20260715_a1b2c3`）
2. 创建归档根目录 `data/workshop_archive/archive_<id>/`
3. 创建六大子目录：A 人员资质 / B 合规凭证 / C 全链路产物 / D 试切过程 / E 试切件实物 / F 签字记录
4. 初始化 `workshop_landing_archive.json`（基于第 6 节模板）
5. 记录归档开始时间戳

### 步骤 2：人员资质材料归档（A 类）

1. 扫描 CNC 操作员证件（正反面） → `A-1/operator_certificate_<name>.pdf`
2. 扫描导师身份与资质证明 → `A-2/mentor_credential_<name>.pdf`
3. 扫描三坐标测量员资质证书 → `A-3/cmm_operator_credential_<name>.pdf`
4. 扫描项目负责人学生证 → `A-4/student_id_<name>.pdf`
5. 在索引文件 A 类下登记每份材料的：文件路径、扫描日期、证件有效期、SHA-256 哈希

### 步骤 3：合规凭证材料归档（B 类）

1. 扫描车间保险凭证 → `B-1/insurance_certificate_<policy_number>.pdf`
2. 归档车间安全规程操作员签字件 → `B-2/safety_procedure_signed_<date>.pdf`
3. 归档试切申请单（导师签字） → `B-3/cutting_application_signed_<date>.pdf`
4. 归档 P3-3 校准试验方案审批件 → `B-4/calibration_plan_approved_<date>.pdf`
5. 归档 P3-4 试切件检测委托单 → `B-5/inspection_commission_<date>.pdf`（如适用）
6. 在索引文件 B 类下登记每份材料的：文件路径、签字日期、保单号、有效期、SHA-256

### 步骤 4：全链路技术产物归档（C 类）

1. 阶段 0 原始照片 → `C-0/photos/<photo_id>.jpg` + `C-0/photo_environment.json`（光照 / 角度 / 设备）
2. 阶段 1 3D 重建产物 → `C-1/<task_id>_pointcloud.ply` + `<task_id>_mesh.obj`
3. 阶段 2 几何特征 JSON → `C-2/<task_id>_geometry_features.json`
4. 阶段 3 STEP + OperationPlan → `C-3/<task_id>.step` + `<task_id>_operation_plan.json`
5. 阶段 4 ChatterParams JSON → `C-4/<task_id>_chatter_params.json`
6. 阶段 5 ChatterReport JSON → `C-5/<task_id>_chatter_report.json`
7. 阶段 6 G 代码 + 报告 → `C-6/<gcode_task_id>.nc` + `gc_<gcode_task_id>_report.json`
8. 阶段 7 CAM 报告 → `C-7/cam_<cam_task_id>.cam_report.json` + `cam_<cam_task_id>.internal_report.json`
9. 在索引文件 C 类下登记每个产物的：阶段号、task_id、文件路径、生成时间戳、SHA-256

### 步骤 5：车间试切过程材料归档（D 类）

1. P3-1 控制器兼容性报告 → `D-1/gcode_controller_compatibility_report.json` + 空运行视频 `D-1/dry_run_video_<date>.mp4`
2. P3-3 校准试验报告 → `D-2/hrc52_calibration_experiment_report.json` + 信号原始数据 `D-2/raw_signals/<test_no>/` + 试验视频 `D-2/calibration_video_<date>.mp4`
3. P3-4 试切件质量报告 → `D-3/first_part_quality_report.json` + CMM 报告 `D-3/cmm_report.pdf` + 粗糙度数据 `D-3/roughness_raw/`
4. 试切现场照片 → `D-4/site_photos/<stage>/`（装夹 / 对刀 / 加工 / 卸件四阶段）
5. 试切过程视频 → `D-5/cutting_video_roughing_<date>.mp4` + `D-5/cutting_video_finishing_<date>.mp4`
6. 在索引文件 D 类下登记每份材料的：材料类型、关联阶段、文件路径、SHA-256、视频时长

### 步骤 6：试切件实物归档（E 类）

1. 首件试切件贴标签（标签模板见 P3-4 第 6.2 节）
2. 涂抹防锈油 → 真空袋封装（加干燥剂） → 归档到指定货架位置
3. P3-3 校准试验件（27 件或代表性样本）按相同流程封装归档
4. 毛坯余料单独封装归档（用于后续可能的材料成分复检）
5. 在索引文件 E 类下登记每件实物的：实物编号、归档位置（货架-层-位）、封装日期、状态（合格/不合格）

### 步骤 7：签字记录材料归档（F 类）

1. P3-1 三方签字件扫描 → `F-1/p3_1_signatures_<date>.pdf`
2. P3-3 校准试验签字件扫描 → `F-2/p3_3_signatures_<date>.pdf`
3. P3-4 良品率判定签字件扫描 → `F-3/p3_4_signatures_<date>.pdf`
4. 归档完整性审核签字件（导师终审） → `F-4/archive_review_signed_<date>.pdf`
5. 在索引文件 F 类下登记每份签字件的：关联阶段、签字人、签字日期、文件路径、SHA-256

### 步骤 8：归档完整性校验

1. 比对索引文件登记条目数与实际文件数（应一致）
2. 抽取 10% 的文件重新计算 SHA-256，与索引记录比对（应一致）
3. 检查索引文件每条记录的必填字段（无空值）
4. 检查跨阶段引用一致性（如 P3-4 报告引用的 cam_report_id 应在 C-7 中存在）
5. 生成归档完整性校验报告 `archive_integrity_check_report.json`

### 步骤 9：导师终审与归档封存

1. 导师审阅归档完整性校验报告
2. 导师在 `F-4/archive_review_signed_<date>.pdf` 上签字
3. 归档目录设置为只读（防篡改）
4. 备份归档目录到 U 盘 + 移动硬盘 + 云存储
5. 在 `workshop_landing_archive.json` 中记录封存时间戳 + 封存操作人

## 7. 验收标准（充要条件，全部满足方为归档完成）

### 7.1 完整性验收

1. 索引文件 `workshop_landing_archive.json` 六大类（A/B/C/D/E/F）全部非空
2. 索引登记条目数 = 实际文件数（含视频、照片、JSON、PDF 等）
3. 索引文件每条记录的必填字段（item_id / file_path / sha256）无空值

### 7.2 完整性校验验收

4. `archive_integrity_check_report.json` 的 `overall_pass=true`
5. SHA-256 抽样校验通过率 100%
6. 跨阶段引用一致性校验全部通过

### 7.3 合规验收

7. A 类全部人员证件在有效期内
8. B-1 保险凭证在试切日期范围内有效
9. B-2 / B-3 / B-4 签字件齐全且签字日期不晚于试切日期
10. F 类全部签字件齐全（P3-1 / P3-3 / P3-4 / 归档终审）

### 7.4 可追溯性验收

11. 任一试切件实物编号 → 可在 E 类查到归档位置
12. 任一试切件 → 可在 D-3 查到质量报告 → 可在 C-7 查到 CAM 报告 → 可在 C-6 查到 G 代码 → 可在 C-0 查到原始照片
13. 全链路追溯可在 30 分钟内完成（外部审计模拟测试）

### 7.5 备份验收

14. 归档目录已设置只读
15. 至少 3 套备份（U 盘 + 移动硬盘 + 云存储）已生成
16. 备份介质的 SHA-256 与原档一致

### 7.6 终审验收

## 8. 失败回退路径

### 8.1 文件缺失（索引登记条目数 > 实际文件数）

- **原因**：归档过程中遗漏、文件被误删、文件路径错误
- **处置**：定位缺失文件来源（哪个 P3 阶段），从该阶段重新导出；若无法找回，需在索引 `issues_found` 字段记录原因，导师签字确认

### 8.2 SHA-256 不一致

- **原因**：文件被篡改、存储介质损坏、扫描件重新生成
- **处置**：立即停止归档封存，定位不一致文件，重新归档原档；记录事件到 `issues_found`，必要时通知保险方与导师

### 8.3 跨阶段引用断裂

- **原因**：上游阶段产物丢失或 task_id 书写错误
- **处置**：从灵境制造系统重新运行对应阶段生成产物（如 CAM 报告可基于 G 代码重新校验），重新归档并更新引用

### 8.4 签字件缺失

- **原因**：某环节忘记签字或签字件遗失
- **处置**：不可补签的签字（如操作员已离职）→ 在 `issues_found` 记录并请导师出具情况说明；可补签的签字 → 召集相关人员补签并扫描归档

### 8.5 实物试切件损坏

- **原因**：防锈不当导致氧化、物理撞击变形
- **处置**：保留损坏件作为证据，记录损坏原因；如可能，基于归档的 G 代码与切削参数重新试切（重新走 P3-4 流程）

## 9. 已知工程边界

### 9.1 数字归档的局限性

- **存储介质寿命**：U 盘 / 移动硬盘寿命 5-10 年，需定期迁移到新介质
- **云存储依赖**：云存储可能因账号失效、服务商倒闭而丢失，建议多家云存储冗余
- **文件格式兼容性**：长期归档应选用开放格式（PDF/A、JSON、CSV），避免专有格式（如 NX .prt）随软件版本淘汰无法打开

### 9.2 实物归档的局限性

- **铝合金氧化**：6061-T6 长期保存可能氧化，防锈油 + 真空袋只能延缓不能阻止
- **HRC52 锈蚀**：淬火钢更易锈蚀，需特别加强防锈
- **实物丢失风险**：车间人员流动可能导致实物归档位置被挪动，需定期盘点

### 9.3 视频录像的局限性

- 视频可记录过程但不可替代签字（项目记忆硬约束）
- 视频文件体积大，长期归档需考虑存储成本
- 视频清晰度需满足"可看清刀位与切削状态"的最低要求（建议 1080p 以上）

### 9.4 与论文 / 审计的关系

- **论文**：归档索引是论文附录"实验数据可追溯性"的核心证据，审稿人可基于归档 ID 核查数据真实性
- **学校审计**：归档材料是大学生创新创业项目结题、毕业设计答辩的必备材料
- **工业合作方**：如未来与机床厂 / CAM 软件厂商合作，归档材料是技术成果转移的交付物

### 9.5 与 P3-1 / P3-3 / P3-4 的依赖关系

- P3-5 必须在 P3-1 / P3-3 / P3-4 全部完成后启动（否则归档不完整）
- 若 P3-1 / P3-3 / P3-4 中途失败重做，P3-5 归档需同步更新（避免归档旧版本产物）
- 归档封存后**不可修改**，如需补充材料需开新归档 ID（`archive_<new_date>_<new_uuid>`）并引用旧归档 ID

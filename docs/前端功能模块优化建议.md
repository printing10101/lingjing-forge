# 前端功能模块优化建议

## 一、整体架构评估

**当前状态**（版本 2.7.0）
- 视图（views）页面：47 个
- 组件目录：232 个文件（已按功能拆解）
- 组件拆分成熟度：（优秀）
- 代码复用程度：（良好）

---

## 二、功能重叠分析

### **高风险重叠（需要合并）**

#### 1. 审批管理模块重叠
**现状**：存在两个审批 Dashboard
- `/approval-dashboard` → `ApprovalDashboard.vue`（ Tabs 结构：pending/approved/rejected/history）
- 系统中还散落多个审批相关页面

**建议**：
- 保留当前 `ApprovalDashboard.vue`（已被拆分成 `ApprovalStatsCards` + `ApprovalRequestList`）
- 检查并删除重复的审批入口或子页面
- **行动项**：遍历所有路由，识别审批流程相关页面，合并为单一路径 `/approvals`

---

#### 2. 成本/费用管理模块冗余
**现状**：至少 3 个成本相关入口
- `/cost-dashboard` → 成本分析 Dashboard
- `cost/` 目录下的 7 个子组件（`CostAlertsTable`/`CostBudgetCards`/`CostTrendChart`等）
- 可能与其他模块（如生产报告）存在统计重叠

**建议**：
- 整合为单一路径 `/costs`，包含以下 Tab：
  - 预算概览（BudgetCards + TrendChart）
  - 成本拆解（DistributionChart）
  - 预警记录（AlertsTable）
- 共享统计计算逻辑到 composable
- **行动项**：审查 `CostDashboard.vue` 与其他统计页面的重复度

---

#### 3. 代理/代理人管理分散
**现状**：3 个相关文件/页面
- `/agent-dashboard` → `AgentDashboard.vue`（代理状态监控）
- `/agent-detail/:id` → `AgentDetail.vue`
- `agent/` 目录下的 7 个子组件
- `rl_agent/` 目录下的 5 个子组件（强化学习代理）

**问题**：`AgentDashboard` 与 `RLAgent` 可能管理不同类型的"代理"
- Agent = AI 任务执行代理
- RLAgent = 强化学习模型训练代理

**建议**：
- 确认业务语义，决定是否合并
- 如需要合并：
  - 父路径 `/agents`
  - Dashboard 作为列表页
  - `AgentDetail` 和 `RLAgentDetail` 作为详情路径（共享组件 `AgentMemoryPanel`）
- 如不需合并：在 UI 上明确区分（不同图标/分类）

---

### **中风险重叠（需要协调）**

#### 4. 统计卡片组件重复实现
**现状**：统计卡片在多处重复
```
- ApprovalStatsCards.vue
- CostBudgetCards.vue
- EquipmentStatsCards.vue
- FlywheelOverview.vue (内置 Stats)
- MaterialStatsCards.vue
- QualityStatsCards.vue
- ProductionSummaryCards.vue
- home/KpiCards.vue
```

**分析**：
- 已有通用设计模式：3-4 个卡片横向排列
- 但每处都是独立实现，无共享 composable

**建议**：
- 创建 `useStatsCards` composable：
  ```typescript
  // src/composables/headless/useStatsCards.ts
  export function useStatsCards(items: StatItem[]) {
    const stats = ref(...)
    const colorTagType = (type: string) => ...
    return { stats, colorTagType }
  }
  ```
- 创建通用 `StatsCards.vue` 组件（替代现有 8 个专用组件）
- 迁移成本：约 3-4 小时

**收益**：
- 减少代码量：~400 行 → 1 个通用组件
- 统一视觉体验
- 方便后续维护和扩展

---

#### 5. 表格/列表组件抽象不足
**现状**：大量重复的表格实现
```
- ProcessRouteCard.vue（卡片式列表）
- ApprovalTable.vue
- CostAlertsTable.vue
- EquipmentDeviceTable.vue
- MaterialListTable.vue（已拆分为独立组件 ）
- ProductionRecordsTable.vue
- ProductionWorkOrdersTable.vue
- QualityRecordsTable.vue
- WorkflowListPanel.vue
```

**分析**：
- `MaterialListTable.vue` 是最佳实践：纯展示组件 + emits 事件
- 其他表格仍散布在页面中

**建议**：
- 创建 `BaseDataTable.vue` 组件（复用 `useDataTable` composable）
- 所有表格统一继承该 Base 组件
- 差异化通过 props 注入（列配置/操作按钮）

**优先级**：中（已有 `useDataTable` composable，需推广）

---

#### 6. 筛选/搜索组件重复实现
**现状**：几乎所有页面都有筛选/搜索逻辑
- `ProcessPlanningFilters.vue`（独立组件 ）
- `QualityInspection.vue` 内联筛选（el-select + el-input）
- `MaterialManagement.vue` 内联筛选
- `WorkflowPanel.vue` 内联筛选

**建议**：
- 将筛选逻辑抽象为通用 `BaseFilterBar.vue`
- 支持配置化：
  - filterTypes: Array<{key, label, options}>
  - searchPlaceholder: string
  - debounceMs: number
- 复用 `ProcessPlanningFilters.vue` 的实现

---

### **低风险可优化（提升空间）**

#### 7. Dialog/模态框模式不统一
**现状**：
- 弹窗命名不一致：`*Dialog.vue` / `*Panel.vue` / `*Detail.vue`
- 部分使用 `el-dialog`，部分自定义组件
- 缺少统一的表单验证 schema

**建议**：
- 统一命名规范：操作类用 `*Dialog`，展示类用 `*Panel`
- 创建 `BaseDialog.vue`（含 loading/error 状态处理）
- 收集复用率>2 的 Detail/Dialog 组件，抽象为通用模式

---

#### 8. 错误处理分散
**现状**：多处内联的错误处理逻辑
- `loading`/`loadError` 状态在各页面重复声明
- 错误提示 `ElMessage.error()` 散落在 catch 块
- 缺少统一的错误码映射

**建议**：
- 创建 `useErrorCode` composable
- 定义错误码枚举：`NETWORK_ERROR`, `PERMISSION_DENIED`, `NOT_FOUND` 等
- 统一映射到用户友好的提示文本

---

## 三、可合并的模块建议

### **优先级：高**

#### 1. 统计数据集整合
**当前**：分散在多个 Dashboard
- Home KPI 卡片
- CostDashboard
- ProductionReport
- QualityStatsCards
- MaterialStatsCards

**合并方案**：
```
创建 `/dashboard` 作为统一数据可视化入口
├── 生产看板（替换 Home.vue 的 KPI）
│   ├── 实时产能卡片
│   ├── 设备稼动率
│   └── 质量合格率
├── 成本看板（整合 CostDashboard）
├── 质量看板（整合 QualityInspection 统计）
```

**实施步骤**：

## 五、UX 流程优化建议

### **高频操作路径优化**

#### 1. 新工件创建流程
**当前操作路径**（以新建工艺路线为例）：
```
工艺规划 → 新建按钮 → 弹窗表单 → 填写 → 提交 → 返回列表
```

**问题**：弹窗表单需反复切换上下文

**优化**：
- 考虑将表单改为侧边抽屉（SlideDrawer）
- 或使用 `ModalForm` 模式（页面内嵌表单）
- 减少页面跳转

**实施**：
- 创建 `ModalForm.vue` 组件
- 支持动态列配置（可复用所有表单页面）

---

#### 2. 详情/编辑入口统一
**当前**：
- 点击卡片 → Detail 弹窗
- Edit 按钮 → Edit 弹窗（部分与 Detail 共用弹窗）

**建议**：
- 统一为：卡片点击 → Detail，Edit 按钮 → ModalForm
- 部分场景支持 Detail → Edit 直接跳转（保持 Dialog 关闭状态）

---

#### 3. 数据刷新机制
**当前**：
- 各页面独立实现刷新（`handleRefreshAll`，`fetchData`）
- `FlywheelDashboard` 有 `handleRefreshAll + handleRefreshMetrics` 组合刷新
- 缺少全局统一刷新机制（如按刷新所有页面）

**建议**：
- 创建 `useRefreshHandler` composable
- 支持刷新时取消 pending 的请求
- 支持并发控制（最多同时 3 个刷新请求）

---

### **响应式优化**

#### 1. 卡片布局
**当前**：Grid 栅格系统
```css
.card-grid {
  grid-template-columns: repeat(2, 1fr);
}
```

**建议**：
- 响应式断点增加：
  ```css
  @media (max-width: 900px) { grid-template-columns: 1fr; }
  ```
- 考虑 3 列 + 1 列的自适应布局（按卡片重要性排序）

---

#### 2. 移动端适配
**现状**：桌面优先设计，移动端未优化

**建议**：
- 当前优先级低（B 端软件，主要在桌面使用）
- 如需要支持平板：
  - 增加触摸友好的手势
  - 按钮尺寸 ≥ 44px（苹果建议）
  - 表格改为卡片列表视图

---

### **视觉体验优化**

#### 1. 加载状态差异化不够
**当前**：
- `loading` = 旋转图标
- `loadError` = 空状态 + 重试按钮

**建议**：
- 增加骨架屏（Skeleton）作为初步加载状态
- 分阶段加载：
  - 阶段 1：骨架屏（快速反馈）
  - 阶段 2：真实数据 + 局部加载
  - 阶段 3：全部加载完成

---

#### 2. 空状态文案优化
**当前**：
- "暂无预警"
- "暂无数据"
- "加载中..."

**建议**：
- 空状态文案需引导用户行动：
  - "暂无预警 → 查看设备列表，开始监控"
  - "暂无工艺路线 → 新建第一条路线"
  - "暂无检测结果 → 首次检测后自动显示"
- 配合 CTAs（Call to Action）按钮

## 七、技术债务清理

### **待清理项**

#### 1. 组件命名规范不一致
**问题**：
- `*Dialog` / `*Panel` / `*Detail` 混用
- `*Form` / `*Edit` / `*Create` 混用

**建议**：
- 统一为：
  - **Dialog** = 可以操作（创建/编辑/删除）
  - **Panel** = 只读展示
  - **Detail** = 详情页（新路径）

**实施**：
- 逐个页面审查，重构命名
- 保持向后兼容（添加别名）

---

#### 2. 样式变量未统一
**当前**：
- `var(--page-padding)` / `var(--content-max-width)` 已使用
- 但部分颜色值硬编码（`var(--text-tertiary)`）

**建议**：
- 在 `src/styles/variables.css` 中定义完整设计系统
- 提取所有硬编码的 hex color → CSS 变量
- 包括：成功（green）、警告（orange）、危险（red）

---

#### 3. 错误处理内联过多
**问题**：
- `try/catch` + `ElMessage.error()` 在多处重复
- 缺少统一的错误码枚举

**建议**：
- 创建 `src/utils/error-handler.ts`：
  ```typescript
  export function handleError(error: unknown, defaultMessage: string) {
    const code = extractErrorCode(error)
    const message = ERROR_CODES[code] || defaultMessage
    ElMessage.error(message)
  }
  ```
- 定义 `ERROR_CODES` 映射表

# 灵境制造 - 版本管理策略

## 版本命名原则

### 当前版本：2.8.0（开发基线）

**定位**：**稳定的开发版本**，代表当前成熟的功能集，但尚未完成全部自主化任务。

---

## 版本分类体系

### A. 开发版本 (2.x.y)
- **适用范围**：当前迭代中的功能
- **特点**：
  - 每 2-4 周一个小版本（2.7.0 → 2.7.1 → 2.7.2）
  - 每 2-3 个月一个大版本（2.7.x → 2.8.0）
  - 新增功能标记为 `x.y.0`
  - Bug 修复标记为 `x.y.Z`
- **使用场景**：
  - 内部测试/持续集成
  - 早期用户反馈
  - 新功能试验

### B. 稳定版本 (1.0.0)
- **适用范围**：工厂正式部署
- **前置条件**（必须全部满足）：
  1. Phase 1-4 自主化任务全部完成（P1-1/2/3, P2-1/2/3, P3-1/2, P4-1/2）
  2. Phase F 工厂现场端到端验证（真实机床数据）
  3. 100% 生产级门禁通过（Q1-Q5, T1-T6, S1-S5, R1-R4）
  4. 自主代码占比 ≥50%（P5-2 验证）
  5. 用户验收测试（UAT）通过
  6. 完整的生产部署文档与运维手册
  7. 90 天稳定运行无重大故障
- **使用场景**：
  - 工厂/车间正式生产环境
  - 对外商业发布

### C. 试验版本 (0.x.x)
- **适用范围**：早期原型/技术验证
- **特点**：
  - 快速迭代，不稳定
  - 功能不全，可能频繁破坏
- **状态**：已完成（历史版本）

## 版本发布流程

### 日常提交（2.7.x）
```bash
# 功能开发
git commit -m "feat(python): 数据飞轮数据采集 API"

# Bug 修复
git commit -m "fix(api): 修复路径参数解析边界条件"

# 重构
git commit -m "refactor(ai): LNN 推理引擎优化"
```

### 小版本发布（2.7.0 → 2.7.1）
1. **条件**：3-5 个 Bug 修复 + 1-2 个小功能
2. **流程**：
   - 分支：`release/2.7.1`
   - 合并测试：全量回归（1976 测试）
   - 文档更新：CHANGELOG.md
   - 打标签：`git tag v2.7.1`
3. **通知**：内部公告 + Jira/钉钉

### 大版本发布（2.7.x → 2.8.0）
1. **条件**：Phase 1-2 关键任务完成
2. **前置门禁**：
   - P5-2 自主占比验证 ≥30%
   - Phase F 厂内验证（模拟环境）
   - 安全审计通过
3. **文档**：
   - CHANGELOG.md（详细变更）
   - 升级指南（Breaking Changes）
   - 迁移脚本（如需要）

## 关键注意事项

### 1. 不承诺「正式版」之前
- 避免对外宣称「可直接投入生产」
- 保留接口/配置变更权利
- 明确标注为「开发版」

### 2. 工厂部署前的准备
若将来发布 1.0.0，需准备：
- **部署文档**：Docker/K8s 配置/数据库迁移脚本
- **运维手册**：监控告警/日志收集/备份恢复
- **用户培训**：操作视频/常见问题解答
- **服务承诺**：SLA（服务级别协议）/ 响应时间

### 3. 自主化目标不可妥协
- 任何任务未完成 ≠ 发布正式版
- 门禁未通过 = 任务未完成
- 严格遵循 `自主化与护城河路线图`

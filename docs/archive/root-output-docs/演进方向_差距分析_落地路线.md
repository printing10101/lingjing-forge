> Phase 0 交付物 · 2026-08-15 · 依据代码实地勘察（Explore 子代理 + 关键文件精读）
> 目标：为 5 个演进方向（借鉴自 5 个前沿开源项目）建立"现状→差距→落地"基线。

## 2. 五方向差距分析 + 落地路线

### 方向 ③ Pointer-CAD：NL2CAD 拓扑校验 + 失败重生成闭环（Phase 1a）
- **现状**：生成路径是"CV 提参 + 参数模板"，无 LLM 生成 CadQuery 代码；`_CadQueryScriptValidator` 只管 AST 安全，**没有几何层校验**（isValid/体积/最小特征尺寸）。
- **差距**：① 无几何合法性门禁；② 无失败重生成；③ 无 LLM→CadQuery 桥（可作为后续扩展，先用参数模板验证闭环）。
- **落地**：新增 `app/cad/_brep_validator.py`（OCC 校验：isValid/isSolid/体积>0/包围盒/最小边长）；接入 `generate_3d_model`/`generate_with_features`/`execute_and_export`（导出前校验 + STEP 回读校验）；`generate_3d_model_with_retry`（失败→剔除致错特征/退化尺寸→重试）。测试覆盖。
- **涉及文件**：新建 `_brep_validator.py`；改 `cadquery_gen.py`。

### 方向 ⑤ NumCraft：SafetyValidator + NL→NC 多智能体（Phase 1b）
- **现状**：`AgentOrchestrator` 是**线性管道**；`ConfigLimiter` 有转速/进给 clamp 但分散；`physics_validator` 可复用。
- **差距**：① 无统一"多智能体编排"（工具调用/分支/回退）；② 无独立安全校验器层（刀长/行程/进给/转速统一限界+多级校验）；③ 无自然语言直出 NC 的端到端入口。
- **落地**：新增 `SafetyValidator`（聚合 `_limiter` + `physics_validator` + `collision_detector` + 刀长/控制器语法白名单），挂到 `GeneratorAdapter.adapt()` 输出前；orchestrator 增加 `validate_safety` 步骤 + 失败回退；提供 `nl_to_nc` 高层入口。测试覆盖。
- **涉及文件**：新建 `app/gcode_generation/safety_validator.py`；改 orchestrator/generator_adapter。

### 方向 ② A2M：设备元数据 → MCP 工具自动生成（Phase 2）
- **现状**：MCP 已具备 SSE+Bearer+`@server.tool` 注册模式；`app/integrations/opcua/adapter.py` 有自动发现。
- **差距**：① 无设备元数据模型（AAS 风格）；② 工具是手写，不能由元数据生成；③ 无"设备→工具→Agent"闭环。
- **落地**：新增 AAS 风格 `DeviceDescriptor` 模型；`mcp_server/tools.py` 增加 `register_device_tools(descriptor)` 动态注册；配 `simulation/` 仿真设备作数据源。测试覆盖。
- **涉及文件**：新建设备模型模块；改 `mcp_server/tools.py`。

### 方向 ④ Mamba/SSM 预测 backbone（Phase 3a）
- **现状**：LNN 注册扩展点成熟（`register_lnn_predictor`）；`LNNTrainer` 可复用；`BaseLNN` ABC 清晰。
- **差距**：① 无 SSM 模型；② 无数据管线（用户暂无自采数据，需合成/标定公开基准）；③ 工程侧推理未接 SSM。
- **落地**：新建 `research/models/torch_mamba_lnn.py` 继承 `BaseLNN`（若 mamba-ssm 安装困难，先实现 S4 简化版兜底）；新建合成时序管线（切削力/振动仿真信号，可叠加噪声/颤振标签）；训练脚本 + 工程侧 `register_lnn_predictor` 挂接。先用 force_vibration_567/PHM2010 冒烟。
- **涉及文件**：research 新增 2-3 文件；工程侧注册扩展。

### 方向 ① SUPCON：仿真工厂闭环控制沙盒（Phase 3b）
- **现状**：`simulation/` 已有刀路/碰撞/切削力仿真，但**无闭环**；`process_planning/sim_integration.py` 存在；OPC-UA 采集层在 `app/integrations/opcua/`。
- **差距**：① 无 MQTT/事件总线；② 无"感知→推理→执行→反馈"循环；③ 无评测基准（NLDF 风格打分）。
- **落地**：新建 `simulation/factory_sandbox/`：虚拟机床/缓冲区/AGV 简化模型 + MQTT(或进程内总线)话题 + 仿真工厂事件流；orchestrator 增加 `simulate` 步骤实现闭环；提供 NLDF 风格 KPI 打分（生产效率/质量/停机）。测试覆盖。
- **涉及文件**：simulation 新增子包；agent 编排扩展。

## 3. 执行顺序与验收标准

| Phase | 内容 | 验收标准 |
|---|---|---|
| 0 | 差距分析（本文档） | 完成 |
| 1a | ③ 拓扑校验+重生成 | 新测试全绿；坏模型可被拦截并重生成成功 |
| 1b | ⑤ SafetyValidator+多智能体 | 安全校验器单测通过；越界参数被拦截 |
| 2 | ② 设备→MCP 工具 | 仿真设备描述符→动态注册工具→调用成功 |
| 3a | ④ Mamba/SSM | 合成数据上可训练；工程侧推理注册可调 |
| 3b | ① 仿真工厂闭环 | 闭环跑通一轮"感知→决策→执行→反馈"；KPI 可输出 |

## 4. 风险
- mamba-ssm 依赖（causal-conv1d 编译）在国内环境可能失败 → 预留 S4 简化实现兜底。
- LLM→CadQuery 生成路径是 ③ 的长期目标，本阶段先验证"参数模板+校验+重生成"闭环，避免范围膨胀。
- 仿真闭环为简化模型，物理保真度有限，定位是"架构验证 + 演示 + 评测基准"而非真实加工。

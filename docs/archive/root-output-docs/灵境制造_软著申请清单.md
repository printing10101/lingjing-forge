## 八、更正后的结论（2026-10-16，用途＝确权 / 防抄袭）

**1. 放弃软著登记。** 除 §二 的 AI 声明硬闸外，登记对"防抄袭"这个目标本身效力有限：著作权自开发完成自动产生，登记只是权属的**初步证据**，不创设排他权；实际比对仍靠源码与创作过程材料。为一证不冒征信风险。

**2. 真正漏的是许可证，不是证书。**

| 事实 | 证据位置 |
|---|---|
| 根目录许可证为 Apache-2.0（任何人可免费复制、修改、商用，仅需保留声明；并含专利授权） | [`LICENSE`](../../../LICENSE) |
| README 明示"开源协议：Apache-2.0" | [`README.md` 第 7 行](../../../README.md) |
| 仓库为公开状态 | https://github.com/printing10101/lingjing-forge （`visibility: PUBLIC`，`createdAt 2026-09-27`） |
| 目前实际被取用程度 | 2026-10-16 `gh api` 实测：stars 0 / forks 0 / network 0 / watchers 0 |

也就是说，"防抄袭"当前是被**自己的许可证合法放开**的。趁 exposure 为 0 改掉，代价几乎为零；但已经拉到代码的人那份授权收不回，只能对新版本生效。
**3. 确权改走这三步（不需要任何 AI 声明）**

- **外部时间戳固定全量快照**：本地 git 不足以作证——历史只剩 2026-09-27 起的 55 commits（更早那段被环境守卫破坏），仓库 `createdAt` 同样是 09-27，无法证明更早的创作时点。做法：发布版本打包 → `sha256` → 上传 Zenodo 取 DOI（不可篡改 + 第三方时间戳，预印本已在用同一路子）；可选叠加可信时间戳（TSA）认证，司法与行政实践中对时间戳证据接受度有先例，按次收费，本轮未核价。
- **署名与权利声明落进代码**：自研模块头部保留本人/项目署名，`NOTICE` 或仓库首页写清著作权人与版本、日期。
- **留创作过程证据**：架构决策、模块划分、迭代记录（`docs/superpowers/specs/`、`docs/paper_and_competition/` 已具雏形）。侵权认定看"接触 + 实质相似"，这些比一张证书有用。

**4. 判据**：真出事时你需要的是"我在某时点已拥有这份完整代码"的第三方记载 + 可比对的源码。Zenodo DOI 与公开仓库已能给出前者，软著证书只补一个"初步权属"标签——用它换征信风险，是亏的。

**5. 本人决定（2026-10-16）**：不申请软著；维持 Apache-2.0 开源，不改许可证。
合规核查（同日实测，支撑该决定）：`git ls-files` 4114 个跟踪文件中第三方代码/二进制为 **0**（`.venv*`、`site-packages/`、`node_modules/`、`desktop_runtime/` 均未入库）；PyCAM 经 `pycam_executable` 以外部可执行程序调用（见 `engineering/python/app/api/v1/cam_validation/service.py:72`），未复制其 GPL 源码；cadquery/VTK/casadi 为 pip 依赖，不在仓库内。
→ 遗留义务：仅在**分发打包后的桌面安装包**（含 bundled runtime 与 wheel）时，才需处理 BSD-3 署名与 LGPL 可重链接/源码可获得性要求；纯源码仓库公开无此义务。
→ 若将来需要"独占"叙事（例如赛事或转让），届时再评估：改许可证只对未来接收者生效，已按 Apache 取得代码者授权不可撤销。

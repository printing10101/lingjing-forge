## 二、目标模型与验收标准

**目标**：任意干净机器（无预装依赖），一条命令或一个安装包，完成安装 → 启动 → 健康检查通过 → 界面可用；文档步骤与真实产物一一对应。

**验收标准**：
- A1 服务端：干净 Ubuntu 22.04（无 Python）执行 `curl -fsSL <url>/install.sh | bash` 成功，`lingjing doctor` 全绿，`http://localhost:8765/api/health/ping` 返回 `{"status":"ok"}`。
- A2 桌面端：干净 Windows 11（无 Python/Node/Rust）安装 msi/nsis → 启动 → 后端自动就绪（健康检查通过）→ 主界面可用。
- A3 一键脚本 URL 在国内网络可达（用户位于中国大陆）。
- A4 文档（安装指南/国内部署指南/README）每一条命令在干净环境实测通过，版本号统一 2.7.0。
- A5 CI 中任何破坏安装链路的改动 → 红灯（安装冒烟测试纳入 PR 门禁）。
- A6 提供 `lingjing doctor/update/uninstall` 生命周期命令。

## 五、风险与约束
- **桌面包体积**：PyTorch 为体积大头；production 已零 research 依赖，确认 onnxruntime-only 后可显著瘦身（阶段 2 专项）。
- **国内网络**：GitHub Release/raw 下载不稳 → 必须国内镜像（决策点 3）；Docker 镜像华为云 SWR 路径已有。**2026-08-03 17:20 实测 github.com:443 连接超时**——推送/拉取需在网络窗口操作或配置代理。
- **Windows 打包**：需 WebView2（tauri.conf 已配 embedBootstrapper ）；PyInstaller 在 CI 上需缓存依赖避免超时。
- **发布即承诺**：文档只写已实测的路径，未建成的设施标注「建设中」，避免再次出现「文档承诺、产物缺失」。

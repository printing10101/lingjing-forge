## 2. 拆分原则（与仓库既有约定对齐）

1. **行为不变**：不改变外部 API 路径 / 请求响应结构 / 数据库 schema / 事件名。拆分是纯搬移 + 导入重接。
2. **按职责划分**：每个新文件只做一件事（实体解析 / 任务执行 / 决策链 / 服务编排）。
3. **复用既有模式**：路由层用 `api/v1/_shared/task_infra.py` 助手；Pydantic 模型进 `schemas.py`；服务逻辑进 `app/services/`；协作对象独立模块（同 workflow/dreaming 既有做法）。
4. **公共导出兼容**：包 `__init__.py` 保留原有符号（`from app.workflow.runner import WorkflowRunner` 等继续可用），新文件内部导入。
5. **每个拆分独立成 commit**：Conventional Commits（`refactor(python): ...`），可单独回滚；一批一个 PR/提交组。
6. **测试不降级**：每个拆分后跑相关模块测试 + 全量关键子集，覆盖率不得低于拆分前。
7. **循环依赖防护**：新模块只依赖更底层模块；God 类拆出的协作模块不得反向 import 主类。

## 3. Python 拆分方案（P1-5）

### 波次 1：9 个头部文件（优先，模式清晰、收益最大）

#### S1. dxf/dxf_parser.py（926 行 → 目标 <200 行）

**现状**：DxfParser 865 行，含 20+ 个 `_extract_*` / `_*_to_obj` 实体解析方法（lines/circles/arcs/texts/mtext/dimensions/polylines/hatches/inserts/splines）。

**拆分**：
```
app/dxf/
  parser.py            # 主解析编排（parse + _extract_entities 分派 + 坐标转换 + 图层）
  entities/            # 新：按实体类型分文件
    __init__.py        # 注册表：ENTITY_EXTRACTORS = {…}，保留 _extract_* 名
    lines.py circles.py arcs.py texts.py dimensions.py polylines.py hatches.py inserts.py splines.py
  extents.py           # _compute_extents 独立
  color.py             # _safe_color 独立
```
**要点**：实体方法签名统一为 `(parser_ctx, entity) -> obj`；用模块级注册表 + parser 内 `getattr(registry, kind)` 分派，删除 parser 上的 20 个方法。

## 5. 通用拆分流程（每个模块统一执行）

1. **基线**：跑该模块全部测试，记录 pass 数与覆盖率（确保拆分后不降）。
2. **提取**：新建目标模块，搬移方法/函数/常量（纯搬移，不改逻辑）。
3. **重接**：原文件改为门面，import 新模块并委托；包 `__init__.py` 公共符号不变。
4. **编译**：`python -m py_compile` + ruff + mypy（若启用）。
5. **测试**：跑模块测试 + 依赖该模块的上游测试（如 routes → service）。
6. **门禁**：全量 unit 子集 + 相关 vitest + eslint；覆盖率对比。
7. **提交**：`refactor(python|frontend): 拆分 xxx`，独立提交可回滚。

## 6. 验收标准

- [ ] 每个拆分模块：原文件行数降至目标值（见各节），新文件职责单一
- [ ] 所有公共导入路径兼容（无破坏性改动）
- [ ] pytest：相关模块测试全绿，全量 unit 失败数不增加
- [ ] vitest：相关组件测试全绿，全量失败数不增加（排除既有 flaky）
- [ ] ruff / eslint / cargo check（如涉 Rust）零新增问题
- [ ] 覆盖率不低于拆分前

## 8. 风险与约束

- **行为风险**：纯搬移理论上零风险，但 import 重接错位会导致 ImportError/循环依赖——每个模块拆分后立即跑导入冒烟（`python -c "import ..."`）。
- **循环依赖**：协作模块不得反向 import 门面；必要时用「参数传递替代 self 访问」。
- **公共 API**：`__init__.py` 导出与 FastAPI 路由路径保持不变（路由文件本身不动路径）。
- **数据层**：不触碰 DB schema / 迁移 / Redis key；仅移动代码。
- **既有 flaky**：全量 vitest 的 http utility 超时（ErrorConflictDialog.test.ts）为既有顺序相关 flaky，验收时单独重跑确认。
- **不做的事**：本方案不引入新依赖、不改变 UI 行为、不重写业务逻辑（仅搬移与轻量解耦）。

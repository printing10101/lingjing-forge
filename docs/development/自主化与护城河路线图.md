# 灵境制造 · 自主化与护城河路线图（AI 执行手册）

> **本文档是给 AI agent（DeepSeek Harness）的执行手册，不是战略 PPT。**
> 每个任务都有：入口路径 / 具体动作 / **生产级验收标准（硬门禁）** / 记忆指针。
> **验收标准 = 顶尖生产级**：任何任务未达 §4 门禁即视为未完成，禁止标记 。
> AI 每次会话开始时，先读 `.dsh-memory/MEMORY.md` 中的「路线图进度」段落，接着未完成的任务干。

---

## 0. 总体目标与原则

| 项 | 内容 |
|----|------|
| **最终目标** | 自主代码占比 20% → 50% + 建立「工艺数据飞轮 + 插件生态」护城河 |
| **总工期** | 10 个月（4 个阶段） |
| **核心原则** | 只重写「业务逻辑白盒层」，保留 CadQuery/OpenCASCADE/PyTorch 等框架调用 |
| **护城河定位** | 「基于实测加工数据驱动的智能制造工艺平台」——数据 + 算法 + 生态，**不是代码全自研** |
| **质量红线** | **生产级标准**：每个交付物必须达到可直接投产的质量（§4 门禁全过） |
| **专利** | 暂不申报（用户决定），但每个自主化任务必须沉淀技术文档，方便未来申报 |
| **禁止事项** | 不重写数据库引擎 / 不替换几何内核 / 不替换 PyTorch |

## 1. AI 工作流约定（每次会话必须遵守）

```
启动会话：
  1. 读 .dsh-memory/MEMORY.md → 找「路线图进度」段 → 找 NEXT_TASK
  2. 读本文档对应任务段落（含 §4 门禁）
  3. 用 todo_write 建立本次会话任务清单（含验收项）
  4. 执行代码任务（保留框架调用）
  5. 逐项过 §4 生产级门禁（测试/覆盖率/性能/安全/文档）
  6. 全部门禁通过 → 更新进度表（）+ 更新验收记录
     任一门禁未过 → 状态保持 ，记录缺口，不提交完成
  7. memory_log 记录完成内容 + 门禁证据 + 更新 NEXT_TASK
  8. 按提交规范 commit（type: refactor/feat/fix，scope 见任务）
```

**提交规范**：`refactor(python): <模块> <动作>` 或 `feat(data): ...`，header ≤100 字符，commitlint 门禁。

**测试环境**（记忆已确认）：
- 系统 Python 3.11：`py -3.11`
- 必须 `PYTHONUTF8=1` + `-o addopts=''`（pytest-cov 未装）
- torch/scipy 环境残缺：与 torch 相关的测试失败为既有问题，非改动引入（用 git stash 验证基线）

## 3. 生产级验收门禁体系（所有任务必须全过）

> 这是全局硬性标准，任务清单里的「验收」是此体系的落地。**任何一项不达标 = 任务未完成。**

### 3.1 代码质量门禁

| # | 门禁 | 标准 | 验证命令 |
|---|------|------|----------|
| Q1 | 静态检查 | `ruff check app/` 全规则（CI 等价）**0 违规** | `ruff check app/` |
| Q2 | 类型安全 | mypy 严格模式 **0 错误**（既有 torch 噪声除外，须列清单说明） | `mypy --config-file mypy.ini <改动文件>` |
| Q3 | 复杂度 | 新增函数圈复杂度 ≤ 10（mccabe）；超标必须拆分 | `ruff check --select C901` |
| Q4 | 代码规模 | 新文件 ≤ 500 行；函数 ≤ 60 行；无超过 3 层的嵌套 | 人工/脚本 |
| Q5 | 无危险模式 | 无 `shell=True` / 无 SQL 字符串拼接 / 无 `eval`/`exec`（受控沙箱除外） | 安全扫描脚本 |

### 3.2 测试门禁（生产级覆盖率）

| # | 门禁 | 标准 | 验证方式 |
|---|------|------|----------|
| T1 | 行覆盖率 | 新增/修改代码 **≥ 90%** | pytest-cov |
| T2 | 分支覆盖率 | **≥ 80%**（条件分支全覆盖） | pytest-cov --branch |
| T3 | 边界用例 | 每个公共函数覆盖：空输入 / 极值 / None / 负数 / 重复值 / 类型错误 | 测试清单核对 |
| T4 | 错误路径 | 每个 except 分支 ≥1 个触发用例；异常类型 + 错误码断言 | 测试清单核对 |
| T5 | 回归基线 | 相关既有测试**全绿**；黄金/契约测试逐字符/逐字段比对零差异 | pytest |
| T6 | 幂等性 | 相同输入重复执行 → 相同输出（状态机/IO 任务必须） | 重复执行断言 |

### 3.3 性能门禁（可量化基准）

| # | 门禁 | 标准 | 验证方式 |
|---|------|------|----------|
| P1 | 基准回归 | 核心路径有性能基准（pytest-benchmark），改动后 **≥ 改动前 95%** | pytest-benchmark |
| P2 | 复杂度上界 | 10 倍输入规模 → 耗时增长 < 10 倍（无 O(n²)+ 无 N+1 查询） | 规模测试 |
| P3 | 内存上界 | 100MB 级输入峰值内存有明确上限（记录在文档） | tracemalloc/监控 |
| P4 | 无泄漏 | 连续 1000 次调用无内存增长、无句柄泄漏 | 循环测试 |

### 3.4 安全门禁

| # | 门禁 | 标准 |
|---|------|------|
| S1 | 输入校验 | 所有外部输入经 Pydantic/模式校验；非法输入返回 4xx + 错误码 |

## 8. 验收执行细则（AI 必读）

1. **门禁是硬性的，不是建议**：§3 每一项都是「必须」，没有「尽量」。
2. **覆盖率报告必须真实**：用 pytest-cov 实测，不估算；缺口说明具体到函数。
3. **性能基准先建后改**：改动前先记录基线（pytest-benchmark 存档），改动后对比。
4. **契约/黄金测试优先**：凡有既有行为（黄金 NC / OpenAPI schema / 状态流转），一律用逐字段比对防回归。
5. **失败也要留痕**：门禁未过的会话，memory_log 记录：哪个门禁没过、差多少、下一步计划。这不是失败，是正常迭代。

## 2. 缺陷 1（致命）：刀路深度与零件厚度不匹配

以 `case2_box_4holes.dxf` 为例：

| 量 | 值 | 来源 |
|---|---|---|
| DXF 特征模型 | 100 × 100 × **10 mm**，4 孔 | pipeline `model` 字段 |
| 实际切削段 | 62 行 | G 代码 `G01` 行 |
| 切削 Z 值 | **45 / 46 / 48**（全部为正，共 3 层） | 实测 |
| 毛坯顶面（校验器视角） | Z = 10 | `stock_top_z` |
| 刀具相对毛坯位置 | **悬空 35–38 mm** | 45 − 10 |

根因：G 代码生成器把 `safe_z`（默认 50.0）当作毛坯顶面来分层下刀（50−2=48、−2=46、−1=45），**完全不读 DXF 模型的实际高度（10 mm）**。结果：

- 只切 3 mm 深，而零件厚 10 mm → **零件根本铣不出来**；
- 切削全程发生在毛坯上方 → **去除材料为 0**；
- 若把这份代码直接下发，刀具会在空中走完整个程序，然后「加工完成」。

其他样本同构：`case10_i_shape`（100×50×10）切削 Z=45–48；`case6_flange`（200×200×10）同。

## 3. 缺陷 2（致命）：体素校验闸「假绿」

同一份空切程序送入 `VoxelValidator.validate()`：

```json
{"passed": true, "severity": "none", "total_segments": 177,
 "cutting_segments": 57, "collision_count": 0,
 "removed_voxel_count": 0, "voxel_count": 108160}
```

三个样本全部如此（`removed_voxel_count` 均为 0）。

问题定义：`passed = not collision_positions`（`voxel_validator.py:380`），即**只判「有没有撞」，不判「有没有切到」**。于是：

- 刀路悬在毛坯上方 → 无碰撞 → `passed=true`；
- 去除量 0 → 与「加工完成」在报告上无法区分；
- 越界运动点在快移检查中被边界放行（`voxel_validator.py:345` 注释自述该行为）。

这直接冲击项目的核心叙事「AI 产出必经物理校验才可上机」：**当前这道闸对「空切」这一类失效是完全透明的**。

建议补的判据（不依赖新模型，纯几何）：
1. `removed_voxel_count / voxel_count` 低于按零件体积估算的下界 → 判 fail；
2. 切削段的最低 Z 与 `stock_top_z − 零件高度` 不一致 → 判 fail；
3. 报告里显式输出「去除体积 vs 期望体积」，让工程师能一眼看出空切。

## 4. 缺陷 3：两个校验器的毛坯定位口径不一致

| 校验器 | 毛坯 XY 定位 | 实测结果 |
|---|---|---|
| `InternalValidator` | 以世界原点为中心（`[-52, 52]`） | 全部 X=95 刀路报「超出毛坯边界」 |
| `VoxelValidator` | **包络居中**（已修，见 `:273` 注释） | XY 判定正常 |

两者对同一份代码给出互相矛盾的空间语义。`InternalValidator` 的越界只作为 `warnings` 输出、不影响 `collisions=[]`，所以**告警被淹没而闸门仍然放行**。

另：`case6_flange` 的程序 XY 包络 265.0×255.6 mm > 请求毛坯 204×204 mm，校验器自动扩料后继续（仅 warning）。程序包络比零件大 30% 意味着大量空行程，值得单独立项核。

## 5. 缺陷 4：AI 模型全部走解析回退（工艺参数环节 0% 神经模型）

每次运行均出现：

```
未找到模型检查点: app/simulation/chatter/checkpoints/chatter_model.pt，使用解析法回退
未找到模型检查点: app/simulation/cutting_force/checkpoints/best_model.pt
```

含义：
- ADR-010 的「双路径颤振预测」，神经网络路径**从未通电**（权重不存在）；

- 即当前「AI 驱动 CAM」的实际成分为 **0%**，全部由解析公式承担。

与 `data/models/world_model/` 下 16 个已训练 checkpoint 形成对比——**世界模型线的权重是齐的，工艺参数线的权重是空的**，两条线的成熟度被长期混为一谈。

### 8.3 修复后的告警复盘（含一处定性更正）

**A. 层间抬刀的 `rapid_z_low` —— 定性更正：这不是 G 代码缺陷**

`InternalValidator` 报 `G00 start Z=12.0 is below safe height 50.0`（severity=medium，每文件多处）。追根因：`app/toolpath/planar_engine.py:334` 的 `clearance: float = 2.0`，层间抬刀固定为 `z_top + clearance`（10+2=12）。

该行为**符合工业实践**：层间/Z 向抬刀用 clearance plane（工件顶 + 2~10mm），只有跨区域 XY 快移、换刀、回原点才回安全平面。`InternalValidator` 要求「所有 G00 都高于 safe_z」的口径过严——它没有夹具/工件实体模型，只能用平面高度做保守判断。

结论：**降级为「校验器口径待商榷」，不作为 P1 修复项**。若日后要放宽，正确做法是区分 `rapid_z`（层间）与 `rapid_xy`（跨区域）分别判据，而不是把抬刀全部拉到 safe_z（会显著增加空行程）。

**B. 钻孔深度超限 —— 已修**（见 §8.2b）。

**C. 体素闸对钻孔固定循环是盲的 —— 结构性缺口，立项**

`app/simulation/toolpath_parser.py:364-368` 的注释明确：对 `G73 / G81–G89` 固定循环，解析器**只把 Z 坐标更新为 R 退回平面**，不展开循环内部的钻深轨迹。

后果：钻孔的实际钻深从不出现在刀路段里，于是
- 上一节 −15mm 的钻穿过切，`VoxelValidator` 报 `collision_count=0`（完全没看到）；
- 任何钻孔撞刀、钻穿垫板，体素闸都不会报。

这**推翻了「体素仿真强制校验」对含孔零件成立的前提**——只要程序里有固定循环，校验覆盖度就退了。修复需展开循环为 linear 段（R 平面 → 钻深 → R 平面 → 下一个孔），影响 `simulation` / `collision_detector` / `cam_validation` 三处消费者，必须单独立项 + 回归，不宜顺手改。

### 8.4 结论

已闭合三项：**刀路深度由零件几何驱动**（P0）、**空切不再能拿到通过判定**（P0）、**孔深受零件厚度约束**（B）。

剩余最大缺口是 **C：钻孔固定循环不进入体素闸**。因此对外表述必须区分两种零件：

- **纯铣削件**：现有链路 = 产出 + 深度正确 + 体素校验真实（去除量 40–66%）→ 可称「已过内部校验」，仍保留 `cam_validation_required`；
- **含孔件**：钻孔段对体素闸不可见 → **不得**声称「体素仿真已覆盖」，只能说「铣削部分已校验，钻孔部分待外部 CAM 复核」。

这条区分必须写进对外材料，否则一旦客户拿含孔件验证就会露。

**A（`rapid_z_low`）** 属校验器口径过严，不修，理由见 §8.3。

### 9.3 修完才暴露的第二层问题：通孔超程被误判为过切

展开后首次运行，case2 直接报 **24 处 critical 过切**，坐标正是四个孔的 `Z=−0.5…−3.0`。

定性：**这是误报**。通孔必须钻穿到毛坯底面以下，`Z<0` 是设计意图而非过切。校验器原来的判据是「任何低于毛坯底面的切削点都算过切」，因为它不知道有垫板。

处理：新增 `breakthrough_tolerance_mm`，容差内的 `Z<0` 计入 `breakthrough_count`（写 warning 提示核对垫板厚度），不判碰撞、也不参与去材料。
**默认值为 0.0，即有既有行为完全不变**（这也是 611 个仿真测试全绿的原因）；生产链路按垫板厚度设 2–3mm。

### 9.5 覆盖度现状（对外口径更新）

C 修复后，**含孔件的铣削段与钻孔段均进入体素校验**，§8.4 的「含孔件不得声称已覆盖」限制**已解除**，但仍有两个前置条件必须同时成立：

1. `voxel_breakthrough_tolerance_mm > 0` 且与实际垫板厚度匹配（默认 0 会把正常超程判成过切）；
2. 程序中的循环属于 **G73/G81/G82/G83（钻孔）或 G74/G84（攻丝）或 G85/G86/G88/G89（镗孔）**；仅当含 **G76 精镗（让刀偏置）或 G87 反镗（方向相反）** 或增量模式（G91）时，`ExpandStats.complete=False` 会让 `warnings` 明确写出「该段不在校验覆盖内」。

> **2026-10-23 覆盖度扩充**：原条件 2 只列 G73/G81–G83，攻击丝与镗孔一律计入缺口。实测发现后处理器的 `tap`（G84）与 `boring`（G86/G89）生成器**会产出这些循环码**，即自产程序同样对体素闸不可见——这是闭环漏洞而非外部输入问题。现已展开 G74/G84（几何等价 G81；攻丝的 F 是螺距 mm/rev，展开后按数值写成进给率并给出告警：轨迹正确、进给速度不等价）与 G85/G86/G88/G89（退刀方式与主轴动作对材料去除无影响）。**仍不支持 G76/G87**：前者带主轴定向与让刀偏置，直上直下会低估孔壁去除；后者进给方向为 Z→R，几何不可复用。测试 19 → 31 项。

两条都满足时，才能说「钻孔段已过体素校验」。

## 10. 阶段 1→2（mesh → 参数化特征）根因修复（2026-10-21 23:00）

### 10.1 实测现象：静默返回 0 特征

用 `data/outputs/e2e_v2/` 里 DXF→STL 产出的真实网格跑 `FeatureExtractionPipeline`
（`create_task` → `run_task` → `get_result`），四个样本**全部**：

| case | mesh | DXF 真值 | 提取结果 | status |
|---|---|---|---|---|
| case2_box_4holes | 260 v / 520 f | 100×100×10，4 孔 | **0 平面 / 0 圆柱 / 0 孔** | `features_extracted` |
| case10_i_shape | 24 v / 44 f | 100×50×10，0 孔 | 0 / 0 / 0 | `features_extracted` |
| case6_flange | 264 v / 528 f | 200×200×10，7 孔 | 0 / 0 / 0 | `features_extracted` |
| case14_round_disk | 264 v / 528 f | 120×120×10，1 孔 | 0 / 0 / 0 | `features_extracted` |

注意 `status=features_extracted`、`error_message=""`——**不报错、不告警**，调用方无从察觉。
这就是 `parametric_geometry/pipeline.py` 里那句「mesh → 参数化 CAD 自动转换未解决」的实际形态。

### 10.2 根因：绝对内点阈值 > 网格总顶点数

| 配置 | 默认值 | 实际网格顶点 | 后果 |
|---|---|---|---|
| `plane_min_inliers` | **1000** | 24–264 | `remaining_count < 1000` 恒真 → **循环第一步即 break** |
| `cylinder_min_inliers` | **500** | 24–264 | 同上 |

### 10.3 修复：按网格规模自适应

`FeatureExtractionConfig` 新增：

```python
min_inliers_ratio: float = 0.02   # LNN_FE_MIN_INLIERS_RATIO
min_inliers_floor: int = 10       # LNN_FE_MIN_INLIERS_FLOOR

def effective_min_inliers(kind, vertex_count) -> int:
    return max(floor, min(absolute, ratio × vertex_count))
```

- 稠密网格（10 万顶点）：`min(1000, 2000) = 1000` → **行为不变**；
- 轻量网格（260 顶点）：`max(10, 5) = 10` → 可以提取；
- `ratio <= 0` 完全退回旧口径。

接入三处：`plane_extractor`（2 处比较）、`cylinder_extractor`（2 处）、`hole_detector`（4 处，其中孔检测按**平面内点数**而非全局数计）。
配置可能是测试替身（`MagicMock`），故每处均以 `try/except (AttributeError, TypeError, ValueError)` 回退绝对阈值。

## 11. 孔轴向约束：容差取值依据与实测（2026-10-21 23:05）

### 11.1 行业口径查证

| 来源 | 口径 |
|---|---|
| PowerMILL（机明软件手册） | 孔特征识别分「自动识别正孔」与「**向导创建斜孔特征**（需交互确认）」两条独立路径——商业 CAM 默认不把斜轴当作正孔；「孔公差（几何闭合容差）」默认 0.001；「不完整孔」最小圆弧角默认 300° |
| RapidMade《Robust Hole Detection in STL Meshes》 | 特征角（边界三角形法向 vs 相邻表面法向）理想为 90°，**考虑网格噪声接受 30°–120°**；圆柱轴用面法向 SVD 拟合，要求 >90% 三角形通过轴向/半径检验 |
| 航空制孔垂直度实测（计量学报 / 浙大） | 实际加工垂直度控制在 **0.05°/100mm ~ 0.2°** 量级 |
| 3DViewStation | 12 种孔类型，识别基于 tessellation，不依赖原生 CAD 内核 |

### 11.2 决策：5°

理由：
1. 比实际加工垂直度（0.05°–0.2°）高 1–2 个数量级，网格噪声余量充足；
2. 实测误检轴线与 Z 轴夹角为 **37°–72°**，5° 能干净剔除；
3. 与 PowerMILL「默认正孔、斜孔交互」的行业习惯一致；
4. 可配置（`LNN_FE_HOLE_AXIS_TOLERANCE_DEG`），设 0 关闭以兼容侧孔/斜孔场景。

### 11.3 实现与效果

`FeatureExtractionConfig.hole_axis_tolerance_deg`（默认 5.0）+ `cylinder_extractor` 在半径校验后增加轴向校验：轴线与 Z 轴夹角超限即判为 RANSAC 过拟合，移除该批内点继续。

| case | 修复前圆柱 | 修复后圆柱 |
|---|---|---|
| case2（4 孔） | 8（全部斜轴误检） | **0** |
| case6（7 孔） | 1 | **0** |
| case14（1 孔） | 2 | **0** |
| case10（0 孔） | 0 | 0 |

**假圆柱数据已清零**——下游 `feature_to_brep` 不会再被污染。

### 11.4 意外发现：孔检测走独立的 2D 圆环路径，精度极高

清除圆柱后 case2 仍有 `holes=2`，说明孔来自 `hole_detector` 的**平面内 2D 圆环检测**（路径 A），不依赖 3D 圆柱拟合。实测参数：

```json

```

对照 DXF 真值（孔位 25/75 × 25/75，直径 10mm）：

| 项 | 提取值 | 真值 | 误差 |
|---|---|---|---|
| 中心 X | 25.000000057 | 25.0 | 5.7e-8 mm |
| 中心 Y | 25.000000039 | 25.0 | 3.9e-8 mm |
| 半径 | 5.000000102 | 5.0 | 1.0e-7 mm |

**精度达到 1e-7 mm 量级**——远优于 3D 圆柱拟合路径。这条路径才是 mesh→孔 的正确方向。

### 11.5 剩余缺陷（3 项，明确可修）

1. **通孔重复计数**：同一个孔在上表面（Z=10）与下表面（Z=0）各报一次 → 1 个通孔被算成 2 个 feature。
2. **`depth_mm = 0.0`**：通孔深度应为 `Z_top − Z_bottom = 10mm`，当前未计算。
3. **召回不足**：4 个孔只检出 1 个位置（25/25），另 3 个（75/25、25/75、75/75）漏检。

第 1、2 项是同一个修法：按「同 XY + 同轴向」把上下两个圆环合并为一个通孔，`depth = Z_上 − Z_下`。第 3 项需查路径 A 的迭代退出条件（首个孔消费内点后剩余不足）。

## 14. P1 已实施：几何自检闸（2026-10-22 00:10）

### 14.1 设计

在 `DxfToModelConverter.convert()` 末尾加入**体积自洽校验**，不依赖 trimesh、不依赖 STL 导出：

```
base_volume  = 切孔前实体体积
final_volume = 切孔后实体体积
removed      = base_volume − final_volume
expected     = Σ(π·r²·height)   # DXF 孔默认贯通
判定：|removed − expected| / expected > 10%  →  geometry_selfcheck_passed = False
```

`ModelConversionResult` 新增字段（**不改 `success` 语义**，避免破坏既有调用方）：

| 字段 | 含义 |
|---|---|
| `base_volume_mm3` / `final_volume_mm3` / `removed_volume_mm3` / `expected_hole_volume_mm3` | 自检原始数据，供前端与工审展示 |
| `geometry_selfcheck_passed` | 闸门结论（默认 True） |
| `geometry_selfcheck_notes` | 失败原因与偏差说明 |

无孔件另有反向判据：`removed > base 的 2%` 即判失败（拦住"没有孔却掉了一大块材料"）。

# ADR-012: 资源卡片（模型/数据集卡片）

**日期**: 2026-07-14
**状态**: 已接受
**决策者**: 灵境制造团队
**关联**: ADR-005（核心架构契约）、ADR-011（项目级 Git 同步）

---

## 背景

阶段 6 p6-2（项目级 Git 同步）已完成，用户可在项目级别同步数据集/模型/配置/工作流。
阶段 6 目标"生态内容飞轮"的下一环是 p6-3：为数据集与模型提供 **卡片式展示**，
包含 README + 指标 + lineage 三大要素，让用户在浏览/选用资源时能快速理解资源全貌。

### 当前现状

1. **Dataset ORM 已有**：`datasets` 表（name / description / schema_json / owner_id / status），
   但 `description` 是短文本（≤2048 字符），无法承载 README 富文本（含 markdown 格式、
   使用示例、引用链接、版本变更说明等）。
2. **DatasetVersion ORM 已有**：`dataset_versions` 表（version / content_hash / row_count /
   size_bytes / storage_uri / lineage_record_id），具备基础指标，但缺少版本级 README。
3. **LineageRecord ORM 已有**：`lineage_records` 表（target / source_type / source_ref /
   inputs / outputs / operation），`ILineageStore.visualize()` 已返回节点/边数据，
   但缺少面向卡片的"上下游摘要"视图（仅返回近 N 层节点数 + 关键路径，避免全图渲染压力）。
4. **Model 产物无独立 ORM 表**：
   - `LNNModelRegistry`（`app/ai/lnn/inference/registry.py`）是内存单例 + 文件路径
     （`models/*.pt`），无版本表，重启即丢失元数据。
   - `ExperimentSnapshot` 间接记录 `model_uri` + `metrics_json`，但 snapshot 是"实验快照"
     而非"模型产物注册表"，无法表达"同一模型的多个版本演进"。
   - ADR-011 第 91 行明确预留："model_artifacts 和 config_specs 持久化作为后续 ADR
     （如 ADR-012/013）" —— 本 ADR 即履行该承诺。
5. **缺少卡片聚合视图**：前端要展示一张卡片，需分别调用 `GET /datasets/{id}` +
   `GET /datasets/{id}/lineage/{uri}` + `GET /snapshots?model_uri=...` 三个端点，
   而后在前端拼接 —— 网络开销大，且后端无法做权限聚合校验。

### p6-3 目标

- **数据集卡片**：聚合 Dataset 元数据 + DatasetVersion 指标 + LineageRecord 上下游摘要 +
  可编辑的 markdown README
- **模型卡片**：新建 `model_artifacts` 表持久化模型产物元数据（model_uri / model_type /
  version / framework / metrics / readme / tags / status），聚合 lineage 摘要
- **可编辑 README**：用户可在卡片上编辑 markdown README，持久化到 DB
- **lineage 摘要视图**：返回近 N 层节点数 + 关键路径，避免全图渲染压力
- **指标历史**：模型卡片支持追加指标记录（如训练过程 metrics 曲线）

## 决策

采用"**新增 2 张 ORM 表 + 复用现有 Dataset/LineageRecord/Snapshot + 新增卡片聚合服务**"
方案，**不修改现有 Dataset/DatasetVersion/LineageRecord ORM 表结构**（避免破坏 ADR-005
契约稳定性），新增的 README 与模型元数据通过新表承载：

### 1. 新增契约 `app/contracts/resource_card.py`

定义以下 dataclass 与枚举：

- `ModelArtifactType`（枚举）：`lnn` / `pytorch` / `onnx` / `sklearn` / `other`
- `ModelArtifactStatus`（枚举）：`draft` / `published` / `deprecated` / `archived`
- `ModelArtifact`（dataclass）：`model_id` / `model_uri` / `name` / `model_type` / `version` /
  `framework` / `storage_uri` / `metrics` / `readme_md` / `tags` / `owner_id` / `status` /
  `created_at` / `updated_at`
- `DatasetReadme`（dataclass）：`dataset_id` / `version`（Optional，None 表示数据集级 README）/
  `readme_md` / `updated_by` / `updated_at`
- `LineageSummary`（dataclass）：`target_uri` / `upstream_count` / `downstream_count` /
  `upstream_layers`（list[list[str]]，按层分组）/ `downstream_layers` /
  `key_path`（list[str]，target 到根的关键路径）/ `total_nodes`
- `DatasetCard`（dataclass）：聚合 `dataset` 元数据 + `latest_version` 指标 +
  `version_count` + `readme` + `lineage_summary`
- `ModelCard`（dataclass）：聚合 `model_artifact` + `snapshot_count` +
  `lineage_summary` + `metrics_history`（list[dict]）

### 2. 新增数据库表 `app/database/models/resource_card.py`

**表 1: `model_artifacts`** —— 模型产物持久化

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | String(64) PK | 模型 ID（`mdl_` 前缀 + uuid） |
| `model_uri` | String(512) UNIQUE | 模型 URI（`model://<name>/<version>`） |
| `name` | String(128) INDEX | 模型显示名 |
| `model_type` | String(32) | lnn/pytorch/onnx/sklearn/other |
| `version` | String(32) | semver |
| `framework` | String(64) | 框架版本（如 `torch-2.1.0`） |
| `storage_uri` | String(512) | 模型文件存储位置 |
| `metrics_json` | Text | 指标 JSON（如 `{"accuracy": 0.95, "loss": 0.05}`） |
| `metrics_history_json` | Text | 指标历史 JSON（追加式记录） |
| `readme_md` | Text | markdown README |
| `tags_json` | Text | 标签 JSON 数组 |
| `owner_id` | String(128) INDEX | 所有者 |
| `status` | String(32) INDEX | draft/published/deprecated/archived |
| `created_at` | DateTime | 创建时间 |
| `updated_at` | DateTime | 更新时间 |

索引：`ix_model_artifacts_owner_status`、`ix_model_artifacts_type_status`、
`uq_model_artifacts_uri`（model_uri 唯一）

**表 2: `dataset_readmes`** —— 数据集 README 持久化

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | String(64) PK | README ID |
| `dataset_id` | String(64) FK→datasets.id | 数据集 ID |
| `version` | String(32) NULLABLE | 版本号（NULL 表示数据集级 README） |
| `readme_md` | Text | markdown README |
| `updated_by` | String(128) | 最后更新者 |
| `updated_at` | DateTime | 更新时间 |

约束：`uq_dataset_readmes_ds_version`（dataset_id + version 唯一，version 为 NULL 时
通过 SQLite 的 NULL 处理保证数据集级 README 唯一）

### 3. 新增服务层 `app/services/resource_card_service.py`

`ResourceCardService` 单例，职责：

- **Model CRUD**：`register_model` / `get_model` / `list_models` / `update_model` /
  `delete_model` / `append_model_metrics`
- **Dataset README CRUD**：`get_dataset_readme` / `upsert_dataset_readme` /
  `delete_dataset_readme`
- **卡片聚合**：`get_dataset_card` / `get_model_card` —— 内部调用 `IDatasetStore` /
  `ILineageStore` / `ISnapshotStore` 聚合数据
- **lineage 摘要**：`get_lineage_summary` —— 调用 `ILineageStore.get_upstream` /
  `get_downstream`，按层分组并裁剪到 `max_depth`（默认 3），提取关键路径

线程安全：`_locks: dict[str, threading.Lock]` 按 resource_key 串行化写操作。

### 4. 新增路由 `app/api/v1/resource_cards.py`

prefix `/api/v1/resource-cards`，12 个端点：

| # | 方法 | 路径 | 权限 | 说明 |
|---|------|------|------|------|
| 1 | GET | `/datasets/{dataset_id}` | `resource_card:read` | 数据集卡片（聚合） |
| 2 | PUT | `/datasets/{dataset_id}/readme` | `resource_card:write` | 更新数据集 README |
| 3 | GET | `/datasets/{dataset_id}/lineage` | `resource_card:read` | 数据集 lineage 摘要 |
| 4 | GET | `/datasets/{dataset_id}/metrics` | `resource_card:read` | 数据集指标（版本数/总行数/总大小） |
| 5 | GET | `/models` | `resource_card:read` | 模型卡片列表（分页+过滤） |
| 6 | POST | `/models` | `resource_card:write` | 注册新模型产物 |
| 7 | GET | `/models/{model_id}` | `resource_card:read` | 模型卡片详情（聚合） |
| 8 | PUT | `/models/{model_id}` | `resource_card:write` | 更新模型卡片（readme/tags/status） |
| 9 | DELETE | `/models/{model_id}` | `resource_card:write` | 删除模型卡片 |
| 10 | GET | `/models/{model_id}/lineage` | `resource_card:read` | 模型 lineage 摘要 |
| 11 | GET | `/models/{model_id}/metrics` | `resource_card:read` | 模型指标历史 |
| 12 | POST | `/models/{model_id}/metrics` | `resource_card:write` | 追加模型指标记录 |

### 5. 新增权限码（追加到 `training_task.py` 的 `PRESET_PERMISSIONS`）

- `resource_card:read` —— 查询卡片 / README / lineage 摘要 / 指标
- `resource_card:write` —— 更新 README / 注册/更新/删除模型 / 追加指标

admin 角色自动获得这两个权限；engineer 角色获得 read + write；operator 角色仅 read。

### 6. 新增 Alembic 迁移 `alembic/versions/<hex>_add_resource_cards.py`

创建 `model_artifacts` + `dataset_readmes` 两张表 + 索引 + 外键。

### 7. 前端契约 `src/contracts/resource_card.ts`

TypeScript 类型与后端 dataclass 对齐，包含：

- 常量对象：`MODEL_ARTIFACT_TYPES` / `MODEL_ARTIFACT_STATUSES` / `DATASET_README_SCOPES`
- 类型守卫：`isModelArtifactType` / `isModelArtifactStatus`
- 中文标签映射：`MODEL_ARTIFACT_TYPE_LABELS` / `MODEL_ARTIFACT_STATUS_LABELS`

## 理由

### 考虑的方案

1. **方案 A: 扩展现有 Dataset 表，新增 `readme_md` 字段；新建 `model_artifacts` 表**
   - 优点：减少表数量
   - 缺点：违反 ADR-005 契约稳定性承诺（Dataset 是 Stable v1.0.0，breaking change 需新开 ADR）；
     README 与 Dataset 元数据耦合，版本级 README 无法表达；现有 `datasets.py` API 与
     `IDatasetStore` 契约需同步修改，影响面大

2. **方案 B: 新建 `dataset_readmes` 表 + `model_artifacts` 表，不修改现有 Dataset 表**（**已选**）
   - 优点：保持 ADR-005 契约稳定性；README 独立演进，支持版本级 README；模型产物有
     独立持久化表，与 ADR-011 预留承诺对齐；卡片聚合服务统一权限校验与数据拼接
   - 缺点：新增 2 张表 + 1 个契约 + 1 个服务 + 1 个路由 + 前端契约/store（代码量较大）

3. **方案 C: 完全复用现有表，仅在 service 层聚合，不新增 ORM 表**
   - 优点：零 ORM 改动
   - 缺点：README 无处持久化（只能存到 `description` 短文本字段）；模型产物无版本表，
     重启即丢失元数据；无法满足"卡片可编辑 README"与"模型指标历史"需求

**选择方案 B** 的关键理由：
- ADR-005 契约稳定性是项目根基，不应为 p6-3 破坏
- ADR-011 已预留 model_artifacts 作为后续 ADR，本 ADR 履行该承诺
- README 与模型元数据是新需求，新表承载天然合理
- 卡片聚合服务统一了权限校验与数据拼接，减少前端多次请求

### lineage 摘要设计

`LineageSummary` 不直接复用 `ILineageStore.visualize()` 的全图返回，而是：
- 调用 `get_upstream(depth=3)` 与 `get_downstream(depth=3)`
- 按"层"分组（BFS），每层最多保留 10 个节点（避免大图渲染压力）
- 提取"关键路径"：target → 根节点的最短路径（用于卡片侧栏展示）
- 返回 `upstream_count` / `downstream_count`（全量计数，不限 depth）+ `total_nodes`

这样卡片展示时既能看到"全局规模"，又能快速浏览"近邻节点"，需要全图时再调用
`GET /datasets/{id}/lineage/{uri}` 获取完整可视化数据。

## 后果

### 积极影响

- 数据集与模型有了统一的卡片展示入口，用户可快速浏览资源全貌
- 模型产物持久化到 DB，重启不丢失元数据，支持版本演进追踪
- README 富文本让用户能编写详细的使用说明、示例、引用链接
- lineage 摘要视图避免前端渲染全图压力，提升卡片加载速度
- 与 ADR-011 项目级 Git 同步对齐：模型产物可通过 `model://<name>/<version>` URI
  被项目引用并同步

### 消极影响

- 新增 2 张表 + 1 个服务 + 1 个路由，代码量增加
- 模型注册需用户主动调用 `POST /models` 或通过训练流程自动注册（本 ADR 不强制
  自动注册，避免破坏现有训练流程）
- README 编辑需前端提供 markdown 编辑器组件（本 ADR 仅提供 API，前端组件由
  后续 UI 实现）

### 后续工作

- 前端 UI 组件：`DatasetCard.vue` / `ModelCard.vue` / `LineageGraph.vue` /
  `MarkdownEditor.vue`（不在本 ADR 范围）
- 训练流程自动注册模型：在 `trainer.py` 训练完成后自动调用
  `ResourceCardService.register_model()`（作为后续优化）
- 模型指标曲线可视化：前端基于 `metrics_history_json` 渲染 ECharts 折线图
  （不在本 ADR 范围）

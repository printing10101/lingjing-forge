# ADR-008: 参数化几何输出（特征 → B-rep → STEP + 工程师两轮审核）

**日期**: 2026-07-13  
**状态**: 已接受  
**决策者**: 项目负责人（独立开发）  
**前置 ADR**: [ADR-007-几何特征辅助提取.md](ADR-007-几何特征辅助提取.md)（阶段 2 导出的 `confirmed_features.json` 是本模块的输入）

---

## 背景

阶段 2（ADR-007）已经完成「mesh → 平面/圆柱/孔/凸台特征列表 + 工程师审核」链路，输出的 `confirmed_features.json` 包含工程师审核通过的特征参数（带 `effective_params()` 合并工程师编辑值）。

但特征列表是「离散几何参数」的 JSON 表示，**无法直接用于**：
- CAM 软件二次校验（NX / PowerMill / PyCAM 只接受 STEP / IGES 等参数化 CAD 格式，不接受 JSON）
- 工艺参数计算（CAM 软件需要从 STEP 中读取完整 B-rep 拓扑，计算刀具路径与残留高度）
- 颤振预测（LTC 网络需要切削深度 / 切削宽度等数值输入，这些数值依赖完整的几何表达）
- G 代码生成（OpenCAMLib 需要 STEP / STL 几何作为刀轨生成输入）

业界公认的硬约束（项目记忆已记录，与 ADR-007 一致）：**mesh → 参数化 CAD 的自动转换在工业上未解决**。因此阶段 3 不能追求「特征列表 → 全自动 STEP 生成」，必须定位为**「工程师助手」**：
- 算法将特征列表转换为 B-rep 中间表示（`BrepShape`）→ 装配为 `AssemblyPlan` → 调用 STEP 引擎写入 STEP 文件
- 工程师对生成的 STEP 进行两轮审核：
  - 第一轮（STEP_GENERATED）：审核 STEP 中特征表达是否与原始特征参数一致
  - 第二轮（REVIEWED）：基于 `effective_params()` 重新生成最终 STEP
- 最终 STEP **必须**导入 CAM 软件（NX / PowerMill / PyCAM）做二次校验后才允许上机床

工业级配合面（H7/h6 等，0.01 mm 公差）物理上无法用手机摄影测量达到，本模块输出的 STEP 仅可作为「工艺理解参考」与「CAM 软件刀轨生成输入」，**不可直接作为加工依据**。

## 决策

采用 **pythonOCC 优先 + FreeCAD API 降级 + 简易 STEP 模板兜底的三级降级策略**，结合 **BrepShape 中间表示 + AssemblyPlan 装配规则 + 工程师两轮审核状态机** 作为阶段 3 的核心 pipeline。整体链路按 7 阶段推进，本 ADR 仅覆盖阶段 3（参数化几何输出）。

### 阶段 3 实现要点

1. **分层架构（4 层清晰职责）**：
   ```
   特征参数 (JSON) ──┐
                     ├─→ feature_to_brep.py    (纯数据转换层)
                     │   ↓
                     │   BrepShape 列表
                     │   ↓
                     ├─→ assembly_builder.py  (装配规则层)
                     │   ↓
                     │   AssemblyPlan
                     │   ↓
                     ├─→ step_writer.py       (STEP IO 层，三级降级)
                     │   ↓
                     │   STEP 文件 (.stp)
                     │   ↓
                     └─→ pipeline.py          (编排器 + 状态机 + 两轮审核)
   ```

2. **BrepShape 中间表示（不依赖 OpenCASCADE）**：
   - 设计动机：pythonOCC / FreeCAD 在 CI / 桌面轻量档位可能缺失，需要一种纯 Python 数据结构作为「特征参数 → STEP 引擎」之间的隔离层
   - 字段：`shape_id` / `shape_type` / `operation`（add / subtract）/ `origin` / `direction` / `params` / `source_feature_id` / `conversion_notes`
   - 转换规则（`feature_to_brep.py`）：
     - `plane` → `BrepShape(shape_type=plane, operation=add, params={width_mm, height_mm})`
     - `cylinder` → `BrepShape(shape_type=cylinder, operation=add, params={radius_mm, height_mm})`
     - `hole` → `BrepShape(shape_type=cylinder, operation=subtract, params={radius_mm, depth_mm})`
     - `boss` → `BrepShape(shape_type=cylinder, operation=add, params={radius_mm, height_mm})`
   - 容错：`radius` / `height` 非法值（0 / 负数）回退为 `0.1`，避免 STEP 引擎写入失败
   - 跳过：`rejected` 状态特征不进入 BrepShape 列表；未识别 `feature_type` 记入 `skipped_features`

3. **AssemblyPlan 装配规则（`assembly_builder.py`）**：
   - **基准选择**：`plane` 优先作为 `base_shape`（工艺上平面通常为零件底面，先加工底面再加工侧面）
   - **add 形状排序**：非 plane 的 add 形状按体积从大到小（先大后小，避免小特征被 fuse 覆盖）
   - **subtract 形状排序**：按 `shape_id` 保持稳定顺序（钻孔顺序不影响最终几何，但稳定顺序便于工程师审核）
   - **毛坯 bbox 估算**：所有 add 形状的 axis-aligned bbox 并集 + 配置的 `blank_margin_mm`（默认 2.0 mm，仅供 CAM 软件参考，不强制约束）
   - **辅助形状**：多个 plane 时，第一个 plane 作为 base，其余 plane 记入 `auxiliary_shapes`（仅作为参考几何，不参与布尔运算，避免非流形几何）
   - **BoundingBox 工具类**：`union_point` / `union_bbox` / `expand` / `is_empty` / `size_x/y/z` / `center`，纯 Python 实现，不依赖 OpenCASCADE

4. **STEP 写入器三级降级（`step_writer.py`）**：
   - **优先级 1: PythonOCCStepWriter**（基于 `OCC.Core.STEPControl`）
     - 工业级 STEP 表达能力最强，支持完整 B-rep 拓扑（顶点 / 边 / 面 / 壳 / 实体）
     - 通过 `BRepPrimAPI_MakeBox` / `BRepPrimAPI_MakeCylinder` / `BRepAlgoAPI_Fuse` / `BRepAlgoAPI_Cut` 构造几何
     - 输出符合 ISO 10303-21 AP214 标准的 STEP 文件
     - 缺点：依赖 `pythonocc-core`，安装复杂（conda-forge 安装或源码编译），CI 环境通常缺失
   - **优先级 2: FreeCadStepWriter**（基于 FreeCAD Python API）
     - 基于 OpenCASCADE，但通过 FreeCAD 封装，安装 FreeCAD 即可用
     - 通过 `Part.makeBox` / `Part.makeCylinder` / `Shape.fuse` / `Shape.cut` 构造几何
     - 输出符合 STEP AP214 标准
     - 缺点：依赖 FreeCAD 安装（约 500 MB），桌面轻量档位可能缺失
   - **优先级 3: TemplateStepWriter**（简易 STEP 模板，零依赖）
     - 手工拼接 ISO 10303-21 字符串，仅包含基本 HEADER + DATA 段
     - 不构造真正的 B-rep 拓扑，仅输出「特征参数元数据」作为 STEP 注释
     - 主要用途：CI 环境验证管线流程，不进入生产链路
   - **无引擎可用时**：`write_step_with_fallback()` 返回 `StepWriteResult(success=False, engine_used="unavailable")`，pipeline 将任务标记为 FAILED 并提示工程师安装 pythonOCC / FreeCAD

5. **工程师两轮审核状态机**（与阶段 2 的单轮审核不同）：
   ```
   PENDING → RUNNING → STEP_GENERATED → REVIEWED → SUCCEEDED
                 ↓             ↓              ↓             ↓
               FAILED       CANCELLED      FAILED         FAILED
              (引擎不可用)                 (最终 STEP 写入失败)
   ```
   - **第一轮（STEP_GENERATED → REVIEWED）**：审核算法生成的「中间 STEP」中特征表达是否与原始特征参数一致
     - 工程师可对每个特征做 `confirmed` / `rejected` / `edited` 三种动作
     - `edited` 时需提供 `edited_params`，将覆盖原始 `params`
     - 全部特征审核完毕后状态自动转移到 `REVIEWED`
   - **第二轮（REVIEWED → SUCCEEDED）**：基于 `effective_params()` 重新生成最终 STEP
     - `finalize_step()` 异步执行：重新加载已审核特征 → 重新调用 `feature_to_brep` → 重新装配 → 重新写入 STEP
     - 最终 STEP 写入成功后状态转移到 `SUCCEEDED`，记录 `final_step_path`
   - **审核状态不允许跳过**：阶段 2 的「FEATURES_EXTRACTED 状态可导出」宽松策略在阶段 3 不再适用——STEP 文件一旦生成即可能被 CAM 软件导入，必须全部审核完毕才能进入 SUCCEEDED 状态

6. **单条特征审核四态**：`StepReviewStatus` 枚举（与阶段 2 `FeatureReviewStatus` 字段一致，便于复用 UI）
   - `pending`: 等待工程师审核（STEP 生成后的默认状态）
   - `confirmed`: 工程师确认 STEP 中特征表达与原始参数一致
   - `rejected`: 工程师拒绝该特征（不进入最终 STEP）
   - `edited`: 工程师编辑过参数，`finalize_step` 时使用 `edited_params` 覆盖原始参数
   - 生效参数通过 `ReviewedFeatureRef.effective_params()` 统一访问：若 `review_status == edited` 且 `edited_params` 非空则用编辑值，否则用原始 `source_params` 副本

7. **精度告知机制**：所有 API 响应必须携带 `step_disclaimer` 字段（通过 `build_step_disclaimer()` 构造）
   - `mesh_calibrated`: 上游 mesh 是否已做尺度归一化（从阶段 2 软依赖查询）
   - `feature_source`: 上游特征提取任务 ID（追溯链路）
   - `precision_tier`: 精度档位（继承自上游，不引入新档位）
   - `engine_used`: STEP 写入引擎（pythonocc / freecad / template / unavailable）
   - `engine_precision_note`: 引擎精度说明（4 种引擎对应 4 种说明）
   - `requires_engineer_review`: 始终 `True`（项目记忆硬约束）
   - `requires_cam_validation`: 始终 `True`
   - `industrial_hard_gates`: 8 条硬门槛警告（含「mesh→CAD 自动转换工业上未解决」「0 缺陷良品率」「0.01mm 配合面公差不可达」「CNC 持证操作员」「导师签字+保险」「CAM 二次校验」「工程师助手定位」「mesh 标定依赖」）
   - `warning_message`: 根据 `mesh_calibrated` + `engine_used` 动态拼接（未标定 + 无引擎时强调「STEP 不可用」）

8. **三档精度规格**（继承自上游 image_to_3d / feature_extraction 模块，**不引入新档位**）：
   - `coarse`: 0.5-2.0 mm，STEP 仅可用于工艺理解
   - `standard`: 0.1-1.0 mm，非配合面特征可用
   - `high`: 0.1-0.5 mm，小零件细节特征可用，仍达不到工业级配合面公差

9. **条件导入 + 12-Factor 配置**：
   - `PythonOccStepWriter` / `FreeCadStepWriter` 在构造时通过 `try: import OCC.Core... / import FreeCAD` 检测可用性，失败时 `is_available()` 返回 `False`
   - `TemplateStepWriter` 零依赖，始终可用
   - `ParametricGeometryConfig`（8 个字段，环境变量前缀 `LNN_PG_*`）支持环境变量覆盖 + dataclass 默认值 + `__post_init__` 校验
   - `TaskStore` 单例模式（双重检查锁）+ 内存字典 + JSON 文件持久化 + 线程锁 + `reset_instance()`（供测试使用）

10. **异步执行 + 并发控制**：
    - `asyncio.Semaphore` 默认串行（`max_concurrent=1`），桌面模式硬件资源有限
    - `asyncio.to_thread` 将阻塞式 STEP 写入任务放到线程中执行，避免阻塞事件循环
    - `run_pipeline()` / `finalize_step()` 均为 async 方法

11. **上游软依赖追溯**：
    - `create_task()` 时通过 `_resolve_upstream_calibrated()` 查询阶段 2 `feature_extraction` 任务的标定状态
    - 三层 try/except ImportError 软依赖：`feature_extraction` → `image_to_3d` → 默认未标定
    - 即便上游模块未启用，本模块仍可独立运行（按未标定处理）

12. **API 路由设计**（10 个端点，与阶段 2 一致的 REST 风格）：
    - 端点路径前缀：`/api/v1/parametric_geometry/`
    - 权限检查：`require_permission("parametric_geometry:read")` / `require_permission("parametric_geometry:write")`（FastAPI dependency，运行时通过 RBAC 从数据库查询角色权限）
    - 所有响应携带 `step_disclaimer` 字段（强制前端展示硬门槛）

## 理由

### 考虑的方案

1. **方案 A: 直接调用 pythonOCC 生成 STEP（不使用 BrepShape 中间表示）**
   - 优点：实现简单，省去中间数据结构
   - 缺点：
     - pythonOCC 在 CI / 桌面轻量档位缺失时整个模块无法工作
     - 测试覆盖率低（CI 环境必然缺失 pythonocc-core）
     - 无法在「无引擎」环境下做基本的装配规则验证
   - 决策：**否决**

2. **方案 B: pythonOCC 优先 + FreeCAD 降级（无模板兜底）**
   - 优点：减少代码量
   - 缺点：
     - CI 环境（无 pythonOCC 也无 FreeCAD）完全无法验证 pipeline 状态机
     - 桌面轻量档位（用户未安装 CAD 软件）无法预览流程
   - 决策：**否决**（模板兜底虽不进入生产链路，但保证管线可测试）

3. **方案 C: pythonOCC 优先 + FreeCAD 降级 + 简易 STEP 模板兜底**（已选）
   - 优点：
     - 三级降级保证「无引擎环境下仍可走通 pipeline」
     - BrepShape 中间表示使测试可在 CI 环境运行（不依赖 OpenCASCADE）
     - 工业级 pythonOCC 引擎保证生产档位 STEP 表达能力
   - 缺点：
     - 三套引擎实现代码量较大（约 600 行）
     - 模板兜底输出的 STEP 仅含元数据，不进入 CAM 软件
   - 决策：**采纳**

4. **方案 D: 全自动特征 → STEP（不要求工程师两轮审核）**
   - 优点：用户操作简单
   - 缺点：
     - 项目记忆硬约束：mesh→CAD 自动转换工业上未解决，必须 human-in-the-loop
     - STEP 文件一旦生成即可能被 CAM 软件导入，未审核的 STEP 风险高
   - 决策：**否决**

### 关键设计权衡

1. **为什么使用 BrepShape 中间表示而不是直接传 feature_params 给 STEP 引擎？**
   - **隔离 OpenCASCADE 依赖**：BrepShape 是纯 Python dataclass，CI 环境（无 OpenCASCADE）也能完成装配规则验证
   - **统一接口**：pythonOCC / FreeCAD / Template 三套引擎接收相同的 `BrepShape` 列表，引擎选择逻辑集中在 `write_step_with_fallback()`
   - **可序列化**：BrepShape 可通过 `to_dict()` 序列化为 JSON，便于调试与持久化
   - **可测试**：`feature_to_brep.py` 转换逻辑可独立于 STEP 引擎测试

2. **为什么 plane 优先作为 base_shape？**
   - 工艺上平面通常为零件底面，先加工底面再加工侧面是常识
   - 若无 plane（仅有圆柱 / 孔），则取体积最大的 add 形状作为 base
   - 若全部为 subtract（无 add 形状），则 `base_shape=None`，pipeline 将任务标记为 FAILED 并提示工程师补充特征

3. **为什么多个 plane 时仅第一个作为 base，其余作为 auxiliary？**
   - 两个 plane fuse 后会产生非流形几何（共享面）
   - 非流形几何在 CAM 软件中无法处理（NX / PowerMill 会报错）
   - 第一个 plane 作为底座基准，其余 plane 仅记录到 STEP 作为参考几何（construction geometry）

4. **为什么两轮审核而不是一轮审核？**
   - **第一轮审核中间 STEP**：算法可能将特征参数错误转换为 BrepShape（如方向搞反、半径单位错误），工程师需要对照原始特征参数审核
   - **第二轮基于 effective_params 重新生成**：若工程师编辑了参数（如修改了半径），需要重新生成最终 STEP
   - 单轮审核无法同时处理「特征表达审核」和「参数编辑生效」两个独立需求
   - 与阶段 2 的单轮审核区别：阶段 2 审核的是「算法提取的特征参数」，阶段 3 审核的是「STEP 中的特征表达」，两者关注点不同

5. **为什么 STEP_GENERATED 状态不允许直接 finalize（必须全部审核完才能进入 REVIEWED）？**
   - STEP 文件一旦生成即可能被 CAM 软件导入
   - 部分特征未审核即 finalize 会导致最终 STEP 包含未审核的特征，风险高
   - 与阶段 2 「FEATURES_EXTRACTED 状态可导出」宽松策略不同——阶段 2 导出的是 JSON（仅供阶段 3 消费），阶段 3 输出的是 STEP（可能直接进入 CAM 软件）

6. **为什么 SUCCEEDED 状态的 STEP 仍要求 CAM 二次校验？**
   - 工程师审核通过仅意味着「特征表达正确」，不代表「加工策略合理」
   - 刀具路径 / 切削参数 / 残留高度等需 CAM 软件精确计算
   - 项目记忆硬约束：生成 G 代码必须经过 CAM 软件（NX / PowerMill / PyCAM）二次校验后才允许上机床

7. **为什么 TemplateStepWriter 输出仅含元数据而不构造真正的 B-rep？**
   - 真正的 B-rep 拓扑构造需要 OpenCASCADE 支持
   - 模板兜底的主要用途是 CI 环境验证 pipeline 流程，不进入生产链路
   - 若用户在无 pythonOCC / FreeCAD 环境下尝试生产 STEP，pipeline 将任务标记为 FAILED 并提示安装依赖

8. **为什么上游软依赖使用三层 try/except ImportError？**
   - 阶段 3 任务可能由阶段 2 创建，也可能由用户上传外部 `confirmed_features.json` 创建
   - 阶段 2 可能未启用（`LNN_FE_ENABLED=false`），但阶段 1（image_to_3d）仍可查询 mesh 标定状态
   - 即便阶段 1 也未启用，本模块仍需独立运行（按未标定处理），不阻断流程

## 后果

### 正面后果

1. **明确划分算法与工程师责任**：算法给建议（BrepShape + AssemblyPlan + STEP）、工程师做决策（两轮审核），符合工业生产 human-in-the-loop 要求
2. **三级降级保证可用性**：pythonOCC（生产）/ FreeCAD（桌面）/ Template（CI 验证）三级降级保证任何环境下 pipeline 都能走通
3. **BrepShape 中间表示使测试可独立于 OpenCASCADE**：CI 环境（无 pythonocc-core）也能完成装配规则验证与状态机测试
4. **精度告知透明**：`step_disclaimer` 字段强制前端展示硬门槛，避免误用
5. **状态机可追溯**：每个任务的 `reviewed_by` / `reviewed_at` / `engineer_notes` 完整记录审核历史，满足 ISO 27001 / SOC 2 审计要求
6. **STEP 输出符合国际标准**：pythonOCC / FreeCAD 引擎输出符合 ISO 10303-21 AP214 标准，可被主流 CAM 软件导入
7. **上游追溯链完整**：`source_feature_extraction_task_id` + `feature_source` + `mesh_calibrated` 完整追溯链路，便于工程师定位问题

### 负面后果

1. **两轮审核耗时**：每个零件 10-60 分钟工程师审核时间，无法做到「拍照即出 STEP」
   - 缓解：算法置信度高的特征可批量 `confirmed`，仅低置信度特征需要逐条审核
2. **精度仍受上游 mesh 限制**：即便工程师审核通过，STEP 几何精度仍受 SfM 噪声影响
   - 缓解：`step_disclaimer` 明确告知「不可用于工业级配合面（0.01mm 公差）」
3. **特征类型有限**：当前仅支持平面 / 圆柱 / 孔 / 凸台四类，不支持螺纹、键槽、倒角等复杂特征
   - 缓解：阶段 3 输出的 STEP 可在 CAM 软件中由工程师手工补充这些特征
4. **依赖 pythonocc-core**：生产档位必须安装 pythonocc-core，安装较复杂
   - 缓解：提供 FreeCAD 降级路径；部署文档建议 conda-forge 安装 `pythonocc-core`
5. **毛坯 bbox 估算精度有限**：简化处理（不旋转方向）导致 cylinder 沿任意方向的 bbox 不精确
   - 缓解：`blank_bbox` 仅供 CAM 软件参考，实际下料尺寸由工艺工程师决定
6. **TemplateStepWriter 输出无 B-rep 拓扑**：CI 环境生成的 STEP 仅含元数据，不可用于 CAM 校验
   - 缓解：测试用例通过 mock `write_step_with_fallback` 隔离引擎选择逻辑

## 验收标准

- [x] 三级 STEP 引擎（pythonOCC / FreeCAD / Template）均能写入 STEP 文件
- [x] 无引擎可用时返回 `engine_used="unavailable"` 并将任务标记为 FAILED
- [x] BrepShape 中间表示不依赖 OpenCASCADE，CI 环境可独立测试
- [x] 装配规则正确（plane 优先 base + 体积排序 + shape_id 稳定排序）
- [x] 工程师两轮审核状态机完整（PENDING → RUNNING → STEP_GENERATED → REVIEWED → SUCCEEDED）
- [x] 第一轮审核支持 confirmed / rejected / edited 三种动作 + 全部审核完自动转 REVIEWED
- [x] 第二轮 finalize_step 基于 effective_params 重新生成最终 STEP
- [x] 所有 API 响应携带 `step_disclaimer` 字段（含 8 条工业硬门槛警告 + 4 种引擎精度说明）
- [x] 上游 mesh 标定状态软依赖查询（feature_extraction / image_to_3d 模块均未启用时按未标定处理）
- [x] SUCCEEDED 状态任务禁止删除（避免误删阶段 4 已引用的 STEP 文件）
- [x] 桌面轻量档位（仅 numpy + 模板引擎）可运行，pythonocc-core / FreeCAD 缺失时降级
- [x] `LNN_PG_ENABLED=false` 时模块完全关闭，main.py 不注册路由
- [x] 配置项支持环境变量覆盖（12-Factor App 原则）
- [x] 精度档位继承自上游，不引入新档位

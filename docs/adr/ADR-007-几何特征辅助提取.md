# ADR-007: 几何特征辅助提取（mesh → 平面/圆柱/孔特征列表 + 工程师审核）

**日期**: 2026-07-13  
**状态**: 已接受  
**决策者**: 项目负责人（独立开发）  
**前置 ADR**: [ADR-006-拍照重建模块.md](ADR-006-拍照重建模块.md)（阶段 1 输出的 mesh 是本模块的输入）

---

## 背景

阶段 1（ADR-006）已经完成「手机多角度拍照 → COLMAP SfM → OpenMVS 稠密化 → 标定块尺度归一化 mesh」链路，输出的 PLY/STL mesh 可以是带 mm 尺度的（放置标定块时）或无量纲的（未放置标定块时）。

但 mesh 是「点云 + 三角面片」的离散表示，**无法直接用于**：
- 工艺参数计算（切削深度、行距、残留高度需要平面/圆柱/孔等几何特征参数）
- 颤振预测（LTC 网络需要切削深度、切削宽度等数值输入）
- G 代码生成（需要明确的特征边界与几何参数）
- CAM 软件二次校验（CAM 软件接受的是 STEP/IGES 等参数化 CAD，不是 mesh）

业界公认的硬约束（项目记忆已记录）：**mesh → 参数化 CAD 的自动转换在工业上未解决**。学术界虽有 Pix2CAD / Point2CAD 等研究，但均停留在实验室阶段，对噪声敏感、对常见工程特征（螺纹、键槽、倒角）识别率低，无法满足生产级 0 缺陷良品率要求。

因此阶段 2 不能追求「全自动 mesh → CAD」，必须定位为**「工程师助手」**：算法提取候选特征 → 工程师逐条审核（confirmed / rejected / edited）→ 导出已确认特征集 → 供阶段 3 参数化 STEP 生成使用。

工业级配合面（H7/h6 等，0.01 mm 公差）物理上无法用手机摄影测量达到，本模块输出的特征参数必须经工程师审核 + CAM 软件（NX/PowerMill/PyCAM）二次校验后才允许上机床。

## 决策

采用 **RANSAC 平面拟合 + 圆柱拟合 + 孔/凸台检测 + 工程师审核状态机** 作为阶段 2 的核心 pipeline。整体链路按 7 阶段推进，本 ADR 仅覆盖阶段 2（几何特征辅助提取）。

### 阶段 2 实现要点

1. **三类特征 + 一类凸台**：算法提取 4 类几何特征
   - **平面（plane）**：RANSAC 拟合 + 迭代提取多个平面，输出 `{normal, offset, area_mm2}`
   - **圆柱面（cylinder）**：RANSAC 拟合圆柱侧面，输出 `{axis, center, radius_mm, height_mm}`
   - **孔（hole）**：在已检测平面的内点上做 RANSAC 圆环拟合，圆心附近点沿法向量偏移判定凹陷，输出 `{normal, center, radius_mm, depth_mm}`
   - **凸台（boss）**：与孔检测共用 RANSAC 圆环拟合逻辑，圆心附近点沿法向量偏移判定凸起，输出 `{normal, center, radius_mm, height_mm}`

2. **双路径 RANSAC 实现**：每个提取器都提供「优先用第三方库 + 退化为纯 numpy 实现」的双路径
   - 平面：`sklearn.linear_model.RANSACRegressor` 优先，不可用时退化为纯 numpy RANSAC（最小二乘 + 内点统计）
   - 圆柱：`pyransac3d` 优先，不可用时退化为纯 numpy RANSAC（随机采样 2 点定轴线 → 投影到 2D 平面 → Kåsa 代数法拟合圆）
   - 孔/凸台：与圆柱拟合的区别——**圆柱拟合的是「侧面」，孔/凸台拟合的是「端面圆周」**；随机采样 3 点定圆 → 统计圆周内点
   - mesh 加载：`trimesh` 优先（支持 PLY/STL/GLB/OBJ），不可用时退化为简易 ASCII PLY 解析（仅支持 vertex + face）

3. **工程师审核状态机**（与拍照重建的纯算法状态机不同）：
   ```
   PENDING → RUNNING → FEATURES_EXTRACTED → REVIEWED → SUCCEEDED
                 ↓             ↓                ↓
               FAILED       CANCELLED        FAILED（审核不通过）
   ```
   - `FEATURES_EXTRACTED`: 算法提取完成，等待工程师审核
   - `REVIEWED`: 工程师已审核每个特征（confirmed / rejected / edited）
   - `SUCCEEDED`: 已确认的特征集导出为 JSON，供阶段 3 参数化 STEP 生成使用

4. **单条特征审核四态**：`FeatureReviewStatus` 枚举
   - `pending`: 等待工程师审核（算法提取后的默认状态）
   - `confirmed`: 工程师确认无误，使用算法原始参数
   - `rejected`: 工程师拒绝（误识别），不进入阶段 3
   - `edited`: 工程师编辑过参数，使用 `edited_params` 覆盖原始参数
   - 生效参数通过 `ExtractedFeature.effective_params()` 统一访问：若 `review_status == edited` 且 `edited_params` 非空则用编辑值，否则用原始 `params`

5. **精度告知机制**：所有 API 响应必须携带 `feature_disclaimer` 字段（通过 `build_feature_disclaimer()` 构造）
   - `mesh_calibrated`: 上游 mesh 是否已做尺度归一化（影响所有几何参数单位）
   - `mesh_source`: mesh 来源标识（image_to_3d 任务 ID 或 "external_upload"）
   - `extraction_method`: 提取方法描述（含 RANSAC 阈值、半径范围等）
   - `expected_confidence_range`: 预期置信度范围（"0.60-0.95（RANSAC inlier 比例，仅供参考）"）
   - `requires_engineer_review`: 始终 `True`（项目记忆硬约束）
   - `requires_cam_validation`: 始终 `True`
   - `industrial_hard_gates`: 8 条硬门槛警告（含「mesh→CAD 自动转换工业上未解决」「0 缺陷良品率」「0.01mm 配合面公差不可达」「CNC 持证操作员」「导师签字+保险」「CAM 二次校验」「工程师助手定位」）
   - `warning_message`: 根据 mesh 标定状态动态拼接（未标定时强调「无量纲值仅可可视化」，已标定时强调「精度受 SfM 噪声影响」）

6. **三档精度规格**（继承自上游 image_to_3d 模块）：
   - `coarse`: 0.5-2.0 mm，特征参数误差较大，仅可用于工艺理解
   - `standard`: 0.1-1.0 mm，非配合面特征可用，配合面仍不可达
   - `high`: 0.1-0.5 mm，小零件细节特征可用，仍达不到工业级配合面公差

7. **条件导入 + 12-Factor 配置**：
   - `_try_import_sklearn()` / `_try_import_pyransac3d()` / `_try_import_trimesh()` 返回模块或 None，不可用时退化
   - `FeatureExtractionConfig`（20+ 字段，环境变量前缀 `LNN_FE_*`）支持环境变量覆盖 + dataclass 默认值 + `__post_init__` 校验
   - `TaskStore` 单例模式（双重检查锁）+ 内存字典 + JSON 文件持久化 + 线程锁

8. **异步执行 + 并发控制**：
   - `asyncio.Semaphore` 默认串行（`max_concurrent=1`），桌面模式硬件资源有限
   - `asyncio.to_thread` 将阻塞式 CPU 密集任务（RANSAC 拟合、mesh 加载）放到线程中执行，避免阻塞事件循环

## 理由

### 考虑的方案

1. **方案 A: 全自动 mesh → CAD 转换（如 Pix2CAD / Point2CAD 等学术方案）**
   - 优点：无需工程师介入，全自动
   - 缺点：
     - 工业上未解决，对噪声敏感、对常见工程特征（螺纹、键槽、倒角）识别率低
     - 无法满足生产级 0 缺陷良品率要求
     - 项目记忆硬约束：mesh→CAD 自动转换工业上未解决，生产系统依赖 human-in-the-loop
   - 决策：**否决**

2. **方案 B: RANSAC 平面/圆柱/孔检测 + 工程师审核**（已选）
   - 优点：
     - RANSAC 是工业上成熟的几何特征提取算法，对噪声鲁棒
     - 双路径实现（第三方库 + 纯 numpy）保证桌面轻量档位也能运行
     - 工程师审核状态机明确划分责任：算法给建议、工程师做决策
     - 输出的 JSON 格式简洁，便于阶段 3 参数化 STEP 生成模块消费
   - 缺点：
     - 工程师审核需要时间（每个零件约 5-30 分钟，取决于特征数量）
     - 仍然达不到工业级配合面公差（0.01mm），仅可用于非配合面
   - 决策：**采纳**

3. **方案 C: 深度学习点云分割（如 PointNet++ / PointTransformer）**
   - 优点：理论上能识别更复杂的特征（螺纹、键槽、倒角）
   - 缺点：
     - 需要大量标注数据（机械零件 mesh + 特征标注），数据集匮乏
     - 模型训练需要 GPU，与「普通手机 + 笔记本即可运行」约束冲突
     - 推理结果可解释性差，工程师难以审核
   - 决策：**否决**（可作为未来研究方向，但不进入生产链路）

### 关键设计权衡

1. **为什么 RANSAC 而不是霍夫变换？**
   - RANSAC 对噪声更鲁棒（霍夫变换对参数空间分辨率敏感）
   - RANSAC 可直接给出内点集（用于工程师审核时高亮显示）
   - RANSAC 实现简单，纯 numpy 也可运行

2. **为什么孔检测要分两步（先平面、后圆环）？**
   - 直接在全局点云上做圆环拟合会产生大量误检（任意三点都能定圆）
   - 先用平面 RANSAC 找到候选平面 → 在平面内点上做圆环拟合，可显著降低误检率
   - 未传入平面时退化为「全局 PCA 求主法向量 → 在 2D 投影上找圆环」（精度略低但可用）

3. **为什么 HOLE / BOSS 判定用「圆心附近点沿法向量偏移」？**
   - 圆环拟合只能给出圆心和半径，无法区分孔（凹陷）和凸台（凸起）
   - 取圆心附近（距圆心 < 0.3 * radius）的内点，计算沿法向量方向的偏移：
     - `offset < -threshold` → HOLE（凹陷）
     - `offset > +threshold` → BOSS（凸起）
     - `|offset| <= threshold` → 默认 HOLE（保守判定，避免误判凸台）

4. **为什么允许 `FEATURES_EXTRACTED` 状态导出？**
   - 工程师可能希望「边审核边导出」——审核一部分特征后立即导出供阶段 3 试用
   - 严格「全部审核完毕才能导出」会降低工作效率
   - 但 `exported_features_path` 仅在 `SUCCEEDED` 状态稳定记录，避免误用

5. **为什么 `create_task_from_upload` 上传 mesh 时仍查询上游 `mesh_calibrated`？**
   - 用户上传的 mesh 可能就是从阶段 1 拍照重建任务下载的
   - 若用户在请求中提供 `source_reconstruction_task_id`，系统应能追溯上游标定状态
   - 即便上游 `calibrated=True`，本地上传的 mesh 也可能与上游不同——此场景需工程师人工确认

## 后果

### 正面后果

1. **明确划分算法与工程师责任**：算法给建议、工程师做决策，符合工业生产 human-in-the-loop 要求
2. **桌面轻量档位可用**：双路径 RANSAC 实现保证 numpy-only 环境也能运行
3. **精度告知透明**：`feature_disclaimer` 字段强制前端展示硬门槛，避免误用
4. **状态机可追溯**：每个任务的 `reviewed_by` / `reviewed_at` / `engineer_notes` 完整记录审核历史，满足 ISO 27001 / SOC 2 审计要求
5. **JSON 输出便于消费**：阶段 3 参数化 STEP 生成模块直接读取 `confirmed_features.json`，无需解析 mesh

### 负面后果

1. **审核耗时**：每个零件 5-30 分钟工程师审核时间，无法做到「拍照即出 G 代码」
   - 缓解：算法置信度高的特征可批量 `confirmed`，仅低置信度特征需要逐条审核
2. **精度仍受上游 mesh 限制**：即便工程师审核通过，特征参数精度仍受 SfM 噪声影响
   - 缓解：`feature_disclaimer` 明确告知「不可用于工业级配合面（0.01mm 公差）」
3. **特征类型有限**：当前仅支持平面/圆柱/孔/凸台四类，不支持螺纹、键槽、倒角等复杂特征
   - 缓解：阶段 3 参数化 STEP 生成时，工程师可手工补充这些特征
4. **依赖第三方库**：`sklearn` / `pyransac3d` / `trimesh` 缺失时退化路径精度略低
   - 缓解：纯 numpy 实现保证基本可用，部署文档建议安装完整依赖

  - 工业级配合面（H7/h6 等，0.01mm 公差）物理上无法用手机摄影测量达到

# ADR-009: 切削参数推荐（材料 + 特征 + 精度档位 → ChatterParams 工程师审核）

**日期**: 2026-07-14  
**状态**: 已接受  
**决策者**: 项目负责人（独立开发）  
**前置 ADR**: [ADR-008-参数化几何输出.md](ADR-008-参数化几何输出.md)（阶段 3 输出的 STEP 文件 + 阶段 2 `confirmed_features.json` 是本模块的输入）

---

## 背景

阶段 3（ADR-008）已经完成「特征参数 → BrepShape → AssemblyPlan → STEP 文件 + 工程师两轮审核」链路，输出的 STEP 文件可供 CAM 软件（NX / PowerMill / PyCAM）做刀轨校验。但 STEP 文件本身**不携带切削参数**：
- 切削速度 V_c（m/min）：决定主轴转速 n = V_c × 1000 / (π × D)，影响刀具寿命与颤振稳定性极限
- 每齿进给量 f_z（mm/tooth）：决定进给速度 F = n × z × f_z，影响表面粗糙度与切削力
- 轴向切深 a_p（mm）与径向切深 a_e（mm）：直接决定颤振稳定性图（Stability Lobe Diagram）的工作点
- 比切削力 K_s（N/mm²）：阶段 5 Tlusty 解析法颤振预测的核心输入，按材料校准

阶段 5 颤振预测需要 `ChatterParams`（spindle_rpm / machine / tool / axial_depth / cutting_force_coeff）作为输入，但这些参数不能由 CAM 软件或 STEP 文件直接给出，必须由本模块基于**材料切削性能数据库 + 几何特征类型 + 精度档位**推导得出。

业界公认的硬约束（项目记忆已记录，与 ADR-007 / ADR-008 一致）：**切削参数推荐不是「最优解搜索」问题，而是「可行域推荐 + 工程师审核」问题**。因此阶段 4 不能追求「全自动切削参数生成」，必须定位为**「工程师助手」**：
- 算法基于材料切削性能基线（`cutting_speed_range` / `feed_range` / `depth_of_cut_range` / `specific_cutting_force`）+ 特征类型（plane / cylinder / hole / boss）+ 精度档位（coarse / standard / high）推导保守参数
- 工程师对推荐结果逐条审核：confirmed（确认）/ rejected（拒绝，不进入 ChatterParams）/ edited（修正，提供 `edited_params` 覆盖推荐值）
- 导出的 `ChatterParams` JSON 仅供阶段 5 颤振预测参考，**实际加工必须经 CAM 软件（NX / PowerMill / PyCAM）二次校验 + 持证操作员 + 导师签字**

材料数据可信度是阶段 4 的核心约束（项目记忆硬约束）：
- HRC52 淬火钢是项目自采工业数据的核心组成，但当前仅有工程估算值（K_s ≈ 2800 N/mm²），标注 `pending_calibration`
- 6061-T6 / TC4 等材料复用 `python/app/database/data/materials.json` 已有 17 种材料基线
- HRC52 不可使用纯文献数据，必须通过自采工业数据校准后才允许进入正式 ChatterParams

工业级配合面（H7/h6 等，0.01 mm 公差）物理上无法用手机摄影测量达到，本模块输出的切削参数仅可作为「工艺理解参考」与「阶段 5 颤振预测输入」，**不可直接作为加工依据**。

## 决策

采用 **材料优先 + 特征驱动 + 精度档位继承** 的推荐策略，结合 **MaterialResolver 材料数据库 + CuttingParamRecommender 推荐引擎 + 工程师单轮审核状态机** 作为阶段 4 的核心 pipeline。整体链路按 7 阶段推进，本 ADR 仅覆盖阶段 4（切削参数推荐）。

### 阶段 4 实现要点

1. **分层架构（4 层清晰职责）**：
   ```
   阶段 3 STEP 路径 + 阶段 2 confirmed_features.json + material_id ──┐
                                                                     ├─→ material_resolver.py    (材料数据层)
                                                                     │   ↓
                                                                     │   MaterialParams (K_s / 范围 / Taylor)
                                                                     │   ↓
                                                                     ├─→ recommender.py          (推荐算法层)
                                                                     │   ↓
                                                                     │   RecommendedCuttingParams 列表
                                                                     │   ↓
                                                                     ├─→ pipeline.py             (编排器 + 状态机 + 审核 + 导出)
                                                                     │   ↓
                                                                     │   ChatterParams JSON
                                                                     │   ↓
                                                                     └─→ routes.py               (API 路由层)
   ```

2. **MaterialParams 数据类（16 字段，覆盖阶段 5 全部需求）**：
   - 标识字段：`id` / `name` / `category` / `data_source` / `calibration_status`
   - 物理属性：`hardness_hb` / `hardness_hrc`（淬火钢专用）/ `tensile_strength_mpa` / `thermal_conductivity` / `density_gcm3`
   - 切削性能：`specific_cutting_force`（K_s，N/mm²）/ `cutting_speed_range`（{roughing: [min,max], finishing: [min,max]}）/ `feed_range` / `depth_of_cut_range`
   - Taylor 刀具寿命：`taylor_exponent_n` / `taylor_constant_c`
   - 关键字段：`calibration_status` 取值 `calibrated` / `pending_calibration`，HRC52 强制 `pending_calibration`

3. **HRC52 补充数据（`_HRC52_SUPPLEMENT`）**：
   - 设计动机：项目记忆硬约束「HRC52 不可使用纯文献数据」，但 6061-T6 自采工业数据中包含 HRC52 工件，需在材料库中提供基线供阶段 5 颤振预测使用
   - 数据来源：基于淬火钢工程估算（HRC52 ≈ HB495，K_s ≈ 2800 N/mm²，切削速度远低于铝合金，roughing [20,40] / finishing [40,80] m/min）
   - 内存覆盖策略：通过 `_HRC52_SUPPLEMENT` 内存常量提供，**不修改原始 `materials.json`**（避免污染共享数据源）
   - 优先级：`MaterialResolver` 查询时优先返回 HRC52 补充数据，其次查 `materials.json` 数据库
   - 校准状态：强制 `calibration_status="pending_calibration"`，`data_source="hrc52_supplement"`，阶段 5 颤振预测必须读取此字段并降低 HRC52 工况的预测置信度

4. **CuttingParamRecommender 推荐引擎（「材料优先 + 特征驱动」策略）**：
   - **材料优先**：`specific_cutting_force`（K_s）直接决定阶段 5 颤振稳定性极限；`cutting_speed_range` / `feed_range` / `depth_of_cut_range` 决定推荐参数上下界
   - **特征驱动**：特征类型（plane / cylinder / hole / boss）决定径向切深 a_e 的默认比例
     - `plane`：a_e = 0.5 × D（行距，平面铣削）
     - `cylinder`：a_e = 0.3 × D（侧铣，避免过切）
     - `hole`：a_e = 1.0 × D（满刀，孔特征专用）
     - `boss`：a_e = 0.5 × D（外轮廓铣削）
   - **精度档位继承**：coarse → roughing / high → finishing / standard 视特征类型分流（hole / boss → finishing，plane / cylinder → roughing）
   - 支持的特征类型集合 `SUPPORTED_FEATURE_TYPES = frozenset({"plane", "cylinder", "hole", "boss"})`，与阶段 2 / 阶段 3 完全一致

5. **保守取值策略（便于工程师审核）**：
   - `cutting_speed`：取材料范围 [min, max] 的 1/3 分位（偏低，保证安全）
   - `feed_per_tooth`：取材料范围 [min, max] 的中位数
   - `axial_depth`：取材料范围 [min, max] 的中位数；hole + roughing 取下限（避免大切深断刀）
   - `radial_depth`：按特征类型占刀具直径比例（见实现要点 4）
   - `spindle_rpm` = V_c × 1000 / (π × D)
   - `feed_rate` = spindle_rpm × num_flutes × feed_per_tooth
   - `tool_life`：Taylor 公式 T = (C / V_c)^(1/n)（简化模型，仅作参考）
   - `cutting_time`：路径长度 100 mm 兜底参考（实际切削时间需 CAM 软件精确计算）

6. **状态机（单轮审核，PARAMS_RECOMMENDED → REVIEWED → SUCCEEDED）**：
   ```
   PENDING ──run_pipeline──→ RUNNING ──成功──→ PARAMS_RECOMMENDED
                                  │                  │
                                  │                  ├── review_params (逐条)
                                  │                  │     │
                                  │                  │     ├── confirmed → 保留
                                  │                  │     ├── rejected → 排除
                                  │                  │     └── edited   → 合并 edited_params
                                  │                  │     │
                                  │                  │     └── 全部审核完毕 ──→ REVIEWED
                                  │                  │                              │
                                  │                  │                              └── export_chatter_params ──→ SUCCEEDED
                                  │                  │
                                  └──失败──→ FAILED ←──┘
                                  │
                                  └──取消──→ CANCELLED
   ```
   - 与阶段 3 两轮审核（STEP_GENERATED + REVIEWED）不同，阶段 4 采用**单轮审核**：推荐结果一次性给出，工程师逐条审核后直接进入 REVIEWED，导出 ChatterParams 后转 SUCCEEDED
   - 设计权衡：切削参数是数值而非几何 B-rep，不存在「重新生成」的必要，工程师编辑后直接合并入 `effective_params()` 即可

7. **to_chatter_params_dict() 阶段 5 契约**：
   - 输入：`RecommendedCuttingParams`（取 `effective_params()`，工程师编辑值优先）
   - 输出：dict，可直接传给阶段 5 `ChatterParams(**dict)` 构造函数
   - 4 个顶层键：
     - `spindle_rpm`：float，主轴转速
     - `machine`：dict（machine_id / stiffness_x/y/z / damping_ratio / natural_freq / modal_mass），使用阶段 5 默认机床参数
     - `tool`：dict（tool_id / diameter / num_flutes / helix_angle=30° / **cutting_force_coeff = K_s**）
     - `axial_depth`：float，轴向切深
   - **K_s 契约**：`cutting_force_coeff` 直接取自 `MaterialParams.specific_cutting_force`，HRC52 标注 `pending_calibration` 时阶段 5 必须降低预测置信度

8. **精度告知机制（13 字段，所有 API 响应必带 `cutting_disclaimer`）**：
   - 上游精度：`mesh_calibrated` / `feature_source` / `step_source` / `precision_tier`
   - 材料可信度：`material_id` / `material_calibration_status`（calibrated / pending_calibration）
   - 设备参数：`machine_type` / `tool_diameter_mm`
   - 强制审核：`requires_engineer_review` = True / `requires_cam_validation` = True
   - 阶段 5 状态：`chatter_params_ready`（是否已导出 ChatterParams）
   - 工业硬门槛：`industrial_hard_gates`（8 条，与 ADR-008 一致并补充 K_s 校准条款）
   - 动态警告：`warning_message`（拼接 mesh 未标定 / 材料 pending / ChatterParams 未输出 / CAM 校验强制等片段）

9. **三档精度继承（不引入新档位）**：
   - `coarse`：粗加工档位，大切深 + 低精度，operation=roughing
   - `standard`：标准档位，平衡切深与精度，hole / boss → finishing，plane / cylinder → roughing
   - `high`：精加工档位，小切深 + 高精度，operation=finishing
   - 精度档位继承链：阶段 1 image_to_3d.precision_tier → 阶段 2 → 阶段 3 → 阶段 4
   - 本模块不引入新档位，全程继承上游告知，与 ADR-007 / ADR-008 完全一致

10. **条件导入 + 12-Factor 配置（与阶段 2 / 3 一致）**：
    - `routes.py` 通过 `_resolve_upstream_calibrated()` 三层 try/except ImportError 软依赖查询阶段 3 任务的 `mesh_calibrated` 字段
    - `parametric_geometry` 模块未启用时按未标定 mesh 处理，并记日志
    - 配置项支持环境变量覆盖（`LNN_CP_*` 前缀），遵循 12-Factor App 原则
    - `LNN_CP_ENABLED=false` 时模块完全关闭，`main.py` 不注册路由

11. **异步执行 + 上游软依赖追溯**：
    - `run_pipeline()` 为 async 方法，与阶段 3 一致
    - 上游追溯链：阶段 4 task → `source_parametric_geometry_task_id` → 阶段 3 task → `mesh_calibrated` 字段
    - 上游任务不存在 / 未 SUCCEEDED / 异常时按未标定处理，记日志不阻塞
    - 上游 STEP 文件路径仅作追溯用，本模块不重新解析 STEP（实际特征参数取自阶段 2 `confirmed_features.json`）

12. **9 个 API 端点（与阶段 3 端点结构对齐）**：
    - `GET /precision_info`：查询精度档位 + 材料列表（含 HRC52 待校准状态）+ 工业硬门槛 + 审核流程说明（不创建任务）

    - `POST /tasks/{task_id}/run`：异步触发流水线（PENDING / FAILED 可执行）
    - `GET /tasks/{task_id}`：查询状态 + 审核进度统计（pending / confirmed / rejected / edited 计数）
    - `GET /tasks`：列出最近任务
    - `GET /tasks/{task_id}/result`：获取推荐参数列表 + `effective_params`
    - `POST /tasks/{task_id}/review`：工程师审核（action = confirmed / rejected / edited）
    - `POST /tasks/{task_id}/export`：导出 ChatterParams JSON → SUCCEEDED
    - `GET /tasks/{task_id}/chatter_params/download`：下载 JSON 文件

    - 设计动机：阶段 5 颤振预测可能已引用 ChatterParams JSON，删除会导致阶段 5 任务悬空

    - 与阶段 3 一致（STEP 文件被阶段 4 引用后禁止删除）

## 理由

### 方案对比

#### 方案 A：纯文献数据（Sandvik / Kennametal 手册）+ 全自动推荐

- 优点：覆盖材料广，无需自采数据
- 缺点：
  - **违反项目记忆硬约束**：HRC52 不可使用纯文献数据，必须基于自采工业数据校准
  - 文献数据未覆盖本项目使用的具体刀具 / 机床 / 冷却条件，K_s 偏差可达 ±30%
  - 阶段 5 颤振预测对 K_s 极其敏感（K_s 偏差直接传递到稳定性极限），文献值会导致预测结果不可信
  - 全自动推荐违反「工程师助手」定位，工业生产中切削参数必须经工程师审核

#### 方案 B：HRC52 补充数据 + pending_calibration 标注 + 工程师单轮审核（**已采用**）

- 优点：
  - HRC52 数据缺口通过内存补充数据补齐，标注 `pending_calibration`，阶段 5 颤振预测可读取此字段降低置信度
  - 6061-T6 / TC4 等材料复用已有 `materials.json`，避免重复维护
  - 工程师单轮审核符合切削参数的数值特性（不需要像 STEP 那样两轮重新生成）
  - `to_chatter_params_dict()` 提供清晰契约，阶段 5 可直接构造 `ChatterParams`
- 缺点：
  - HRC52 数据为工程估算值，需后续自采工业数据校准
  - 保守取值（1/3 分位）偏安全，可能牺牲材料去除率

#### 方案 C：ML 学习历史切削参数 + 个性化推荐

- 优点：理论上可学习企业历史最优参数
- 缺点：
  - 本项目为大一独立项目，无历史切削数据可学习
  - ML 推荐缺乏可解释性，工程师审核困难
  - 违反「材料优先」原则，K_s 必须基于材料物理属性而非历史数据

#### 方案 D：CAM 软件内置切削参数库直接调用

- 优点：参数与 CAM 软件一致
- 缺点：
  - NX / PowerMill 切削参数库为商业闭源，无法编程访问
  - 阶段 5 颤振预测需要 K_s，CAM 软件切削参数库不直接提供
  - 违反「不耦合商业软件」原则，桌面轻量档位无法运行

### 设计权衡

**Q1：为什么采用「材料优先」而非「特征优先」？**
A：阶段 5 颤振预测的核心输入是 `cutting_force_coeff`（K_s），K_s 完全由材料决定（TC4 ≈ 1600 / 6061-T6 ≈ 800 / HRC52 ≈ 2800 N/mm²）。特征类型仅影响 a_e（径向切深）的默认值，对颤振稳定性极限影响远小于 K_s。因此材料数据库是推荐引擎的一等公民，特征类型仅在材料基线确定后调整 a_e。

**Q2：为什么切削速度取 1/3 分位而非中位数？**
A：保守取值便于工程师审核。1/3 分位偏低保证安全，工程师若需要更高材料去除率可手动 edit 为中位数或上限。反向设计（取上限）一旦推荐错误，可能导致刀具崩刃或颤振，工业代价远高于保守取值。

**Q3：为什么 hole + roughing 取 axial_depth 下限？**
A：孔加工轴向切深等于孔深，大切深易导致断刀。即使是 roughing 档位，孔特征仍取下限值，避免推荐参数直接导致刀具损坏。

**Q4：为什么径向切深 a_e 按特征类型给固定比例而非材料推导？**
A：a_e 主要受刀具直径与几何特征约束（如侧铣 cylinder 时 a_e > 0.5×D 易过切），与材料关系较弱。固定比例便于工程师审核，且与 CAM 软件默认值一致。

**Q5：为什么 Taylor 刀具寿命公式简化为 T = (C / V_c)^(1/n)？**
A：完整 Taylor 公式还需考虑进给量与切深，但本项目材料库的 `taylor_exponent_n` 与 `taylor_constant_c` 仅为单参数拟合值。简化公式输出的 `tool_life_estimate_min` 仅作参考，实际刀具寿命需 CAM 软件基于完整切削条件计算。

**Q6：为什么 SUCCEEDED 状态禁止删除？**
A：阶段 5 颤振预测可能已引用 ChatterParams JSON 路径，删除会导致阶段 5 任务悬空。与阶段 3 STEP 文件被阶段 4 引用后禁止删除的设计一致。

**Q7：为什么 K_s → cutting_force_coeff 直接传递而非重新计算？**
A：阶段 5 Tlusty 解析法需要的是「单位切削力」（N/mm²），与 `MaterialParams.specific_cutting_force` 物理意义完全一致。直接传递避免二次拟合引入误差，HRC52 的 `pending_calibration` 状态通过 `calibration_status` 字段传递给阶段 5，由阶段 5 决定如何处理。

**Q8：为什么采用单轮审核而非阶段 3 的两轮审核？**
A：阶段 3 STEP 文件是几何 B-rep，工程师审核后可能需要基于 `effective_params()` 重新生成 STEP（第二轮 finalize）。阶段 4 切削参数是数值，工程师编辑后直接合并入 `effective_params()`，导出 ChatterParams 时取 `effective_params()` 即可，不需要「重新生成」环节。

## 后果

### 正面后果

1. **材料数据库统一**：6061-T6 / TC4 / HRC52 等材料参数集中在 `MaterialResolver`，阶段 5 / 阶段 6 可复用
2. **HRC52 数据缺口补齐**：内存补充数据避免依赖外部数据库，`pending_calibration` 标注强制阶段 5 降低预测置信度
3. **阶段 5 契约清晰**：`to_chatter_params_dict()` 输出 4 键 dict，阶段 5 可直接 `ChatterParams(**dict)` 构造，K_s 直接取自 `MaterialParams.specific_cutting_force`
4. **精度档位全程继承**：coarse / standard / high 三档与阶段 1 / 2 / 3 一致，不引入新档位
5. **工程师审核流程清晰**：单轮审核（PARAMS_RECOMMENDED → REVIEWED → SUCCEEDED）比阶段 3 两轮审核更简洁
6. **API 端点与阶段 3 对齐**：9 个端点结构与 `parametric_geometry` 一致，前端可复用组件
7. **条件导入 + 12-Factor**：模块可独立启停，`LNN_CP_ENABLED=false` 时不影响主程序
8. **HRC52 工业硬门槛强制告知**：所有 API 响应携带 `cutting_disclaimer`，前端必须展示 8 条工业硬门槛

### 负面后果

1. **HRC52 数据待校准**：K_s = 2800 N/mm² 为工程估算值，需后续自采工业数据校准后才能进入正式 ChatterParams
2. **保守取值偏安全**：1/3 分位切削速度可能牺牲材料去除率，工程师需手动 edit
3. **Taylor 刀具寿命简化模型**：未考虑进给量与切深，`tool_life_estimate_min` 仅为参考值
4. **切削时间估算粗糙**：路径长度 100 mm 兜底，实际切削时间需 CAM 软件精确计算
5. **不支持 5 轴加工参数**：当前仅支持 3 轴铣削（plane / cylinder / hole / boss），5 轴加工需阶段 6 / 7 扩展
6. **材料数据库未覆盖涂层刀具**：`specific_cutting_force` 基于无涂层刀具，涂层刀具需后续扩展

# ADR-003: 采用 SQLite 作为主数据库方案

**日期**: 2024-01-12  
**状态**: 已接受  
**决策者**: 数据库架构组、运维团队、技术负责人

---

## 背景

灵境制造系统需要选择合适的数据库方案来存储以下数据：

1. **用户和权限数据**：用户信息、角色、权限配置
2. **任务和工单数据**：加工任务、工艺参数、执行记录
3. **AI 模型数据**：模型配置、训练记录、推理结果
4. **知识图谱数据**：本体定义、实体关系、规则库
5. **审计日志**：操作日志、安全日志、系统日志
6. **时序数据**：传感器数据、监控指标（短期存储）

项目需要考虑以下约束条件：

- **部署环境**：支持边缘部署（工厂现场）和云端部署
- **运维成本**：需要低运维成本，适合中小规模部署
- **数据规模**：单实例数据量通常在 GB 级别，不超过 100GB
- **并发需求**：读多写少，并发写入通常 < 100 TPS
- **可靠性要求**：需要数据持久化和备份恢复能力

## 决策

采用 **SQLite 3.40+** 作为主数据库方案，配合以下策略：

- **嵌入式部署**：SQLite 作为嵌入式数据库，无需独立数据库服务
- **WAL 模式**：启用 Write-Ahead Logging 提升并发性能
- **数据分片**：按项目/租户分片，每个项目独立数据库文件
- **备份策略**：每日自动备份，保留 30 天
- **迁移工具**：使用 Alembic 管理数据库 Schema 演进
- **扩展方案**：需要时可通过 Litestream 实现实时复制到 S3

对于以下特殊场景，采用补充方案：

- **时序数据**：使用 InfluxDB 或 TimescaleDB（可选）
- **缓存数据**：使用 Redis
- **全文搜索**：使用 SQLite FTS5 扩展或 Elasticsearch（可选）

## 理由

### 考虑的方案

1. **方案 A：PostgreSQL**
   - 优点：
     - 功能强大，支持复杂查询和事务
     - 生态成熟，工具链完善
     - 支持 JSON、全文搜索、地理数据等高级特性
     - 并发性能好，支持高并发写入
   - 缺点：
     - 需要独立部署和维护数据库服务
     - 运维成本较高（备份、监控、调优）
     - 资源占用较大（内存、CPU）
     - 边缘部署复杂（需要安装和配置）

2. **方案 B：MySQL**
   - 优点：
     - 社区庞大，生态成熟
     - 性能稳定，可靠性高
     - 工具链完善，易于管理
   - 缺点：
     - 需要独立部署和维护
     - 运维成本较高
     - 对 JSON 和高级查询的支持不如 PostgreSQL
     - 边缘部署同样复杂

3. **方案 C：SQLite** **选择**
   - 优点：
     - **零运维**：无需独立数据库服务，无后台进程
     - **嵌入式**：与应用同进程，无网络开销
     - **轻量级**：资源占用极小，适合边缘部署
     - **可靠性高**：经过数十年验证，数据安全性高
     - **性能优秀**：读性能优异，WAL 模式下写性能良好
     - **易于备份**：单文件备份，简单可靠
     - **跨平台**：支持所有主流操作系统
   - 缺点：
     - 并发写入受限（单写者锁）
     - 不支持分布式事务
     - 缺少某些高级特性（如物化视图）
     - 数据规模受限（理论上限 281TB，实际建议 < 1TB）

### 决策依据

1. **部署场景**：系统需要支持边缘部署（工厂现场），SQLite 的零运维特性是关键优势
2. **数据规模**：单实例数据量通常在 GB 级别，SQLite 完全能够胜任
3. **并发需求**：读多写少，并发写入 < 100 TPS，SQLite WAL 模式能够满足
4. **运维成本**：SQLite 无需独立服务，大幅降低运维复杂度和成本
5. **可靠性**：SQLite 经过数十年验证，数据安全性有保障
6. **扩展性**：通过数据分片和 Litestream 复制，可以应对未来增长

## 后果

### 积极影响

- **运维简化**：无需维护独立数据库服务，运维成本降低 60%+
- **部署简化**：边缘部署无需安装数据库，部署时间从小时级降至分钟级
- **性能提升**：嵌入式部署无网络开销，读性能提升 20-30%
- **成本降低**：无需数据库许可证和额外的硬件资源
- **可靠性提升**：单文件备份简单可靠，恢复时间短
- **开发效率**：本地开发无需配置数据库，开箱即用

### 消极影响

- **并发限制**：高并发写入场景性能受限（可通过分片缓解）
- **扩展性限制**：单实例数据规模上限（可通过分片和归档缓解）
- **功能限制**：缺少某些高级特性（如物化视图、全文搜索需扩展）
- **监控复杂度**：需要自行实现数据库监控和告警

### 技术影响

- **Schema 设计**：需要精心设计表结构和索引，优化查询性能
- **并发控制**：需要使用乐观锁或队列机制处理并发写入
- **数据分片**：需要实现按项目/租户的数据分片逻辑
- **备份恢复**：需要实现自动化备份和恢复流程
- **迁移管理**：使用 Alembic 管理 Schema 演进
- **性能监控**：需要实现数据库性能监控和慢查询分析

### 业务影响

- **部署灵活性**：支持边缘和云端灵活部署，适应不同客户需求
- **总拥有成本**：降低数据库相关的硬件、软件和运维成本
- **交付速度**：简化部署流程，加快项目交付速度
- **客户满意度**：降低客户的运维负担和技术门槛

### 阶段二：数据分片（2024 Q2）
- 实现按项目/租户的数据分片逻辑

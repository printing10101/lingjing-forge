# ADR-013: 颤振预测接入 LTC（ChatterParams → 双路径预测 → ChatterReport 工程师审核）

**日期**: 2026-07-14  
**状态**: 已接受  
**决策者**: 项目负责人（独立开发）  
**前置 ADR**: [ADR-009-切削参数推荐.md](ADR-009-切削参数推荐.md)（阶段 4 输出的 `ChatterParams` JSON 是本模块的核心输入）

---

## 背景

阶段 4（ADR-009）已经完成「材料 + 特征 + 精度档位 → `MaterialResolver` 查询 → `CuttingParamRecommender` 推荐 → 工程师单轮审核 → 导出 `ChatterParams` JSON」链路，输出的 `ChatterParams` 携带阶段 5 颤振预测所需的全部输入：
- `spindle_rpm`（float）：主轴转速，决定颤振稳定性叶瓣图（Stability Lobe Diagram）的工作点
- `machine`（dict）：机床模态参数（`stiffness_x/y/z` / `damping_ratio` / `natural_freq` / `modal_mass`），Tlusty 解析法的 FRF 输入
- `tool`（dict）：刀具参数（`tool_id` / `diameter` / `num_flutes` / `cutting_force_coeff` = K_s），K_s 是颤振稳定性极限的核心输入
- `axial_depth`（float）：轴向切深，与稳定性极限直接比较判断是否稳定

但 `ChatterParams` 本身**不携带颤振稳定性结论**：
- 极限切深 `limit_depth_mm`（mm）：当前工况下不发生再生颤振的最大轴向切深
- 稳定性判定 `stable`（1.0/0.0）：当前 `axial_depth` 是否低于 `limit_depth_mm`
- 稳定性裕度 `stability_margin`：`(limit_depth - axial_depth) / limit_depth`，用于阶段 6 G 代码生成的切深自适应调整
- 预测方法 `method`（analytical / neural_network / fallback）：标记本预测结果的来源路径，供工程师审核决策

阶段 6 G 代码生成需要 `ChatterReport`（每个特征的稳定性结论 + 极限切深 + 安全裕度）作为输入，但这些结论不能由 CAM 软件或 `ChatterParams` 直接给出，必须由本模块基于**Tlusty 解析法（默认）+ LTC 神经网络（实验性）+ 兜底默认值（保守）** 三路径预测得出。

业界公认的硬约束（项目记忆已记录，与 ADR-007 / ADR-008 / ADR-009 一致）：**颤振预测不是「精确求解」问题，而是「多路径预测 + 工程师审核」问题**。因此阶段 5 不能追求「全自动颤振判定」，必须定位为**「工程师助手」**：
- 算法基于机床 FRF（Frequency Response Function）+ 切削力系数 K_s（直接取自阶段 4，不二次拟合）+ Tlusty 单自由度系统稳定性极限解析法推导保守结论
- LTC 神经网络路径为实验性，仅在 `chatter_model.pt` 存在时启用；缺失时自动回退到 Tlusty 解析法
- 兜底路径在解析法异常 + LTC 不可用时返回保守默认值（`limit_depth=1.0mm`，`confidence=0.3`），确保链路不中断
- 工程师对每个特征的预测结果逐条审核：confirmed（确认）/ rejected（拒绝，不进入 ChatterReport）/ edited（修正，提供 `edited_params` 覆盖预测值）
- 导出的 `ChatterReport` JSON 仅供阶段 6 G 代码生成参考，**实际加工必须经 CAM 软件（NX / PowerMill / PyCAM）二次校验 + 持证操作员 + 导师签字**

HRC52 材料数据可信度是阶段 5 的核心约束（项目记忆硬约束）：
- HRC52 淬火钢的 K_s = 2800 N/mm² 为工程估算值，阶段 4 已标注 `pending_calibration`
- 阶段 5 颤振预测对 K_s 极其敏感（K_s 偏差直接传递到稳定性极限），HRC52 预测置信度必须强制降低
- 6061-T6 / TC4 等材料 K_s 已校准，可使用默认置信度
- HRC52 不可使用纯文献数据，必须通过自采工业数据校准后才允许进入正式 ChatterReport

工业级配合面（H7/h6 等，0.01 mm 公差）物理上无法用手机摄影测量达到，本模块输出的颤振预测结论仅可作为「工艺理解参考」与「阶段 6 G 代码生成输入」，**不可直接作为加工依据**。

## 决策

采用 **ChatterParams 驱动 + 双路径预测 + 兜底保守** 的预测策略，结合 **ChatterPredictorAdapter 预测适配器 + ChatterPredictionPipeline 编排器 + 工程师单轮审核状态机** 作为阶段 5 的核心 pipeline。整体链路按 7 阶段推进，本 ADR 仅覆盖阶段 5（颤振预测接入 LTC）。

### 阶段 5 实现要点

1. **分层架构（5 文件清晰职责）**：
   ```
   阶段 4 ChatterParams JSON + material_id ──┐
                                              ├─→ chatter_store.py        (任务 + 状态机 + 审核存储层)
                                              │   ↓
                                              │   ChatterPredictionTask / FeatureChatterResult
                                              │   ↓
                                              ├─→ predictor_adapter.py   (双路径预测适配层)
                                              │   ↓
                                              │   路径 A: Tlusty 解析法 (compute_stability_limit，默认)
                                              │   路径 B: LTC 神经网络 (chatter_model.pt 存在时启用)
                                              │   路径 C: 兜底默认值 (limit_depth=1.0mm, confidence=0.3)
                                              │   ↓
                                              ├─→ chatter_disclaimer.py   (精度告知层，14 字段 + 8 条硬门槛)
                                              │   ↓
                                              ├─→ pipeline.py            (编排器 + 状态机 + 审核 + 导出)
                                              │   ↓
                                              │   ChatterReport JSON
                                              │   ↓
                                              └─→ routes.py              (API 路由层)
   ```

2. **三路径预测策略（优先级递减）**：
   - **路径 A：Tlusty 解析法（工程默认，`method="analytical"`）**
     - 调用 `app.simulation.chatter.compute_stability_limit()` 计算单自由度系统稳定性极限
     - 输入：机床 FRF（`stiffness_x/y/z` / `damping_ratio` / `natural_freq` / `modal_mass`）+ K_s（直接取自 `chatter_params_dict["tool"]["cutting_force_coeff"]`，不二次拟合）
     - 输出：`limit_depth_mm`（极限切深）+ `stability_margin`（安全裕度）+ `stable`（1.0/0.0）
     - 置信度：`DEFAULT_CONFIDENCE = 0.8`（已校准材料）/ `PENDING_CALIBRATION_CONFIDENCE = 0.5`（HRC52 待校准）
   - **路径 B：LTC 神经网络（实验性，`method="neural_network"`）**
     - 仅在 `chatter_model.pt` 存在时启用（`check_ltc_model_available()` 探测）
     - MC dropout 推理模式切换使用锁保护（项目记忆硬约束：防止并发推理冲突）
     - 推理路径禁止 `fit_transform`（项目记忆硬约束：防止数据泄露，preprocessors 必须用 `transform`）
     - LTC 模型不可用时自动回退到路径 A
   - **路径 C：兜底默认值（保守，`method="fallback"`）**
     - 解析法异常 + LTC 不可用时启用
     - `limit_depth_mm = 1.0mm`，`confidence = FALLBACK_CONFIDENCE = 0.3`
     - 确保链路不中断，工程师可基于兜底值审核调整

3. **ChatterPredictorAdapter 双路径适配器（`predict_feature` 签名）**：
   - 实际签名：`predict_feature(self, feature_id, feature_type, material_id, chatter_params_dict, source_cutting_params_task_id="")`
   - K_s 契约：从 `chatter_params_dict["tool"]["cutting_force_coeff"]` 直接读取，**不二次拟合**（项目记忆硬约束）
   - HRC52 检测：`material_id` 命中 `PENDING_CALIBRATION_MATERIALS` 时强制降低置信度
   - `PENDING_CALIBRATION_MATERIALS: frozenset[str] = frozenset({"steel_hrc52", "hrc52", "hrc_52", "hardened_steel_hrc52"})`
   - 置信度三档：`DEFAULT_CONFIDENCE = 0.8` → `PENDING_CALIBRATION_CONFIDENCE = 0.5` → `FALLBACK_CONFIDENCE = 0.3`
   - 安全裕度比：`SAFETY_MARGIN_RATIO = 0.8`，实际切深超过极限切深 80% 时发出警告

4. **FeatureChatterResult 数据类（24 字段，覆盖阶段 6 全部需求）**：
   - 标识字段：`feature_id` / `feature_type` / `material_id` / `source_cutting_params_task_id`
   - 工况字段：`spindle_rpm` / `axial_depth_mm` / `machine_id` / `tool_id`
   - 预测结果：`limit_depth_mm`（极限切深）/ `stable`（1.0/0.0，用 float 而非 bool）/ `stability_margin`（安全裕度）
   - 方法标记：`method`（analytical / neural_network / fallback）/ `ltc_active`（LTC 是否实际参与）
   - 置信度：`confidence`（0.0-1.0）/ `inference_time_ms`（推理耗时）
   - 材料校准：`material_calibration_status`（calibrated / pending_calibration）/ `cutting_force_coeff`（K_s 实际值）
   - 警告：`warnings`（list[str]，动态拼接）
   - 审核状态：`review_status`（pending / confirmed / rejected / edited）/ `edited_params`（工程师编辑值）/ `reviewer_id` / `review_notes` / `reviewed_at`

5. **effective_result() 契约（阶段 6 G 代码生成直接消费）**：
   - 返回 dict：`{"limit_depth_mm": float, "axial_depth_mm": float, "stable": 1.0/0.0}`
   - **`stable` 用 float（1.0/0.0）而非 bool**，与 `chatter_store.py:164` 实现一致，便于 JSON 序列化与阶段 6 数值比较
   - pending 状态：返回预测值（`limit_depth_mm` / `axial_depth_mm` / `stable`）
   - edited 状态：返回 `edited_params` 覆盖值（工程师修正后的 `limit_depth_mm` 与 `stable`）
   - 阶段 6 G 代码生成可直接 `result.effective_result()` 获取最终生效的稳定性结论

6. **状态机（单轮审核，PENDING → RUNNING → PREDICTED → REVIEWED → SUCCEEDED）**：
   ```
   PENDING ──run_pipeline──→ RUNNING ──成功──→ PREDICTED
                                  │                  │
                                  │                  ├── review_result (逐条)
                                  │                  │     │
                                  │                  │     ├── confirmed → 保留
                                  │                  │     ├── rejected → 排除
                                  │                  │     └── edited   → 合并 edited_params
                                  │                  │     │
                                  │                  │     └── 全部审核完毕 ──→ REVIEWED
                                  │                  │                              │
                                  │                  │                              └── export_chatter_report ──→ SUCCEEDED
                                  │                  │
                                  └──失败──→ FAILED ←──┘
                                  │
                                  └──取消──→ CANCELLED
   ```
   - 与阶段 4 单轮审核（PARAMS_RECOMMENDED → REVIEWED → SUCCEEDED）一致，阶段 5 采用**单轮审核**：预测结果一次性给出，工程师逐条审核后直接进入 REVIEWED，导出 ChatterReport 后转 SUCCEEDED
   - 设计权衡：颤振预测结论是数值（`limit_depth_mm` / `stable`），不存在「重新生成」的必要，工程师编辑后直接合并入 `effective_result()` 即可

7. **ChatterReport 导出契约（阶段 6 输入）**：
   - 输入：所有 `FeatureChatterResult`（取 `effective_result()`，工程师编辑值优先）
   - 输出：JSON 文件，包含每个特征的稳定性结论
   - 排除规则：`review_status="rejected"` 的特征不进入 ChatterReport
   - 状态转换：仅 REVIEWED 状态可导出，导出成功后任务转 SUCCEEDED
   - 阶段 6 G 代码生成可直接读取 ChatterReport JSON 获取每个特征的 `limit_depth_mm` 与 `stable`

8. **精度告知机制（14 字段，所有 API 响应必带 `chatter_disclaimer`）**：
   - 上游精度：`mesh_calibrated` / `chatter_params_source` / `material_id` / `material_calibration_status`（calibrated / pending_calibration）
   - 精度档位：`precision_tier` / `machine_type`
   - 预测方法：`prediction_method`（analytical / neural_network / mixed / fallback）/ `ltc_model_available`（LTC 模型是否存在）/ `ltc_active_ratio`（LTC 实际参与比例，0.0-1.0）
   - 强制审核：`requires_engineer_review` = True / `requires_cam_validation` = True
   - 阶段 6 状态：`chatter_report_ready`（是否已导出 ChatterReport）
   - 工业硬门槛：`industrial_hard_gates`（8 条，与 ADR-008 / ADR-009 一致并补充 LTC 实验性条款）
   - 动态警告：`warning_message`（拼接 mesh 未标定 / 材料 pending / LTC 不可用 / ChatterReport 未输出 / CAM 校验强制等片段）

9. **三档精度继承（不引入新档位）**：
   - `coarse`：粗加工档位，大切深 + 低精度，适用于稳定性裕度大的工况
   - `standard`：标准档位，平衡切深与精度，默认档位
   - `high`：精加工档位，小切深 + 高精度，适用于配合面加工
   - 精度档位继承链：阶段 1 image_to_3d.precision_tier → 阶段 2 → 阶段 3 → 阶段 4 → 阶段 5
   - 本模块不引入新档位，全程继承上游告知，与 ADR-007 / ADR-008 / ADR-009 完全一致

10. **条件导入 + 12-Factor 配置（与阶段 2 / 3 / 4 一致）**：
    - `routes.py` 通过 `_resolve_upstream_calibrated()` 三层 try/except ImportError 软依赖查询阶段 4 任务的 `mesh_calibrated` / `chatter_params_path` / `material_id` 字段
    - `cutting_parameters` 模块未启用时按未标定 mesh 处理，并记日志
    - 配置项支持环境变量覆盖（`LNN_CH_*` 前缀），遵循 12-Factor App 原则
    - `LNN_CH_ENABLED=false` 时模块完全关闭，`main.py` 不注册路由

11. **异步执行 + 上游软依赖追溯**：
    - `run_pipeline()` 为 async 方法（与阶段 3 / 4 一致），内部无 await 但保持 async 签名便于未来扩展并发预测
    - 上游追溯链：阶段 5 task → `source_cutting_parameters_task_id` → 阶段 4 task → `mesh_calibrated` / `chatter_params_path` / `material_id` 字段
    - 上游任务不存在 / 未 SUCCEEDED / 异常时按未标定处理，记日志不阻塞
    - 仅 SUCCEEDED 状态的阶段 4 任务才被认为是可信 ChatterParams 来源

12. **10 个 API 端点（与阶段 4 端点结构对齐）**：
    - `GET /precision_info`：查询精度档位 + LTC 模型可用性 + 工业硬门槛 + 审核流程说明（不创建任务）
    - `POST /tasks`：创建任务（校验 precision_tier / source_cutting_parameters_task_id 存在性 / chatter_params_path 存在性 / material_id 存在性 / mesh_calibrated 自动追溯）
    - `POST /tasks/{task_id}/run`：异步触发双路径预测（PENDING / FAILED 可执行）
    - `GET /tasks/{task_id}`：查询状态 + 审核进度统计（pending / confirmed / rejected / edited 计数）+ `chatter_disclaimer`
    - `GET /tasks`：列出最近任务
    - `GET /tasks/{task_id}/result`：获取预测结果列表 + `effective_result`
    - `POST /tasks/{task_id}/review`：工程师审核（action = confirmed / rejected / edited）
    - `POST /tasks/{task_id}/export`：导出 ChatterReport JSON → SUCCEEDED
    - `GET /tasks/{task_id}/chatter_report/download`：下载 JSON 文件
    - `DELETE /tasks/{task_id}`：删除任务（**SUCCEEDED 禁删**硬约束）

13. **SUCCEEDED 禁删硬约束**：
    - 设计动机：阶段 6 G 代码生成可能已引用 ChatterReport JSON，删除会导致阶段 6 任务悬空
    - 实现：`TaskStore.delete_task()` 校验状态，SUCCEEDED 直接抛 `ReviewError`
    - 与阶段 3 / 4 一致（STEP 文件 / ChatterParams 被下游引用后禁止删除）
    - `LNN_CH_ALLOW_DELETE_SUCCEEDED` 强制 False（不可通过环境变量开启，项目记忆硬约束）

14. **LTC 神经网络实验性标记**：
    - LTC 路径在 `chatter_disclaimer.warning_message` 中显式标注「LTC 神经网络为实验性，结果仅供参考」
    - `ltc_active_ratio` 字段透明告知 LTC 实际参与比例（0.0 = 全解析法 / 1.0 = 全 LTC / 0.5 = 混合）
    - 工程师可基于 `ltc_active_ratio` 决定是否需要额外校验
    - 默认 `force_analytical=False`，LTC 模型存在时自动启用；`force_analytical=True` 时强制走解析法

15. **cam_validation_required 始终 True（项目记忆硬约束）**：
    - `ChatterPredictionConfig.cam_validation_required` 强制 True，不可通过环境变量关闭
    - `__post_init__` 校验逻辑：若 `cam_validation_required=False` 强制覆盖为 True
    - ChatterReport 仅供阶段 6 G 代码生成参考，实际加工必须经 CAM 软件（NX / PowerMill / PyCAM）二次校验

## 理由

### 方案对比

#### 方案 A：纯 LTC 神经网络预测（全自动）

- 优点：理论上可学习复杂非线性稳定性边界
- 缺点：
  - **违反项目记忆硬约束**：训练领域专用小模型（CFC/LTC）在有限数据下不可行，本项目无足够颤振样本
  - LTC 模型未训练时无法预测，链路中断
  - 神经网络缺乏可解释性，工程师审核困难
  - 违反「工程师助手」定位，工业生产中颤振预测结论必须经工程师审核

#### 方案 B：Tlusty 解析法（默认）+ LTC 神经网络（实验性）+ 兜底默认值 + 工程师单轮审核（**已采用**）

- 优点：
  - Tlusty 解析法基于物理模型（FRF + K_s），可解释性强，工程可用
  - LTC 神经网络作为实验性路径，`chatter_model.pt` 存在时自动启用，缺失时回退到解析法
  - 兜底默认值确保链路不中断（解析法异常 + LTC 不可用时返回保守 `limit_depth=1.0mm`）
  - 工程师单轮审核符合颤振预测的数值特性（不需要像 STEP 那样两轮重新生成）
  - HRC52 `pending_calibration` 状态强制降低置信度（0.8 → 0.5），透明告知工程师
- 缺点：
  - Tlusty 解析法为单自由度系统简化模型，多自由度系统需后续扩展
  - LTC 路径当前无训练好的模型，仅作为架构完备性预留
  - 兜底默认值 `limit_depth=1.0mm` 过于保守，可能牺牲材料去除率

#### 方案 C：纯机器学习（历史振动数据训练）

- 优点：理论上可学习企业历史颤振数据
- 缺点：
  - 本项目为大一独立项目，无历史颤振数据可学习
  - 机器学习推荐缺乏可解释性，工程师审核困难
  - 违反「物理优先」原则，颤振稳定性极限必须基于 FRF + K_s 物理模型而非历史数据
  - 项目记忆硬约束：训练领域专用小模型（CFC/LTC）在有限数据下不可行

#### 方案 D：CAM 软件内置颤振仿真直接调用

- 优点：结论与 CAM 软件一致
- 缺点：
  - NX / PowerMill 颤振仿真为商业闭源模块，无法编程访问
  - 阶段 6 G 代码生成需要 `ChatterReport` JSON，CAM 软件不直接提供
  - 违反「不耦合商业软件」原则，桌面轻量档位无法运行

### 设计权衡

**Q1：为什么采用 Tlusty 解析法作为默认路径而非 LTC 神经网络？**
A：Tlusty 解析法基于物理模型（机床 FRF + 切削力系数 K_s），可解释性强，工程师可基于物理直觉审核预测结论。LTC 神经网络在有限数据下训练不可行（项目记忆硬约束），当前仅作为架构完备性预留，`chatter_model.pt` 不存在时自动回退到解析法。工程优先于学术价值。

**Q2：为什么 K_s → cutting_force_coeff 直接传递而非重新拟合？**
A：阶段 4 的 `MaterialParams.specific_cutting_force`（K_s）已基于材料物理属性校准（6061-T6 ≈ 800 / TC4 ≈ 1600 / HRC52 ≈ 2800 N/mm²），与 Tlusty 解析法需要的「单位切削力」物理意义完全一致。直接传递避免二次拟合引入误差（项目记忆硬约束：K_s → cutting_force_coeff 直接传递，不二次拟合）。HRC52 的 `pending_calibration` 状态通过 `material_calibration_status` 字段传递，由本模块决定如何降低置信度。

**Q3：为什么 HRC52 置信度从 0.8 降至 0.5 而非直接拒绝预测？**
A：HRC52 是项目自采工业数据的核心组成，完全拒绝预测会阻断阶段 6 G 代码生成链路。采用「降低置信度 + 透明告知」策略：置信度从 `DEFAULT_CONFIDENCE=0.8` 降至 `PENDING_CALIBRATION_CONFIDENCE=0.5`，`chatter_disclaimer.warning_message` 显式标注「HRC52 待校准，预测置信度已降低」，工程师可基于置信度决定是否需要额外校验。HRC52 数据待自采工业数据校准后，更新 `calibration_status` 为 `calibrated` 即可恢复默认置信度。

**Q4：为什么 `stable` 用 float（1.0/0.0）而非 bool？**
A：与 `chatter_store.py` 实现一致，便于 JSON 序列化（JSON 无 bool 类型，序列化为 true/false 后阶段 6 数值比较需额外转换）与阶段 6 G 代码生成的数值比较（`if stable > 0.5:`）。`effective_result()` 返回 `{"stable": 1.0 if self.stable else 0.0}`，edited_params 中 stable 也用 0/1 表示，保持类型一致。

**Q5：为什么采用单轮审核而非两轮审核？**
A：颤振预测结论是数值（`limit_depth_mm` / `stable`），工程师编辑后直接合并入 `effective_result()`，导出 ChatterReport 时取 `effective_result()` 即可，不需要「重新生成」环节。与阶段 4 单轮审核一致，比阶段 3 两轮审核（STEP_GENERATED + REVIEWED）更简洁。

**Q6：为什么 SUCCEEDED 状态禁止删除？**
A：阶段 6 G 代码生成可能已引用 ChatterReport JSON 路径，删除会导致阶段 6 任务悬空。与阶段 3 STEP 文件 / 阶段 4 ChatterParams 被下游引用后禁止删除的设计一致。`LNN_CH_ALLOW_DELETE_SUCCEEDED` 强制 False（项目记忆硬约束，不可通过环境变量开启）。

**Q7：为什么 LTC 神经网络路径标记为实验性？**
A：项目记忆硬约束明确「训练领域专用小模型（CFC/LTC）在有限数据下不可行」，当前 LTC 路径仅作为架构完备性预留，无训练好的模型。`chatter_disclaimer.warning_message` 显式标注「LTC 神经网络为实验性，结果仅供参考」，`ltc_active_ratio` 透明告知 LTC 实际参与比例。默认 `force_analytical=False`，LTC 模型存在时自动启用；`force_analytical=True` 时强制走解析法（工程优先）。

**Q8：为什么 `cam_validation_required` 强制 True 不可关闭？**
A：项目记忆硬约束明确「生成的 G 代码必须通过现有 CAM 软件（NX/PowerMill/PyCAM）二次校验后才允许上机床」。ChatterReport 仅供阶段 6 G 代码生成参考，实际加工必须经 CAM 软件二次校验 + 持证操作员 + 导师签字。`__post_init__` 校验逻辑强制覆盖为 True，不可通过环境变量关闭。

**Q9：为什么兜底默认值 `limit_depth=1.0mm` 而非 0？**
A：`limit_depth=0` 会导致阶段 6 G 代码生成无法生成任何刀轨（切深必须大于 0）。`limit_depth=1.0mm` 是保守非零值，确保链路不中断，工程师可基于兜底值审核调整。`FALLBACK_CONFIDENCE=0.3` 透明告知工程师此为兜底值，需要额外校验。

## 后果

### 正面后果

1. **三路径预测鲁棒性强**：Tlusty 解析法（默认）+ LTC 神经网络（实验性）+ 兜底默认值（保守），任一路径异常不阻断链路
2. **HRC52 置信度透明降低**：`pending_calibration` 状态强制置信度从 0.8 降至 0.5，工程师可基于置信度决策
3. **阶段 6 契约清晰**：`effective_result()` 输出 3 键 dict（`limit_depth_mm` / `axial_depth_mm` / `stable`），阶段 6 G 代码生成可直接消费
4. **精度档位全程继承**：coarse / standard / high 三档与阶段 1 / 2 / 3 / 4 一致，不引入新档位
5. **工程师审核流程清晰**：单轮审核（PENDING → RUNNING → PREDICTED → REVIEWED → SUCCEEDED）与阶段 4 一致
6. **API 端点与阶段 4 对齐**：10 个端点结构与 `cutting_parameters` 一致，前端可复用组件
7. **条件导入 + 12-Factor**：模块可独立启停，`LNN_CH_ENABLED=false` 时不影响主程序
8. **LTC 实验性透明告知**：`ltc_active_ratio` + `warning_message` 显式标注 LTC 实际参与比例与实验性状态
9. **K_s 直接传递避免误差**：`cutting_force_coeff` 直接取自阶段 4 `MaterialParams.specific_cutting_force`，不二次拟合
10. **SUCCEEDED 禁删保护下游**：阶段 6 G 代码生成引用 ChatterReport 后，任务禁止删除

### 负面后果

1. **HRC52 数据待校准**：K_s = 2800 N/mm² 为工程估算值，置信度强制降至 0.5，需后续自采工业数据校准后才能恢复默认置信度
2. **LTC 路径当前无模型**：`chatter_model.pt` 不存在，LTC 路径仅作为架构完备性预留，当前实际全走解析法
3. **Tlusty 单自由度简化模型**：多自由度系统颤振需后续扩展（当前仅支持单自由度 FRF）
4. **兜底默认值过于保守**：`limit_depth=1.0mm` 可能牺牲材料去除率，工程师需手动 edit
5. **不支持 5 轴加工颤振预测**：当前仅支持 3 轴铣削颤振预测，5 轴加工需阶段 6 / 7 扩展
6. **LTC MC dropout 锁保护增加开销**：并发推理时锁竞争可能影响吞吐量，但保证推理一致性

- 项目记忆硬约束：
  - 系统定位「工程师助手」，非「全自动颤振预测器」
  - HRC52 不可使用纯文献数据，必须基于自采工业数据校准
  - K_s → cutting_force_coeff 直接传递，不二次拟合
  - ChatterReport 仅供阶段 6 G 代码生成参考，实际加工必须经 CAM 软件（NX / PowerMill / PyCAM）二次校验
  - 工业级配合面（H7/h6 等，0.01mm 公差）物理上无法用手机摄影测量达到
  - CNC 机床操作需持证操作员 + 导师签字 + 保险
  - SUCCEEDED 状态禁止删除（阶段 6 G 代码生成可能已引用 ChatterReport）
  - `cam_validation_required` 始终 True（不可关闭）
  - MC dropout 模式切换使用锁保护；推理路径禁止 fit_transform
  - 训练领域专用小模型（CFC/LTC）在有限数据下不可行，优先开源 LLM 本地部署 + 架构完备性
- 颤振稳定性理论：
  - Tlusty 解析法：单自由度系统稳定性极限，基于 FRF + K_s 推导
  - LTC（Liquid Time-Constant）网络：实验性路径，`chatter_model.pt` 不存在时自动回退到解析法
  - 稳定性叶瓣图（Stability Lobe Diagram）：主轴转速 vs 极限切深的稳定性边界
- 切削力系数参考（与 ADR-009 一致）：
  - TC4 钛合金 K_s ≈ 1600 N/mm²（低导热性，切削温度高）
  - 6061-T6 铝合金 K_s ≈ 800 N/mm²（易切削，切削力小）
  - HRC52 淬火钢 K_s ≈ 2800 N/mm²（pending_calibration，待自采校准）
- 置信度三档策略：
  - `DEFAULT_CONFIDENCE = 0.8`：已校准材料（6061-T6 / TC4）
  - `PENDING_CALIBRATION_CONFIDENCE = 0.5`：HRC52 待校准材料
  - `FALLBACK_CONFIDENCE = 0.3`：兜底默认值路径
- 安全裕度：`SAFETY_MARGIN_RATIO = 0.8`，实际切深超过极限切深 80% 时发出警告

# ADR-010: 工作流模板市场

**日期**: 2026-07-14
**状态**: 已接受
**决策者**: 灵境制造团队

---

## 背景

阶段 5（CLI + SDK + HTTP API 契约）已完成，软件可被脚本/notebook 调用。阶段 6 目标是"生态内容飞轮"——让用户能分享、复用工作流模板，并在项目级别同步数据集/模型/配置/工作流。

当前现状：

1. **WorkflowSpec 契约稳定**（`app/contracts/task.py`），6 节点线性 DAG 已在 `plugins/data_flywheel/templates/model_iteration_pipeline.yaml` 落地，是事实上的工作流模板雏形。
2. **扩展点已预留**：`BUILTIN_EXTENSION_POINTS.WORKFLOW_TEMPLATE = "core.workflow_template"` 早在 ADR-005 阶段就预留，但当前没有任何插件注册到这个扩展点。
3. **市场机制已有参考**：
   - `app/plugins/skill_marketplace.py` 提供完整的 publish/download/rate/list/search/unpublish 实现（listings.json + .skz 包格式 + 评分计数 + 线程安全锁）
   - `app/templates/template_branching.py` 提供 5 类分支机制（main/industry/material/project/experiment）
   - `app/api/v1/template_market.py` 已有 publish/subscribe/export/import/sync/trending/metrics 端点
4. **持久化混合策略**：SQLite（workflow_runs、template_branches.db）+ JSON 文件（listings.json）+ 内存注册表（PluginRegistry）。
5. **缺失**：没有 `workflow_templates` SQLAlchemy 表；`PluginManifest` 没有声明模板贡献的字段；`/api/v1/plugins/marketplace` 是空占位。

p6-1 需要把 `core.workflow_template` 扩展点真正落地，让用户能发布、发现、订阅、实例化工作流模板。

## 决策

采用"契约层 + 加载器 + 服务层 + 路由层 + 数据库 + 前端"六层落地工作流模板市场，**复用现有 WorkflowSpec 与 PluginManifest 契约，不修改 WorkflowSpec 本身**：

1. **新增契约** `app/contracts/workflow_template.py`：定义 `WorkflowTemplateManifest` dataclass（模板元数据 + 嵌入 WorkflowSpec + 输入参数 schema + 市场统计字段）。
2. **扩展 PluginManifest**：新增可选字段 `workflow_templates: list[str]`（YAML 文件相对路径），让插件声明贡献的模板。`manifest_loader.py` 同步更新 schema 校验。
3. **新增加载器** `app/plugins/workflow_template_loader.py`：参考 `manifest_loader.py` 模式，加载 `templates/*.yaml` → `WorkflowTemplateManifest`，含 schema 校验。
4. **新增数据库表** `app/database/models/workflow_template.py`：`workflow_templates`（模板主表）+ `workflow_template_versions`（多版本表，复合唯一约束 `(template_id, version)`）。
5. **新增服务层** `app/services/workflow_template_service.py`：参考 `skill_marketplace.py` 实现 publish/list/get/search/instantiate/export/import/rate/unpublish，线程安全（threading.Lock），SQLite + JSON 双持久化。
6. **新增路由** `app/api/v1/workflow_templates.py`：REST 端点 prefix `/api/v1/workflow_templates`。
7. **前端契约** `src/contracts/workflow_template.ts`：TS 类型与后端 dataclass 对齐。
8. **前端 Store** `src/stores/workflowTemplate.ts`：Pinia store（fetchTemplates/publishTemplate/instantiateTemplate/searchTemplates/rateTemplate）。

## 理由

### 考虑的方案

1. **方案 A: 复用 `template_market.py` 现有路由扩展工作流模板**
   - 优点：路由已存在，开发量最小
   - 缺点：`template_market.py` 当前服务于参数模板分支系统（`template_branching.py`），与 WorkflowSpec DAG 结构耦合度低；强行扩展会让路由语义混淆；现有 `/api/v1/template_market` 端点语义是"参数模板"，不是"工作流模板"

2. **方案 B: 新建独立的 `workflow_templates` 路由 + 契约 + 服务层**（**已选**）
   - 优点：语义清晰（工作流模板 ≠ 参数模板）；可独立演进；与 WorkflowSpec 契约直接对齐；前端可独立设计模板市场 UI；与阶段 7 可解释性可视化天然衔接（模板实例化 → 工作流运行 → LTC 隐状态可视化）
   - 缺点：代码量略大（新增 1 个契约 + 1 个加载器 + 1 个服务 + 1 个路由 + 2 张表 + 前端契约/store）

3. **方案 C: 把工作流模板作为插件子能力，不独立市场**
   - 优点：改动量最小，仅扩展 `PluginManifest.workflow_templates` 字段
   - 缺点：模板无法独立发布/订阅/评分；用户必须安装整个插件才能用模板；无法支持"无插件纯模板"场景（如用户手写 YAML 分享）；违背"生态内容飞轮"目标

**选择方案 B** 的关键理由：
- 阶段 6 目标是"生态内容飞轮"，模板必须能独立流转（发布/订阅/评分/导出/导入），方案 A/C 都无法满足
- `template_market.py` 的语义是参数模板分支，强行扩展会造成路由层语义污染
- 方案 B 与现有 `skill_marketplace.py` 模式高度一致，可复用 90% 的市场机制代码
- 独立路由便于后续阶段 7 可解释性可视化接入（模板实例化 → 运行 → 可视化）

## 后果

### 积极影响
- `core.workflow_template` 扩展点真正落地，插件可通过 `IExtensionRegistry.register` 贡献模板
- 用户可独立发布/订阅/评分工作流模板，无需安装整个插件
- 模板多版本管理（semver），支持 `instantiate` 一键实例化为工作流运行
- 与阶段 5 SDK 对齐：`lomo workflow run --from-template <template_id>@<version>` 可在 CLI/SDK 层后续扩展
- 为阶段 6 p6-2（项目级 Git 同步）提供基础——模板可作为项目级配置的一部分

### 消极影响
- 新增 2 张数据库表，需配套 Alembic 迁移脚本
- 前端需新增模板市场 UI（本 ADR 仅交付契约/store，UI 在 p6-3/p6-4 阶段补齐）
- `PluginManifest` 契约新增可选字段，向后兼容（旧 plugin.yaml 不受影响），但 CI 需更新 schema 校验

### 技术影响
- 数据库：新增 `workflow_templates` + `workflow_template_versions` 表，使用 JSONB(JSON) 双兼容模式存储 `spec_json` / `inputs_schema` / `parameters`
- 持久化策略：模板元数据存 SQLite，模板 spec 存 SQLite JSONB（不使用 listings.json 文件模式，因为模板 spec 较大且需要事务一致性）
- 线程安全：服务层使用 `threading.Lock` 保护发布/评分等写操作（参考 `skill_marketplace.py`）
- 契约层：`WorkflowTemplateManifest` 是 `@dataclass(frozen=True)`，不可变，与 `PluginManifest` 风格一致

### 业务影响
- 用户可在模板市场浏览/搜索工作流模板（按 category/tags/author 过滤）
- 模板评分机制驱动优质内容浮现（参考技能市场的 avg_rating + rating_count + downloads 三维度）
- 模板导出/导入（`.lomo.yaml` 格式）支持离线分享，为 p6-4 项目导入导出铺路

## 修复内容详解

### 1. 异常分级体系 (P0)

**设计目标**: 为所有业务异常提供分级处理机制

**核心特性**:
- **ErrorLevel 枚举**: `INFO`, `WARNING`, `ERROR`, `CRITICAL`
- **AppException 基类**: 支持 `retryable`, `hint`, `detail`
- **标准化响应格式**: 所有异常统一 JSON 格式

**新增异常类分类**:

#### A. AI/LLM 异常 (6xxx)
```python
class LLMException(Base):              # 6001 - 通用 LLM 异常
class LLMProviderException(Base):      # 6010 - 提供商服务异常
class LLMTimeoutException(Base):       # 6011 - 超时异常
class LLMRateLimitException(Base):     # 6012 - 限流异常
class LLMAuthException(Base):          # 6013 - 认证失败
```

#### B. CAD 异常 (7xxx)
```python
class CadException(Base):              # 7001 - 通用 CAD 异常
class CadParserException(Base):        # 7010 - 解析失败
class CadFileNotFoundError(Base):      # 7011 - 文件未找到
```

#### C. NC 代码异常 (8xxx)
```python
class NCCodeException(Base):           # 8001 - 通用 NC 异常
class NCCodeGenerationException(Base): # 8010 - 生成失败
class PostprocessorException(Base):    # 8011 - 后处理器错误
class NCCodeValidationException(Base): # 8012 - 验证失败
```

#### D. 熔断器异常 (9xxx)
```python
class CircuitBreakerOpenException(Base):    # 9001 - 熔断器打开
class CircuitBreakerHalfOpenException(Base): # 9002 - 半开探测
```

**错误响应示例**:
```json

  "level": "warning",
  "hint": "请检查网络状态或增加超时时间",
  "retryable": true,

```

### 2. 熔断器模式 (P0)

**设计目标**: 防止级联故障，提供自动降级能力

**核心组件**:
- `CircuitBreaker`: 熔断器实现
- `CircuitBreakerRegistry`: 单例注册中心
- `CircuitBreakerConfig`: 配置类

**状态流转图**:
```
CLOSED ──(失败>=threshold)──→ OPEN ──(超时)──→ HALF_OPEN
  ↑                              ↓                    ↓
  └────(成功>=threshold)←──────└─────(成功)─────┘
                                   │
                                   └──(失败)──→ OPEN
```

**配置参数**:
```python
config = CircuitBreakerConfig(
    failure_threshold=5,          # 连续失败 5 次熔断
    recovery_timeout=30,          # 30 秒后尝试恢复
    half_open_max_calls=3,        # 半开状态最多 3 次探测
    success_threshold=2,          # 2 次成功探测后完全恢复
)
```

**使用方式**:
```python
# 创建熔断器
registry = CircuitBreakerRegistry()
breaker = registry.get_or_create(
    "llm_provider_ollama",
    config=CircuitBreakerConfig(
        failure_threshold=5,
        recovery_timeout=30
    )
)

# 执行受保护调用
result = breaker.execute(lambda: call_ai_service())
```

### 3. 全局异常中间件 (P2)

**设计目标**: 统一错误响应格式，提供降级策略

**中间件**:
- `GlobalExceptionMiddleware`: 统一异常捕获
- `RequestLoggingMiddleware`: 请求/响应日志

**异常处理策略**:
```python
AppException → 返回标准错误 JSON (code/message/level/hint)
CircuitBreakerOpenException → 返回 429 Too Many Requests
UnexpectedException → 生产环境脱敏，开发环境返回 stacktrace
```

**自动注册**:
```python
# start_server.py
from app.core.middleware import setup_exception_handlers

app = FastAPI()
app = setup_exception_handlers(app)  # 自动注册所有中间件
```

## 使用指南

### 在 API 中使用新异常

```python
from app.core.exceptions import LLMTimeoutException, LLMProviderException

async def call_llm(provider: str, prompt: str):
    """调用 LLM 示例"""
    try:
        response = await llm_provider.provider.chat(prompt)
        return response
    except asyncio.TimeoutError as e:
        # 捕获超时，提升到特定异常
        raise LLMTimeoutException(
            provider=provider,
            timeout_sec=30
        ) from e
    except aiohttp.ClientConnectionError as e:
        raise LLMProviderException(
            provider=provider,
            message=str(e)
        ) from e
```

### 在服务中应用熔断器

```python
from app.core.circuit_breaker import CircuitBreakerConfig, CircuitBreakerRegistry

registry = CircuitBreakerRegistry()
breaker = registry.get_or_create(
    name="llm_provider",
    config=CircuitBreakerConfig(
        failure_threshold=5,
        recovery_timeout=30,
    )
)

@app.post("/api/ai/chat")
async def ai_chat(request: ChatRequest):
    try:
        # 受保护调用
        result = await breaker.execute(
            lambda: llm_provider.chat(request.prompt)
        )
        return result
    except CircuitBreakerOpenException:
        # 降级：返回缓存结果或默认响应
        return {"message": "服务繁忙，请稍后重试"}
```

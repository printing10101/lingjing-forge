# 04. 后端核心模块

> 后端以 FastAPI 为核心，主入口在 `python/app/main.py`。

## 4.1 应用入口 `app/main.py`

### 4.1.1 创建应用
```python
app = FastAPI(
    title="灵境制造 API",
    version="2.5.0",
    description="Lingjing Manufacturing - NC Machining AI Platform",
    docs_url="/api/docs",
    redoc_url="/api/redoc",
    openapi_url="/api/openapi.json",
)
```

### 4.1.2 启动事件 `startup_event`
顺序：
1. **CORS 安全门** — `enforce_startup_security()`：失败则 `sys.exit(1)`
2. **优雅关闭处理器** — `shutdown_handler.setup()`
3. **环形日志** — `await ring_log.start()`
4. **Alembic 自动迁移** — `command.upgrade(alembic_cfg, "head")`，失败抛错
5. **数据库初始化** — `await init_db()`
6. **Redis 初始化** — `await get_redis()`
7. **任务管理器** — `AsyncTaskManager().initialize(max_concurrent=...)`
8. **启动事件日志** — `ring_log.append("system_event", ...)`

### 4.1.3 关闭事件 `shutdown_event`
逆序关闭：日志、任务管理器、Redis、DB；并向 SSE 发送 shutdown 事件。

### 4.1.4 中间件注册顺序（从外到内）
```
RequestIdMiddleware           # 生成 X-Request-ID
SecurityHeadersMiddleware    # 纯 ASGI 安全头
IdleAutoShutdownMiddleware    # 空闲自动休眠（BaseHTTPMiddleware）
CORSMiddleware                # CORS（启动时已校验）
MetricsMiddleware             # 性能指标（BaseHTTPMiddleware）
UnifiedAuthMiddleware         # 统一鉴权（LNN+JWT+Agent）
```

### 4.1.5 限流
- 默认 100 req/min/IP
- 通过 `app.state.limiter` 暴露
- 端点级覆盖：`@limiter.limit("60/minute")`

## 4.2 全局配置 `app/config.py`

### 4.2.1 设计原则
- 12-Factor：配置走环境变量，代码中仅保留开发默认值
- 命名约定：`LNN_<SECTION>_<KEY>`（如 `LNN_SIM_VOXEL_SIZE` → `SimulationConfig.voxel_size`）

### 4.2.2 配置分组
| 配置类 | 说明 |
|--------|------|
| `ServerConfig` | HTTP 服务器绑定 |
| `AIConfig` | AI 推理/训练 |
| `SimulationConfig` | 数控仿真参数 |
| `DatabaseConfig` | 数据库路径 |
| `StorageConfig` | 文件存储路径 |
| `SecurityConfig` | 鉴权、限流、CORS |
| `PathsConfig` | 项目路径约定 |
| `TaskSystemConfig` | 异步任务并发数 |
| `LoggingConfig` | 日志轮转 |
| `ProcessPlanningConfig` | 工艺规划阈值 |
| `TokenConfig` | LNN 认证令牌管理 |
| `AppConfig` | 顶层聚合 |

### 4.2.3 令牌加载优先级
1. `LNN_TOKEN` 环境变量（推荐生产）
2. `.lnn_token` 文件（开发）
3. 自动生成 UUID

## 4.3 核心工具模块 `app/core/`

| 文件 | 职责 |
|------|------|
| `dependencies.py` | FastAPI Depends 工厂 |
| `error_taxonomy.py` | 错误分类与编码 |
| `exceptions.py` | 自定义异常类 |
| `log_sanitizer.py` | 日志脱敏（敏感字段） |
| `logging_config.py` | 统一日志格式 + 轮转 |
| `request_id.py` | RequestId 中间件 + 上下文变量 |
| `response.py` | 统一响应体 `success()` / `error()` / `ErrorCode` |

### 统一响应
```python
return success(data=..., message="OK")
return error(code=ErrorCode.NOT_FOUND, message="...")
```
标准字段：`code / message / data / request_id / detail?`。

## 4.4 中间件

### 4.4.1 `app/middleware/cors_config.py`
- `cors_settings`：读取环境变量
- `enforce_startup_security()`：启动强校验
- `validate_cors_config()`：运行时配置合规
- `CorsConfigError`：校验失败异常
- 规则：拒绝通配符 `*` 与 `allow_credentials=True` 同时出现

### 4.4.2 `app/middleware/rate_limiter.py`
- 基于 `slowapi.Limiter`
- 端点装饰：`@limiter.limit("60/minute")`
- 全局异常处理：`rate_limit_handler`

### 4.4.3 `app/auth/security_headers_asgi.py`
- 纯 ASGI，**不缓冲请求体**
- 设置 CSP / HSTS / X-Frame-Options / X-Content-Type-Options / Referrer-Policy

### 4.4.4 `app/sidecar/sidecar_lifecycle.py`
- `IdleAutoShutdownMiddleware` — 空闲超时自动退出
- `GracefulShutdownHandler` — 优雅关闭处理器（信号 + 状态文件）

## 4.5 异常处理
```python
register_exception_handlers(app)
```
注册全局异常处理，统一响应格式 + request_id + 错误码。

## 4.6 监控与可观测性

### 4.6.1 指标
- `app/utils/utils.py:get_metrics_collector()` 提供指标收集
- `/api/metrics` Prometheus 文本格式导出

### 4.6.2 环形日志
- `app/utils/ring_buffer.py:get_ring_log_buffer()`
- 支持多缓冲区（`BUFFER_TYPES`）
- 端点：
  - `GET /api/v1/logs/stats`
  - `GET /api/v1/logs/{buffer_type}?since=&until=&level=&limit=&offset=`

### 4.6.3 审计日志
- `app/audit/audit_log.py` — `AuditLog` 类
- 记录用户决策（`UserDecision`）、AI 模块调用（`AIModule`）、操作状态（`OperationStatus`）
- 落盘：`logs/audit/audit_log.jsonl`

### 4.6.4 健康检查
- `app/api/v1/health.py`
- `GET /api/health` 主检查（Redis / DB / 任务系统）
- `GET /api/health/ping` 轻量存活（Docker HEALTHCHECK 使用）
- 公开端点，不需鉴权

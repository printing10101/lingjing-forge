# 11. 部署与运行

## 11.1 本地开发

### 11.1.1 前置依赖
- Node.js 20+
- pnpm 8+
- Python 3.10+
- PostgreSQL 15+（可选）
- Redis 7+（可选）
- Rust（仅 Tauri 构建需要）

### 11.1.2 启动步骤
```bash
# 1. 后端
cd python
python -m venv .venv
.\.venv\Scripts\activate           # Windows
# source .venv/bin/activate         # Linux/macOS
pip install -e ".[dev]"
uvicorn app.main:app --reload --port 8765

# 2. 前端（新终端）
cd ..
pnpm install
pnpm dev                            # http://localhost:1420

# 3. 桌面（可选）
pnpm tauri dev
```

## 11.2 Docker Compose 部署

### 11.2.1 Profile
| Profile | 启用服务 |
|---------|---------|
| `api` | `lnn-api` |
| `monitoring` | `prometheus`、`grafana`、`pushgateway` |
| `full` | 全部 |

### 11.2.2 启动
```bash
docker compose --profile full up -d        # 完整栈
docker compose --profile api up -d         # 仅 API
docker compose --profile monitoring up -d  # 仅监控
docker compose logs -f lnn-api
docker compose down
```

### 11.2.3 关键服务
- `lnn-api` — FastAPI 主服务（8765）
- `lnn-redis` — Redis 7（6379）
- `lnn-postgres` — PostgreSQL 15（5432）
- `lnn-network` — 内网 bridge
- `prometheus` — Prometheus（9090）
- `grafana` — Grafana（3000）
- `pushgateway` — Push Gateway（9091）

## 11.3 健康检查

### 11.3.1 端点
- `GET /api/health` — 深度（Redis / DB / 任务系统）
- `GET /api/health/ping` — 轻量存活

### 11.3.2 Docker HEALTHCHECK
Dockerfile 中指向 `/api/health/ping`。

## 11.4 Tauri 桌面构建

### 11.4.1 前端构建
```bash
pnpm build    # 产物在 dist/
```

### 11.4.2 桌面打包
```bash
pnpm tauri build
# 产物在 src-tauri/target/release/bundle/
```

### 11.4.3 Sidecar
- `src-tauri/binaries/` 存放 Python 后端的可执行打包
- 启动时主进程拉起 Sidecar
- 停止时发送 SIGTERM，触发 GracefulShutdownHandler

## 11.5 Prometheus / Grafana

### 11.5.1 启动监控
```bash
docker compose --profile monitoring up -d
```
- Prometheus: http://localhost:9090
- Grafana: http://localhost:3000（默认 admin/admin）

### 11.5.2 告警规则
`deploy/prometheus/alert_rules.yml`，关键告警：
- `APIErrorRateHigh`（5xx 比例 > 5%）
- `LNNInferenceLatencyHigh`（P95 > 500ms）
- `LNNTrainingGPUUsageHigh`（> 90%）
- `TaskQueueBacklog`（积压 > 100）
- `RedisDown` / `PostgresDown`
- `IdleAutoShutdownWarning`

### 11.5.3 Push Gateway
容器内的短期批处理任务（训练）通过 pushgateway 上报指标。

## 11.7 性能与调优

### 11.7.1 后端
- Uvicorn workers 数：`WEB_CONCURRENCY`（默认 1）
- AsyncTaskManager `max_concurrent`：根据 CPU/GPU 调整
- 模型缓存：`model_cache.LRU` + 显存感知
- 慢 SQL：定位 `request_id` 关联的 `pg_stat_activity`

### 11.7.2 前端
- Vite 预构建
- 路由懒加载
- Three.js 按需加载
- Pinia 持久化：仅必要字段
- Axios 拦截器：避免重复请求

### 11.7.3 AI 推理
- 量化：动态量化（CPU）/ 静态量化（GPU）
- 批处理：`batch_inference`
- 模型预热：启动时加载常用模型
- 设备自适应：`device_manager`

## 11.8 故障排查

| 症状 | 排查路径 |
|------|---------|
| 启动失败 "CORS configuration failed" | 检查 `LNN_CORS_ALLOW_ORIGINS` 与 `allow_credentials` 配置 |
| 启动失败 "alembic upgrade failed" | 检查数据库连接 + 迁移脚本版本 |
| 任务卡在 PENDING | Redis 是否可达 / AsyncTaskManager 是否初始化 |
| 训练 OOM | `device_manager.get_optimal_batch_size` 调小 |
| 401 Unauthorized | `.lnn_token` 是否存在 / JWT 是否过期 / 撤销列表 |
| 429 Too Many Requests | 限流触发，调高或加白名单 |
| 桌面模式 Sidecar 启动失败 | 查看 `src-tauri/binaries/` + sidecar.json |
| LNN 路由错误率升高 | 查看 `app.state.routing_stats` + 路由模型版本 |

## 11.10 版本升级

```bash
git pull
docker compose build --pull
docker compose --profile full up -d
```

迁移会自动执行（`alembic upgrade head`），需保证兼容旧数据。

回滚：
```bash
docker compose down
git checkout <previous-tag>
docker compose build
docker compose --profile full up -d
```

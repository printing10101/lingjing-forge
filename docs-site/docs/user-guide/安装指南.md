# 安装指南

> 本文档说明如何在不同操作系统上完成灵境制造 v2.7.0 的安装部署，包含环境要求、一键安装脚本、桌面端安装包、容器部署、服务管理命令与安装验证方法。
>
> 最后核对：2026-08-03（与代码 `VERSION` 文件、根 `README.md`、`deploy/install.sh`、`Dockerfile` 保持一致）。

## 1. 环境要求

### 1.1 硬件最低配置

| 组件 | 最低配置 | 推荐配置 |
|------|----------|----------|
| CPU | 4 核 x86_64 | 8 核 x86_64，支持 AVX2 |
| 内存 | 8 GB RAM | 16 GB RAM（启用 AI 推理时建议 32 GB） |
| GPU | 可选（CPU 推理即可运行） | NVIDIA GPU，CUDA 11.8+，显存 ≥ 6 GB（启用 GPU 推理加速时） |
| 硬盘 | 10 GB 可用空间 | SSD 50 GB 可用空间（用于模型缓存与项目数据） |
| 网络 | 仅离线运行时无需外网 | 首次部署需要外网拉取模型权重与依赖 |

### 1.2 软件依赖

| 依赖 | 版本要求 | 说明 |
|------|----------|------|
| 操作系统 | Windows 10/11、Ubuntu 20.04+、macOS 12+、Debian 11+、CentOS 8+ | 详见 1.3 兼容性列表 |
| Python | **3.12**（服务端一键脚本会自动用 uv 安装，无需手动预装） | 桌面端内置 Python 运行时，无需系统 Python |
| Node.js | 18.x / 20.x LTS | 仅在需要前端源码构建时需要 |
| pnpm | 8.x | 前端包管理 |
| Docker | 24.0+ | 可选，容器化部署时需要 |
| Redis | 6.0+ | 可选，用于任务队列与限流计数（单机模式可使用内置内存实现） |
| 浏览器 | Chrome 100+ / Edge 100+ / Firefox 100+ | 访问 Web 端 |
| Tauri Runtime | 2.0+ | 仅使用桌面端时需要（已随安装包自带） |

> 说明：早期文档声称「暂不支持 Python 3.12」，该信息已过时。v2.7.0 生产代码基于 Python 3.12（见 `Dockerfile` 的 `python:3.12-slim`），服务端一键脚本也会自动安装 Python 3.12，请直接使用 3.12。

### 1.3 操作系统兼容性

| 操作系统 | 状态 | 备注 |
|----------|------|------|
| Windows 11 (x86_64) | 完全支持 | 桌面端与 Web 端均支持 |
| Windows 10 21H2+ (x86_64) | 完全支持 | 桌面端与 Web 端均支持 |
| Ubuntu 22.04 LTS | 完全支持 | 推荐生产环境 |
| Ubuntu 20.04 LTS | 完全支持 | |
| Debian 11 (Bullseye) | 支持 | 需手动安装 libgomp1 |
| CentOS Stream 8 / Rocky Linux 8 | 社区支持 | 需启用 EPEL 仓库 |
| macOS 13 Ventura (Apple Silicon) | 实验性 | 部分 AI 模型未提供 MPS 后端 |
| macOS 12 Monterey (Intel) | 支持 | |
| Windows Server 2019 / 2022 | 支持 | 仅推荐服务模式 |
| Alpine Linux 3.18+ | 不支持 | musl libc 与 Rust 仿真引擎存在兼容问题 |

> 标记 的系统未在 CI 中覆盖，可能存在边缘问题，建议优先在 标记的系统上生产部署。

### 1.4 硬件档位配置

灵境制造支持根据用户硬件条件选择不同的能力子集，避免老旧硬件无法启动 Ollama 或内存不足导致应用卡死。档位通过环境变量 `LNN_HARDWARE_TIER` 控制，可在 `.env` 文件中设置。

| 档位 | 硬件要求 | 启用的能力 | 跳过的能力 |
|------|----------|------------|------------|
| `minimal` | 4 核 CPU / 8 GB RAM / 无 GPU | 规则引擎 + 云端 API + CAM 核心功能 | Ollama 本地 LLM、本地模型训练 |
| `standard`（默认） | 8 核 CPU / 16 GB RAM / 可选 GPU | 上述 + 本地小模型（7B 量化版） | 大模型推理（14B+） |
| `high` | 8 核+ CPU / 32 GB RAM / NVIDIA GPU ≥ 6 GB | 上述 + 本地 7B-14B 模型 | GPU 训练 |
| `ultra` | 工作站级（CPU 16 核+ / 64 GB RAM / GPU ≥ 12 GB） | 全部能力，含 14B+ 模型 + GPU 训练 | 无 |

#### 1.4.1 轻量模式（Lightweight Mode）

轻量模式是 `minimal` 档位的隐式行为，也可独立启用：

- 跳过 Ollama 启动探测（即使已安装 Ollama 也不加载）
- 强制使用云端 API 或规则引擎
- 限制 AI 并发数为 1，降低内存占用

启用方式：

```bash
# .env 文件
LNN_LIGHTWEIGHT_MODE=true
LNN_SKIP_OLLAMA=true        # 可选：显式跳过 ollama 模块导入
LNN_MAX_CONCURRENT_AI=1     # 可选：显式限制并发数
```

#### 1.4.2 档位选择建议

| 用户场景 | 推荐档位 | 理由 |
|----------|----------|------|
| 仅使用 CAM 核心功能（工艺规划、刀具路径、碰撞检测） | `minimal` | 无需 AI 推理，资源占用最低 |
| 偶尔使用 AI 预测（磨损预测、稳定性图） | `standard` | 默认平衡，CPU 推理可接受延迟 |
| 频繁使用 AI 预测 + 本地知识库问答 | `high` | GPU 加速显著降低推理延迟 |
| 研究 LTC 神经网络训练 + 大模型微调 | `ultra` | GPU 训练必需 |

> **注意**：更改档位需重启后端进程才能生效。

## 2. 选择安装方式

灵境制造提供三条相互独立的部署路径，按场景选择其一即可：

| 方式 | 适用场景 | 产物 | 难度 |
|------|----------|------|------|
| **桌面端安装包** | Windows 单机用户、希望开箱即用 | `灵境制造-setup-<版本>.exe` / `.msi` | |
| **服务端一键脚本** | Linux/macOS 服务器、无容器环境 | 用户目录内 venv + systemd（可选） | |
| **Docker 容器** | 生产环境、需要 PostgreSQL/Redis/TDengine 全套 | 本地构建镜像 + compose 编排 | |

> 源码目录约定：服务端代码位于仓库的 `engineering/python/` 目录（旧文档中的 `python/` 路径已废弃）。

## 3. 桌面端安装（Windows）

### 3.1 下载安装包

前往 [GitHub Releases](https://github.com/printing10101/Virtual-Realm-Manufacturing/releases) 下载最新版本的安装包：

- `灵境制造-setup-<版本>.exe`（NSIS 安装包，推荐）
- `灵境制造-<版本>.msi`（Windows Installer 包）

当前版本为 **2.7.0**，对应文件名如 `灵境制造-setup-2.7.0.exe`。

### 3.2 安装与启动

1. 双击 `.exe` / `.msi`，按向导完成安装（默认安装到 `C:\Users\<你>\AppData\Local\灵境制造`）。
2. 首次启动时，安装包内的引导程序会自动完成：
   - 解压内置 Python 3.12 运行时与预装依赖（含 torch CPU 版、cadquery 等）；
   - 初始化本地数据库（SQLite）；
   - 生成随机 JWT 密钥与管理员账号（首次启动日志中可见）。
3. 启动完成后，桌面客户端自动打开 Web 界面（默认 `http://127.0.0.1:8765`）。

> 桌面端为离线自包含，无需手动安装 Python、Redis 或数据库。

## 4. 服务端一键安装脚本（Linux / macOS）

### 4.1 获取并执行

脚本地址为仓库内的真实文件 `deploy/install.sh`，通过 GitHub 原始地址获取：

```bash
# 标准安装（自动用 uv 安装 Python 3.12 + 依赖 + 初始化数据库，安装到 ~/.lingjing-manufacturing）
curl -fsSL https://raw.githubusercontent.com/printing10101/Virtual-Realm-Manufacturing/main/deploy/install.sh | bash

# 中国大陆加速（GitHub 代理 + 阿里云 PyPI 镜像）
curl -fsSL https://ghproxy.com/https://raw.githubusercontent.com/printing10101/Virtual-Realm-Manufacturing/main/deploy/install.sh | bash -s -- --cn

# 自定义端口（默认 8765）
curl -fsSL https://raw.githubusercontent.com/printing10101/Virtual-Realm-Manufacturing/main/deploy/install.sh | bash -s -- --port 9000
```

> 基础安装**不需要 root 权限**：数据全部写入用户目录 `~/.lingjing-manufacturing`（可通过环境变量 `LINGJING_HOME` 修改根目录）。仅当显式传入 `--systemd` 安装系统服务时才需要 root。

### 4.2 脚本参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--port <n>` | API 监听端口 | `8765` |
| `--no-systemd` | 不询问是否安装 systemd 服务 | 交互式询问 |
| `--systemd` | 直接安装 systemd 服务（需 root） | 交互式询问 |
| `--cn` | 使用中国大陆镜像（GitHub 代理 + 阿里云 PyPI） | 关闭 |
| `--help` | 显示帮助 | - |

> 脚本会**自动生成管理员账号与随机密码**并在安装末尾打印，无需、也不支持手动传入 `--admin-user` / `--admin-pass`。早期文档中的 `--mode`、`--data-dir`、`--enable-gpu`、`--enable-redis`、`--log-level` 等参数**均已不存在**，请勿使用。

### 4.3 环境变量（可选）

在运行脚本前可通过环境变量微调行为：

| 变量 | 说明 | 默认 |
|------|------|------|
| `LINGJING_HOME` | 安装与数据根目录 | `~/.lingjing-manufacturing` |
| `LINGJING_PORT` | API 端口 | `8765` |
| `LINGJING_CN` | 设为 `1` 等效于 `--cn` | `0` |
| `LINGJING_REPO` | 源码仓库地址 | 官方 GitHub 仓库 |
| `LINGJING_SRC` | 复用已存在的源码目录（跳过 clone） | 自动 clone |
| `LINGJING_PYTHON_MIRROR` | uv 安装 Python 的镜像 | 官方 |

### 4.4 Windows 服务端

Windows 服务端请使用 **Git Bash**（或 WSL2）运行同一份 `install.sh`，**没有**独立的 `install.ps1` 脚本（早期文档中的 `.ps1` 用法不可用）。

## 5. Docker 容器部署

### 5.1 构建并启动（完整版）

镜像通过仓库 `Dockerfile` **本地构建**，没有公开预构建的 `lingjing/manufacturing-api` 拉取地址（旧文档中的 `docker pull` 命令不可用）。

```bash
git clone https://github.com/printing10101/Virtual-Realm-Manufacturing.git
cd Virtual-Realm-Manufacturing

# 配置环境变量（设置数据库密码等）
cp .env.example .env
# 编辑 .env：POSTGRES_PASSWORD、REDIS_PASSWORD、JWT 密钥等

# 国内用户：在 .env 中设置 IMAGE_REGISTRY 使用华为云 SWR / 阿里云 ACR 基础镜像
# IMAGE_REGISTRY=swr.cn-north-4.myhuaweicloud.com

# 构建并启动（完整版含 PostgreSQL + Redis + TDengine + Prometheus + Grafana + nginx）
docker compose -f docker-compose.yml --profile full up -d --build
```

### 5.2 SQLite 轻量版

```bash
docker compose -f docker-compose-sqlite.yml up -d --build
```

启动后访问 `http://localhost:8765`，API 文档 `http://localhost:8765/docs`。

## 6. 服务管理命令（lingjing CLI）

服务端一键安装会在 `~/.local/bin/lingjing` 安装一个管理命令行。安装后请先执行 `source ~/.bashrc`（或重新打开终端）使其生效。

| 命令 | 作用 |
|------|------|
| `lingjing doctor` | 全面自检（Python、依赖、端口、数据库连通性） |
| `lingjing start` | 启动后端服务 |
| `lingjing stop` | 停止后端服务 |
| `lingjing restart` | 重启后端服务 |
| `lingjing status` | 查看运行状态 |
| `lingjing update` | 拉取最新代码并更新依赖 |
| `lingjing uninstall` | 卸载（保留数据目录，除非手动删除） |
| `lingjing version` | 显示当前版本号 |

示例：

```bash
lingjing doctor     # 安装后第一件事：确认环境健康
lingjing start      # 启动
lingjing status     # 查看是否就绪
```

### 7.1 健康检查端点

| 端点 | 用途 | 预期响应 |
|------|------|----------|
| `GET /api/health/ping` | 轻量级存活探针 | `200 {"ping": true}` |
| `GET /api/health` | 主健康检查 | `200 {"status": "...", "version": "2.7.0", "timestamp": ...}` |
| `GET /api/v1/health/quick` | 快速探测 | `200` |
| `GET /api/v1/health/system` | 系统级组件健康（数据库/缓存/模型等） | `200` 含组件详情 |

验证命令：

```bash
curl -fsS http://localhost:8765/api/health/ping
# 预期输出: {"ping": true}

curl -fsS http://localhost:8765/api/health
# 预期输出含 "version": "2.7.0"
```

### 7.2 进程验证

```bash
# 查看服务进程（服务端一键安装场景）
ps aux | grep uvicorn | grep -v grep

# 或使用 lingjing CLI

```

早期文档提到的 `python -m app.tests.smoke_test` 端到端脚本**当前不存在**。如需验证完整业务链路，请通过 Web 界面依次执行：导入 STEP 图纸 → 工艺规划 → LNN 推理（切削力预测）→ 后处理（Fanuc）→ 导出 NC 代码。

## 8. 常见问题

| 症状 | 原因 | 解决 |
|------|------|------|
| `ModuleNotFoundError: No module named 'app'` | 未激活 venv 或在错误目录启动 | 服务端一键安装后使用 `lingjing start`；如需手动运行，先 `source ~/.lingjing-manufacturing/venv/bin/activate` 并 `cd engineering/python` |
| `OSError: [Errno 98] Address already in use` | 8765 端口被占用 | 用 `--port` 指定其他端口，或 `lingjing stop` 后重启 |
| `PermissionError` 写入数据目录 | `LINGJING_HOME` 无写权限 | 确认对该目录有写权限，或改用其他 `LINGJING_HOME` |
| `torch.cuda.OutOfMemoryError` | GPU 显存不足 | 改用 CPU 推理或降低并发；桌面端默认 CPU 推理 |
| 依赖/模型下载卡住 | 网络问题 | 重试用 `--cn` 参数启用国内镜像 |

## 9. 卸载

### 9.1 服务端

```bash
lingjing uninstall
```

卸载会移除程序与 venv，但**保留 `LINGJING_HOME` 下的工件与模型缓存**以便重装后继续使用。如需彻底清理：

```bash
rm -rf ~/.lingjing-manufacturing
```

> **警告**：上述操作不可逆，请提前备份！

### 9.2 桌面端

通过 Windows「设置 → 应用 → 灵境制造 → 卸载」即可。

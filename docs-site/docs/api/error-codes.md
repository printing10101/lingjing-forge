# 错误码说明

> 灵境制造 API 错误码体系完整参考。
> **错误码格式**：`E[0-9]{4}`，前两位标识阶段，后两位为具体错误。
> **错误响应格式**：所有 API 端点的错误响应均遵循统一格式，具体示例参见 [examples.md](./examples.md)。

## 1. 错误码分类总览

| 范围 | 类别 | 阶段 |
|------|------|------|
| `E1xxx` | 图纸解析 | 图纸导入 / 特征识别 |
| `E2xxx` | 3D 重建 | 三维模型重建 |
| `E3xxx` | 工艺规划 | 切削参数、刀具选择、装夹 |
| `E4xxx` | NC 代码生成 | 刀轨计算、后处理 |
| `E5xxx` | 系统/基础设施 | 模型加载、资源、连接 |
| `1xxx` | 通用 | 鉴权、参数、限流（HTTP 标准） |
| `4xxx` | 业务资源 | 模型未找到、用户未找到 |
| `5xxx` | 异步任务 | 任务未找到、任务冲突 |
| `7xxx` | 目标与策略 | 目标对齐未找到 |
| `8xxx` | Agent 状态 | 状态未找到、状态冲突 |
| `9xxx` | 技能与插件 | 技能未找到 |
| `10xxx` | 预算治理 | 预算超限 |

## 2. 错误响应字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `code` | int | | 数值错误码（去掉 E 前缀），如 `3001` |
| `error_code` | string | | 字符串错误码，如 `"E3001"` |
| `message` | string | | 人类可读的错误描述 |
| `severity` | string | | `critical` / `error` / `warning` |
| `detail` | string | | 详细错误上下文 |
| `suggestion` | string | | 修复建议 |
| `recoverable` | bool | | 客户端是否可重试 |
| `adjusted_values` | object | | 系统自动调整后的参数值 |
| `request_id` | string | | 唯一请求 ID，用于日志关联 |
| `timestamp` | string | | 错误发生时间（ISO 8601） |

---

## 3. 严重程度分级

| 等级 | 含义 | 用户操作 |
|------|------|----------|
| `critical` | 阻断性错误，必须处理 | 停止后续操作，排查根本原因 |
| `error` | 严重错误，建议处理 | 修正后重试 |
| `warning` | 警告，可继续 | 关注但不阻断流程 |

| 错误码 | 数值码 | 描述 | 严重程度 | 可能原因 | 解决建议 |
|--------|--------|------|----------|----------|----------|
| `E1001` | 1001 | 图纸解析失败 | critical | 文件格式不支持、文件损坏、超过 10MB | 确认格式为 SVG/PNG/PDF，文件 ≤ 10MB，清晰度 ≥ 300dpi |
| `E1002` | 1002 | 线型识别失败 | error | 图纸线型不符合 ISO 128 标准 | 检查线型合规性，使用高对比度图纸或手动标注 |

## 5. 错误处理最佳实践

### 5.1 客户端

1. **总是检查 HTTP 状态码**：4xx/5xx 表示业务错误
2. **优先使用 `error_code`（字符串）**：版本升级更稳定
3. **使用 `request_id` 关联日志**：通过 `X-Request-ID` 头在服务端查询
4. **对可重试错误实现退避**：`recoverable: true` 的错误使用指数退避
5. **对 `recoverable: false` 不要重试**：直接报错给用户

### 5.2 服务端开发

1. **使用结构化异常**：`ManufacturingError` 自动带 `request_id`
2. **不要泄露敏感信息**：使用 `safe_errors.py` 过滤
3. **提供明确建议**：`suggestion` 字段必须有可操作信息
4. **保持错误码稳定**：删除错误码需经过 6 个月弃用周期
5. **审计日志**：所有 4xx/5xx 错误必须记录到 `audit.log`

### 5.3 错误码维护

- **新增**：在 `app/core/error_taxonomy.py` 的 `ErrorCategory` 中定义
- **修改**：保持向后兼容（可新增可选字段）
- **废弃**：标注 `@deprecated` 并保留 ≥ 6 个月
- **映射表**：`CATEGORY_TO_NUMERIC` 集中维护 E 前缀与数值码的对应

## 6. 错误码查询工具

```bash
# 列出所有 critical 错误
python -m app.cli errors list --severity critical

# 通过字符串码查询
python -m app.cli errors show E3004

# 输出最近 24 小时的错误统计
python -m app.cli errors stats --from "24h ago"
```
